# LiveTrial：Windows でタイムアタックを記録する

これは英語版ガイド（[LIVETRIAL.md](../../LIVETRIAL.md)）の機械翻訳です。内容は英語版が正となります。翻訳の誤りは「Translation correction」の Issue フォームからお知らせください。

[すべてのガイド](../../../../README.md#get-started) · [LiveTrial コンポーネントの README](../../../../apps/timetrials-desktop/README.md)

LiveTrial は、キャプチャーボードを通してタイムアタックを見守る、または録画した動画を読み込む Windows 用の
プログラムです。走行ごとの記録（合計タイムとラップタイム、キャラクターとカスタマイズ、ゴースト）を認識し、
クリップと一緒に PC に保存します。一度サインインすれば、結果をコミュニティのウェブサイトに送れます。まだ送れない
結果は PC で待機します。

## コミュニティのウェブサイトなしで使う

LiveTrial は単独でも使えます。キャプチャー、動画の解析、**記録履歴**、クリップ、修正はすべてローカルで動作します。
アカウントなしで記録した走行は、**<account>として送信** で送るまでこの PC にだけ残ります。**自分の記録**、
**ランク**、**カスタマイズ** のタブには、サインインしたコミュニティが必要です。

## 必要なもの

- x86-64 の Windows（Windows 11 で動作確認済み）。プログラム用に約 1 GB と、録画用の空き容量。
- ライブキャプチャーには：Windows がビデオデバイスとして認識するキャプチャーボードとそのドライバー、そして
  **FFmpeg**（無料。ライセンスの都合で同梱していません。下の手順 4 を参照）。動画ファイルだけなら、キャプチャー
  ボードも FFmpeg も不要です。
- 結果を送るには：コミュニティのウェブサイトのアドレスと、そこでのアカウント（[プレイヤー向け](PLAYERS.md) を参照）。
  ローカルの試用インストールと同じコンピューターでは `http://127.0.0.1:<port>` が使えます。それ以外では信頼された
  HTTPS アドレスを使ってください。

## インストール

1. プロジェクトの [GitHub Releases](https://github.com/fromthelake/MK8DX-Ecosystem/releases) ページ（各リリースに
   パッケージが添付されています）から `desktop-client-….zip` と `SHA256SUMS.txt` をダウンロードします。クローンが
   あれば、同じパッケージを自分でビルドすることもできます：[Client builds](../../../CLIENT_BUILDS.md#livetrial-windows)。PowerShell で確認します：
   `Get-FileHash '.\desktop-client-<version>.zip' -Algorithm SHA256` を実行し、値全体を比較してください。
2. ZIP を **まるごと**、自分のフォルダー（たとえばドキュメントの下）に展開します。フォルダー構成はそのままにして
   ください。パッケージには専用の Python ランタイム、認識エンジン、ゲームのアセットが含まれています。
3. `LiveTrial.exe` をダブルクリックします。ダッシュボードが専用のウィンドウで開きます（Edge、なければ Chrome、
   なければ既定のブラウザー）。動画の解析はすぐに使えます。
4. ライブキャプチャーを使うには、FFmpeg を一度インストールします。いちばん簡単なのは、PowerShell を開いて
   `winget install Gyan.FFmpeg` を実行し、新しい PATH が反映されるよう LiveTrial を終了して起動し直す方法です。
   winget がない場合は Windows 用ビルド（たとえば [ffmpeg.org/download.html](https://ffmpeg.org/download.html) から
   リンクされている gyan.dev のリリース zip）をダウンロードして展開し、`bin\ffmpeg.exe` を
   `%LOCALAPPDATA%\MK8DX\LiveTrial\tools\ffmpeg\bin\` にコピーします。FFmpeg がない場合は、**キャプチャー開始** が
   そのことを知らせ、これらの手順を表示します。

## コミュニティに接続する

1. **設定** を開きます。**コミュニティWebサイトのアドレス** にコミュニティのアドレス（たとえば
   `https://www.example.org`）を入力し、**サーバーを保存** を選びます。LiveTrial は自動で再起動します。開いたままに
   してください。
2. 再起動後、設定に自分のアドレスが正確に表示されていることを確認してから、アカウントメニューからサインインします
   （メールのコード、メールのリンク、またはウェブサイトでの承認）。
3. 自動の再起動に失敗した場合は、アプリで **LiveTrialを終了** を選び、閉じるまで待ってから `LiveTrial.exe` を
   もう一度起動します。ウィンドウを閉じるだけでは不十分です。LiveTrial がバックグラウンドで動き続けることがあります。

アカウントと送信待ちの記録はサーバーごとに別々に保存されます。サーバーを切り替えても、古い記録が新しい
コミュニティに送られることはありません。ローカルのメール受信箱のアドレスやサーバーの内部アドレスは、決して
LiveTrial に入力しないでください。

## あとから接続する

先に記録して、あとからコミュニティに参加することもできます。すでにこの PC にある記録はこう扱われます：

- **記録する前にコミュニティを選んでください。** 記録はサーバーごとに保存されます。コミュニティのアドレスを保存する
  前に、または別のコミュニティが設定されていたときに記録したものは、そのサーバーに残り、新しいコミュニティに
  提案されることはありません。そうした録画を移すには、接続したあとでその動画ファイルに対してもう一度
  **動画を解析** を実行します。
- **アカウントなしで記録した走行** は、あとでサインインしても送られません。1 件の記録（**記録履歴** 内、または
  レース後の行）で、または送信待ちリスト（上部のカウンター）の **アカウントなし** の行で **<account>として送信** を
  選ぶと、それらすべてがサインイン中のアカウントに渡されます。記録はそのアカウントのプレイヤーに入ります。
  この選択をしない限り、何も割り当てられません。
- **サインイン中に記録した走行** は、必ず同じアカウントで送られます。**今すぐ送信** は送信待ちの記録をすべて、
  それぞれのアカウントで送ります。アカウントがサインアウトしている記録は、そのアカウントが再びサインインするまで
  待機します。
- **記録は 1 回だけ保存されます。** どの記録にも固有の投稿 ID があり、ウェブサイトは同じ記録の 2 つ目のコピーを
  受け付けません。
- **クリップと動画はこの PC に残ります。** ウェブサイトに送られるのは結果（タイム、コース、カスタマイズ）だけです。
  YouTube へのアップロードは別の任意の手順です。

## 使い方

- **キャプチャー開始**：キャプチャーボードを選びます。LiveTrial はまずそこから静止画を 1 枚表示するので、正しい
  デバイスかどうか確認できます。その後、**ライブ** タブに映像と認識したすべての記録が表示されます。
- **動画を解析**：`.mp4`/`.mkv` ファイルを選ぶと（ファイルは
  `%LOCALAPPDATA%\MK8DX\LiveTrial\videos` にコピーされます）、LiveTrial はキャプチャーと同じように処理します。
- 各レースの後、**前回のレース** の行に記録の場所が表示されます：ウェブサイト上、保存済みで送信待ち
  （**今すぐ送信**）、またはこの PC にのみ（**<account>として送信**）。
- **記録履歴** にはすべての記録がクリップ付きで並びます。認識結果は修正できます。修正すると新しいバージョンが
  保存され、以前のものも残ります。
- 自動送信は初期設定ではオフです。設定でオンにしてください。記録は必ず先にローカルに保存されます。

本体の言語がダッシュボードの言語と違う場合は、設定で **Switchの言語** を設定してください。

ダッシュボードを操作できるのはこのコンピューターからだけです。LiveTrial のウィンドウ、またはこの PC で開いたダッシュボードのページから操作します。エンジンを `--lan` 付きで起動した場合（[LiveTrial コンポーネントの README](../../../../apps/timetrials-desktop/README.md) を参照）、ネットワーク上のスマートフォンやタブレットはライブ表示と走行を見ることはできますが、何も変更できません。

## 読みやすいクリップ名

LiveTrial の中では、クリップは内部の名前のままです。完了したクリップは、1 つのフォルダー
`ドキュメント\MK8DX\LiveTrial-clips`（ディスク上では `Documents\MK8DX\LiveTrial-clips`）にも、読みやすい名前で表示されます。

```
2026-11-16 10h25m  Mario Kart Stadium  150cc  1m46s784.mp4
```

- クリップの開始日時（この PC の時計）、コース、クラス（50cc、100cc、150cc、200cc、Mirror）、タイムが、2 つのスペース
  で区切られて並びます。録画ボタンで撮ったクリップは `Manual`、ゴーストのリプレイは `Ghost <コース>` になります。
  LiveTrial が認識できなかったコースやタイムは省かれ（`Unknown track`）、推測で入れることはありません。同じ名前が
  すでにある場合は ` (2)` が付きます。
- ファイル名に使うのは英字、数字、スペース、`-` だけなので、LiveTrial が日本語のときはコース名が英語になります。
  アポストロフィなどの記号は取り除かれます（Yoshi's Circuit は Yoshis Circuit）。
- LiveTrial のデータと同じドライブではハードリンクになり、追加の容量を使いません。別のドライブではコピーになります。
  LiveTrial のストレージのクリーンアップがクリップを削除すると、その読みやすいコピーも削除されます。ピン留めした
  クリップはコピーも残ります。
- **記録履歴** ではクリップの下に名前が **Open folder** ボタンと一緒に表示されます。コピーをオフにしたり別のフォルダーを
  選んだりするには、**設定** の **クリップの読みやすいコピー** を使います。

コピーはクリップが完成した後、バックグラウンドで作られます。失敗しても（フォルダーにアクセスできないなど）、
クリップ自体には影響しません。

## 困ったときは

- ウェブサイトが違う、またはサインインで違うサイトが開く：**LiveTrialを終了** で LiveTrial を終了し、もう一度起動して
  設定のアドレスを確認します。同じ PC の別の Windows アカウントで LiveTrial がまだ動いている可能性もあります。
- キャプチャーデバイスが表示されない：USB の接続とドライバーを確認し、数秒待ってからもう一度試します。
- 認識の誤り：送信する前に記録履歴で記録を修正します。認識は、自分の結果を自分で確認することの代わりには
  なりません。

LiveTrial は Windows 専用です。macOS 版や Linux 版はありません。自分でビルドするには
[Client builds](../../../CLIENT_BUILDS.md) を参照してください。
