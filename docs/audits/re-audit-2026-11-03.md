# Open-source release re-audit (2026-11-03)

Scope: this repository only, branch `main` at `995dda0`, and `public-main-candidate` at `57a9b6d`. The candidate is a
single root commit, and its tree (`850f6196…`) is identical to the tree of `main`. Baseline:
[open-source-readiness.md](open-source-readiness.md). The status column in [remediation-plan.md](remediation-plan.md)
was not relied on. Every status below was checked again. Several rows in that column are now out of date (see N5).

## Verdict: **Conditional Go**

The tree itself is ready to publish. All four blockers are resolved in the tree. One complete GitHub Actions run
on the exact candidate commit is green. No personal data about community members was found in the tree.

The remaining risk is **where** the tree is published. The planned remote still holds the old history, and that
history contains the personal data that B4 removed. See condition 1.

### Conditions for Go

1. **Publish only the candidate history.** Do not make the existing private `fromthelake/MK8DX-Ecosystem` public
   as it is now. Its `main` (`ba35ce4`) and the tags `v0.1.0-rc.1` to `rc.7` still contain the original migration
   0048. Its old file name (`0048_split_<name>_tournament_identity.*`) and its contents name a community member.
   The old commit messages also refer to private intake commits. Do one of the following:
   - Publish into a **new or recreated** repository that receives only `57a9b6d` as `main`. Use no `--mirror`, no
     `--tags` and no old releases.
   - Delete every old branch, tag and release on the existing repository before it is made public. Even then,
     GitHub can keep unreachable objects reachable by SHA, so a new repository is the safer choice.

   The README, CODEOWNERS, issue-template `config.yml` and `SOURCE_FOR_BINARIES.txt` link to
   `fromthelake/MK8DX-Ecosystem`. Keep that name for the new repository, or update those links.
2. **Publish the next release candidate (`0.1.0-rc.8`) on the new history at or soon after publication.** The
   README says release candidates are on the Releases page (`README.md:48-50`). A fresh repository has none.
3. **Owner acknowledgement of N1 (catalog divergence for 0048/0049/0057).** This needs no code change before
   publication. Record it in `docs/OPERATIONS.md` or the changelog before the first public release.

Recommended, not blocking: decide on N2 (a leftover first name used as an identifier), and fix the small
documentation drift in N3 to N5.
