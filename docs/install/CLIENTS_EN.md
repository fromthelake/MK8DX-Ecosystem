# Using the clients without building them yourself

Nederlands: [CLIENTS.md](CLIENTS.md)

LiveTrial and the Tournament Tools also work without a website: they process recordings and keep the results locally. You only need your own website installation to send results; the Android app and the browser scanner always need one. On the same Windows PC, use the address that the start window shows in LiveTrial and Tournament, for example `http://127.0.0.1:18080` (A1) or `http://127.0.0.1:18090` (A3). For a public website, use the full trusted HTTPS URL, for example `https://www.example.org`. The file `/client-config.json` on that host confirms the same address without secrets. Never type `mysql`, `api:8080`, a VPS SSH IP or the private `operator.json` into a client. A1 localhost is for the website on one PC; the Android sign-in client requires HTTPS, so A1 is not a phone route.

## Android APK

**Where:** on an Android 8.0/API 26 or newer device, preferably arm64. **Do:** get `mk8dx-android-release-<version>.apk` from the latest release, compare its SHA-256 with `SHA256SUMS.txt` on the PC you transfer it from, copy the APK file to your phone and open it from **Files/Downloads**. Android may ask, per file app, for permission to install “unknown apps” from this source; give it only for this checked package and turn the permission off again after installation if you like. **You see:** MK8DX appears among your apps. **See something else?** Check free space, the Android version and the file hash; do not install an APK of unknown origin. This is the release APK signed locally with the retained owner key, not a Play Store app. Earlier public debug APKs must be uninstalled once before this installation; save any results not yet sent first. Later APKs with the same release key can update it in place.

**First start:** the **Choose your community** screen asks how your community plays. For **Online community**, enter `https://<your-hostname>` under **Website address**, without a trailing `/` or path, and tap **Save**. At home or at the club (A2), tap **Scan the QR code** and scan the **Prepare a device** card; the app then stores the trust in that installation itself ([A2 guide, chapter 7](A2_HOME_GUIDE_EN.md#7-the-android-app-and-livetrial)). **You see:** the home page. At the top are the logo, the community chip, the bell and your name. Through the community chip → **Add a community** you add another community later, and you switch with **Change community** in one tap. Each community keeps its own sign-in and waiting runs; nothing is sent to another community automatically. **See something else?** Check in the phone browser that the same HTTPS address opens without a certificate warning. Then sign in in the app through the browser code and choose your own account. Camera/photo permission is only needed for scanning.

**App Links:** `/.well-known/assetlinks.json` returns JSON `[]` by default, so no association with an arbitrary domain. Visiting the website and signing in to the app manually work without automatic Android link association. Your own signed APK needs, in route C, its own applicationId/signing keystore and the matching fingerprint on your domain; never share the private signing key with the server configuration.

## LiveTrial Windows

**Where:** on a Windows x86-64 PC that has the recording or the video file. **Do:** check `desktop-client-<version>.zip` against the checksum, extract **the whole folder** into your own Documents folder and keep the folder structure with engine/runtime/assets. Open the included `LiveTrial.exe`. **You see:** a local LiveTrial window; there is no need to edit Python code or `example.invalid`. Go to **Settings → Community website address**, enter the exact address of your installation and choose **Save server**. LiveTrial then restarts itself; leave the window open. **Check:** Settings shows the chosen address, and after that Sign in asks for the right community. **See something else?** Check that you extracted the complete ZIP and that the address opens as trusted in the browser. If the automatic restart fails, choose **Quit LiveTrial**, wait until the app has really closed and open `LiveTrial.exe` again. You can also process a local analysis file without signing in; live capture needs a suitable capture card/driver and the package requirements. Results, accounts and the queue stay separate locally **per server**. A server change asks for confirmation; old runs do not go to the new community.

## Scanner in the browser

**Where:** on a PC or phone in a trusted browser. **Do:** open `<your-website>/scanner/`, choose **image upload** first and select a results photo of your own. **You see:** the scanner interface and a recognition/confirmation step. Check the details before sending. **See something else?** Check the HTTPS URL, the loaded models and any browser message. Outside localhost the camera works only in a trusted secure context, asks for permission, and recognition depends on the photo/camera. A failed recognition is no reason to ignore security warnings. On A2, the described local CA trust step for the second browser is needed first.

## Tournament Live and Processor

**Where:** on a Windows x86-64 recording PC. **Do:** check `tournament-tools-<version>.zip`, extract it completely and double-click `Install-MK8DX-TournamentTools.cmd`. The installer creates a local runtime; it needs internet once to download Python 3.12 and public PyTorch/PyPI packages. All OCR models are in the package; after that, processing works offline. This is a package installation, not a source build. Expect several GB of download/disk space, especially with CUDA. **You see:** `SUCCESS`, and in the package folder `TournamentProcessor.cmd`, `TournamentAnalysis.cmd`, `TournamentLive.cmd`, `TournamentLiveCli.cmd` and `TournamentConnect.cmd`. **See something else?** Read `install.log` in the package folder; keep `runtime-assets` intact and check the network/free space.

**Recorded video:** drag an `.mp4`/`.mkv` onto `TournamentProcessor.cmd`; the package writes a session folder next to the file with Excel, CSV and `*_TournamentRaceResultsV1.json`. **Live capture:** connect a recognized capture card, open `TournamentLive.cmd`, choose/check picture and sound and confirm races before export. Processing a file does not require a capture card. **Website connection (optional):** open PowerShell in the package folder and run `.\TournamentConnect.cmd sign-in`; the first time, the CLI asks once for the exact address of your installation. On A1 or A3 that is the `http://127.0.0.1:<port>` address shown by the MK8DX window: plain HTTP is accepted only for such addresses on this PC, every other address needs HTTPS. Without a terminal, set it first with `TournamentConnect.cmd server <address>`. Complete the browser sign-in. `TournamentConnect.cmd server` shows the address; `TournamentConnect.cmd server https://www.example.org` changes it after explicit confirmation. Sessions and waiting uploads stay separate per server. For `TournamentConnect.cmd send`, the administrator first gives the ordinary signed-in Player tournament rights through **Administration → Tournaments → Directors**. This does not grant general administration. Import on the website happens under **Administration → Tournaments → Import canonical race results** or within a group with **Offline fallback: import a saved Live / Processor result file**; an upload is evidence in a queue, not automatic publication. Keep the local session/output when you update.

## Connect later

**LiveTrial:** runs are kept per server. So choose the community address in **Settings** before you record, even if you do not have an account yet: runs recorded before an address was saved, or while another community was chosen, stay with that server and are never offered to the new one. To bring such a recording over, process its video again with **Analyse a video** after connecting. Runs without an account are not sent when you sign in later: choose **Send as <account>** on one run (in **Run history** or on the line after the race), or on the **No account** line of the waiting list (the counter at the top) to give all of them to the signed-in account. They land on that account's Player; nothing is assigned without this choice. Runs recorded with an account always go out with that same account: **Send now** sends everything that is waiting, each with its own account, and a run of a signed-out account waits until that account signs in again. Every run has its own submission ID; the website does not accept the same run a second time. Clips and videos stay on the PC; only the result (times, track, setup) goes to the website.

**Tournament Tools:** a night processed without a connection is complete on the PC (`Output_Results\` with Excel, CSV and `*_TournamentRaceResultsV1.json`) and is not sent to the website afterwards by itself. Bring it over within the group with **Offline fallback: import a saved Live / Processor result file** or the group's Excel import (every recognized name must be matched to a Player first), as an administrator through **Import canonical race results** (imported races stay private until they are published), or with `.\TournamentConnect.cmd send <name>_TournamentRaceResultsV1.json` after `sign-in`: it asks for the night, the group and the first race number, and the races arrive in **Incoming results**. If the website cannot be reached, the file stays where it is; send it again later. In Tournament Live, **Connect to Tournament Manager** after a finished session offers that session to the night you pick in **Choose Tournament**; on the website the Director then opens Step 5 (Step 9 for the final groups) → **Available Tournament Live recordings**, chooses the group under **Link to group** and then **Link reviewed recording**. Tournament Live may add a capture card it remembers by itself, as an extra source on Group 1; select it and choose **Remove selected**, or give it its own group, otherwise **Start all** stops because two feeds share a group. In Tournament Live, uploads that failed while Live was connected are sent again by Live, automatically or with **Retry upload**, only for the same account. A session run with **Work offline** is not kept for upload. Signing in adds two things: the list of nights you may deliver to and, during the night, the live feed to a chosen group (`target`). A race counts only after the Director has confirmed it in **Incoming results**.
