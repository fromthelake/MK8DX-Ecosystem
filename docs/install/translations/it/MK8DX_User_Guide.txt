Guida per MK8DX 0.2.10 · 16 novembre 2026

Benvenuto

MK8DX è un sito web per le Prove a tempo e i tornei di Mario Kart 8 Deluxe. Puoi sfogliare i percorsi e i tempi di riferimento, accedere tramite un link via email e inviare i tuoi risultati. Un amministratore può controllare gli invii. Lo scanner, l'app Android e i programmi per Windows sono strumenti separati.

I pacchetti di rilascio sono allegati alle GitHub Releases del progetto. Apri la pagina delle release, https://github.com/fromthelake/MK8DX-Ecosystem/releases, e scegli la release più recente. Sotto Assets, scarica il pacchetto per la tua via e SHA256SUMS.txt. Il pulsante Source code (zip) di GitHub non è il pacchetto di installazione. Se invece lavori da un clone del codice sorgente, puoi compilare i pacchetti da solo; vedi “Risoluzione dei problemi e compilazione in proprio”. La sigla v0.2.10 nel nome di un file di pacchetto identifica questa release; le immagini Docker all'interno del pacchetto host portano tag di versione corrispondenti. Conserva tutti i file della stessa release.

Scegli un solo modo di usare il sito web. Su un solo computer Windows, usa Docker oppure XAMPP, Node.js e il MariaDB attuale incluso. La via di rete Docker documentata raggiunge un secondo PC Windows sulla tua rete attendibile. Per un dominio pubblico, scegli un hosting web condiviso con Node.js (il capitolo usa come esempio mijn.host Starter) oppure il tuo VPS con Docker. Questi capitoli sono alternative, non un corso da completare in ordine. I client per telefono e Windows vengono dopo le vie per il sito web.

A1 (Docker su un computer) e A3 (XAMPP/Node.js su Windows) sono supportati dopo test di installazione da zero e di aggiornamento con dati conservati. A2 (rete di casa o del club, novità della 0.2.0) ha un proprio pacchetto con una configurazione guidata nel browser ed è stato testato dall'inizio alla fine su Windows 11. B1 (VPS con Docker) è documentato ma non è stato testato dall'inizio alla fine. B2 (hosting Node.js condiviso): il sito della nostra community funziona così; il pacchetto pubblico non è ancora stato installato da zero su un nuovo account di hosting. Le installazioni locali A1 e A3 sono state testate su Windows 11 x86-64, compresi gli account e i risultati di LiveTrial e di Tournament Processor/Connect nel database e sul sito web. L'acquisizione fisica di Tournament Live ha superato un collaudo completo a 1× con il pacchetto 0.2.2. Se hai solo Linux o macOS, senza un computer Windows o un altro server, le scelte sono più limitate. I due capitoli finali spiegano cosa puoi provare in locale su quello stesso computer e quali prodotti non esistono ancora per il tuo sistema operativo.

Provalo su un computer

Questa è una prova su un computer Windows 11 con un processore x86-64. Come margini consigliati prevedi 8 GB di memoria e circa 15 GB di spazio di lavoro libero. Non sono minimi rigidi misurati. In Windows, trovi il processore e la memoria in Impostazioni → Sistema → Informazioni. Lo spazio libero è in Esplora file → Questo PC. Non ti servono un dominio né un servizio email a pagamento.

1. Installa Docker Desktop dalla pagina ufficiale per Windows. Scegli WSL2 e i container Linux. Riavvia Windows se il programma di installazione lo chiede. Apri Docker Desktop e attendi “Engine running” (motore in esecuzione).

Docker Desktop per Windows: https://docs.docker.com/desktop/setup/install/windows-install/

Apri PowerShell dal menu Start. Questo comando dovrebbe mostrare una versione:

docker compose version

Se Docker non si avvia, segui prima il suo messaggio su WSL o sulla virtualizzazione. MK8DX non può avviarsi mentre Docker Desktop è chiuso.

2. Installa Python dalla 3.12 alla 3.15 per Windows x86-64 dalla pagina ufficiale. Nel programma di installazione, seleziona “Add python.exe to PATH” (aggiungi python.exe al PATH) e scegli “Install Now” (installa ora). Chiudi e riapri PowerShell. Controlla la versione:

Python per Windows: https://www.python.org/downloads/windows/

python --version

Se non vedi una versione dalla 3.12 alla 3.15, ripara Python con lo stesso programma di installazione. Controlla anche se Windows ha aperto un alias del Microsoft Store invece del Python installato. Qui Python esegue solo l'assistente di configurazione; non devi compilare software.

3. Metti mk8dx-host-local-v0.2.10-amd64.zip e SHA256SUMS.txt nella stessa cartella di download. Apri PowerShell in quella cartella e verifica il pacchetto host:

Get-FileHash '.\mk8dx-host-local-v0.2.10-amd64.zip' -Algorithm SHA256

Confronta l'intero valore con la riga di quel file in SHA256SUMS.txt. Se sono diversi, fermati e chiedi una copia corretta. Fai clic con il tasto destro sullo ZIP e scegli “Extract All” (Estrai tutto). Una destinazione adatta è Documents\MK8DX-A1. Apri la cartella estratta che contiene Start-MK8DX.cmd e compose.yaml.

4. Fai doppio clic su Start-MK8DX.cmd. La finestra si apre con una breve introduzione di gara: il logo MK8DX e un conto alla rovescia 3-2-1-GO con segnali acustici (Start-MK8DX.cmd -SkipCountdown toglie il conto alla rovescia; la guida all'hosting elenca tutte le opzioni). Poi chiede “Dove verrà eseguito MK8DX?” ed elenca A1, A2 e B1. Digita A1 e premi Invio. Inserisci l'indirizzo email che userai in seguito per accedere e diventare amministratore. La prima configurazione parte poi da sola. MK8DX carica i programmi forniti e crea le proprie chiavi, un database e i dati di riferimento standard. Il primo avvio può richiedere un po' di tempo.

Annota l'indirizzo mostrato come “Origine web” e quello mostrato come “Posta in arrivo locale”. L'indirizzo del sito web può essere simile a http://127.0.0.1:18080 e la casella di test a http://127.0.0.1:18025. Le tue cifre finali possono essere diverse. Usa sempre gli indirizzi effettivamente mostrati.

Hai perso gli indirizzi in seguito? Apri di nuovo Start-MK8DX.cmd e scegli 3 per lo stato. “origin” è l'indirizzo completo del sito web per il tuo browser e per LiveTrial. “localMailInbox” è l'indirizzo di Mailpit. Apri quel secondo indirizzo solo nel browser per leggere la posta di accesso locale. Le cifre dopo i due punti sono la porta. “127.0.0.1” significa questo computer, quindi questi indirizzi A1 non funzionano su un altro PC o telefono.

I dati personali dell'installazione sono conservati fuori dal pacchetto estratto, in %LOCALAPPDATA%\MK8DX\Server. Conserva questa cartella e il volume del database Docker quando ricevi un pacchetto software più recente.

5. Apri l'indirizzo del sito web mostrato in un browser sullo stesso computer. Fai clic su “Accedi” (in inglese “Sign in”, in olandese “Aanmelden”) e inserisci esattamente l'indirizzo del passaggio 4. In un'altra scheda del browser, apri “Posta in arrivo locale”. Questo è Mailpit, una casella di posta di test sul tuo computer. Apri lì la tua email di accesso più recente e segui il suo link. Non cercare questa email di prova nella tua normale casella di posta.

Hai effettuato l'accesso, ma non hai ancora i diritti di amministratore. Apri di nuovo Start-MK8DX.cmd e scegli 5. La prima assegnazione dice “created” (creato); una ripetizione dice “unchanged” (invariato). Aggiorna il sito web o accedi di nuovo. Dovrebbe comparire la vista di amministrazione. Il primo che si registra a caso non riceve mai automaticamente i diritti di amministratore.

6. Apri Percorsi, scegli un percorso e guarda Staff Nintendo e Record mondiali. Puoi inviare un tuo tempo di prova tramite “Pubblica il tuo tempo” nella pagina del percorso (poi “Pubblica” e “Conferma e pubblica”). Controlla i dati prima di inviarli. Un invio non equivale a un'approvazione pubblica.

Mailpit contiene link di accesso. Non condividere questa casella di test con altre persone. Per un sito pubblico, scegli la via dell'hosting condiviso o del VPS con una vera posta in uscita.

Su un computer senza Docker: XAMPP e Node.js

Questa è una prova separata su un computer Windows 11. Docker non serve. XAMPP fornisce Apache e la finestra di controllo che avvia il tuo sito web locale. MK8DX stesso gira su Node.js. Il download attuale di XAMPP contiene MariaDB 10.4.32; questa via non usa quella versione. Il pacchetto MK8DX include un'istanza separata e mantenuta di MariaDB 11.4.13, legata solo a 127.0.0.1:18306. I database XAMPP esistenti e gli altri siti web non vengono modificati. Prevedi 8 GB di RAM e diversi GB di spazio libero per il pacchetto, il database, lo scanner e i backup.

1. Scarica XAMPP per Windows dal suo sito ufficiale e installalo in un posto che puoi ritrovare, come C:\xampp. Nel XAMPP Control Panel usa solo Apache. Non avviare MySQL, FileZilla, Mercury o Tomcat per MK8DX. Se usi già XAMPP per altri progetti, mantieni i loro database e le loro impostazioni.

XAMPP per Windows: https://www.apachefriends.org/download.html

2. Installa Node.js 24 per Windows dal sito ufficiale di Node.js. Installa Python 3.12 o successivo dalla pagina di download ufficiale per Windows e seleziona “Add python.exe to PATH” (aggiungi python.exe al PATH). Chiudi e riapri PowerShell. Controlla:

Node.js: https://nodejs.org/en/download
Python: https://www.python.org/downloads/windows/
node --version
python --version

Dovresti vedere Node 24 e Python 3.12 o successivo. Eseguono file MK8DX già compilati; non compili l'applicazione. Se un comando è sconosciuto, riapri PowerShell e, se necessario, ripara quell'installazione.

3. Metti mk8dx-xampp-node-windows-v0.2.10.zip e SHA256SUMS.txt nella stessa cartella di download. In PowerShell, confronta l'intero valore SHA-256 con la riga di questo ZIP:

Get-FileHash '.\mk8dx-xampp-node-windows-v0.2.10.zip' -Algorithm SHA256

Se corrispondono, fai clic con il tasto destro sullo ZIP e scegli “Extract All” (Estrai tutto). Una cartella adatta è Documents\MK8DX\nodocker-v0.2.10. Apri la cartella estratta che contiene Start-MK8DX-No-Docker.cmd. Contiene già bin\mailpit.exe e bin\mariadb-11.4.13-winx64.zip. Non compili codice sorgente e non sostituisci un vecchio database XAMPP. Non mettere questo pacchetto in htdocs.

4. Prepara Apache solo per questo sito locale. Apri PowerShell nella cartella MK8DX estratta. Imposta -XamppRoot sulla posizione effettiva di XAMPP:

powershell -ExecutionPolicy Bypass -File .\tooling\configure_xampp.ps1 -XamppRoot 'C:\xampp'

L'assistente salva prima apache\conf\httpd.conf in %LOCALAPPDATA%\MK8DX\ApacheBackup. Aggiunge solo “Include conf/extra/mk8dx-local.conf” e una porta separata 18090, poi controlla la sintassi di Apache. Aspettati “Apache syntax OK”. Se la porta 18090 è già occupata o le impostazioni sono diverse, fermati e leggi l'errore; non rimuovere un altro sito XAMPP. Per una posizione di XAMPP diversa, anche con spazi, sostituisci in questo comando solo C:\xampp.

5. Fai doppio clic su Start-MK8DX-No-Docker.cmd. Scegli la via A3 e inserisci l'indirizzo email che userai in seguito come amministratore. La finestra crea un'installazione privata in %LOCALAPPDATA%\MK8DX\NoDocker. Al primo avvio estrae MariaDB 11.4.13 solo in quella cartella, crea un database dedicato e un utente limitato, applica le migrazioni e Staff Nintendo e Record mondiali, e avvia Node.js e Mailpit. Può richiedere diversi minuti. Lascia aperta questa finestra MK8DX. Un riavvio conserva le chiavi, gli account, i risultati e il database.

A ogni avvio questa finestra mostra anche “Sito web:” e “Email di accesso - una casella di prova:”. “Sito web” è l'indirizzo completo per il tuo browser e per LiveTrial: http://127.0.0.1:18090. “Email di accesso - una casella di prova” è la casella di posta di test locale: http://127.0.0.1:18227. Apri Mailpit solo nel browser. Le cifre dopo i due punti sono le porte. “127.0.0.1” significa questo computer, quindi questi indirizzi non funzionano su un altro dispositivo. Se li dimentichi, guarda in alto nella stessa finestra MK8DX al prossimo avvio.

6. Apri XAMPP Control Panel. Se Apache è già verde, fai clic su Stop solo per Apache, attendi che la sua riga non sia più verde, poi fai di nuovo clic su Start. Questo carica la nuova impostazione del sito del passaggio 4. Se Apache era fermo, fai subito clic su Start. Apri http://127.0.0.1:18090 nel browser. La casella di posta di test locale è http://127.0.0.1:18227. Se il sito non è disponibile, controlla prima la finestra MK8DX, poi conferma che Apache sia verde. In una seconda finestra PowerShell aperta nella cartella del pacchetto, controlla il database e l'API:

python tooling/install.py check-database --state-dir "$env:LOCALAPPDATA\MK8DX\NoDocker"
python tooling/install.py check --state-dir "$env:LOCALAPPDATA\MK8DX\NoDocker"

Aspettati “MariaDB 11.4.13” e “ready” (pronto). Il sito web, lo scanner, il database e la casella di test sono legati a questo computer. Non inoltrare una porta del router e non esporre phpMyAdmin o la casella di test ad altre persone.

Apache non diventa verde? Un Apache di XAMPP non modificato vuole anche le porte 80 e 443, oltre alla 18090. Se un'installazione A2, IIS o un altro server web su questo computer usa già una di queste porte, Apache non si avvia e il registro nel XAMPP Control Panel indica la porta occupata. Ferma l'altro programma durante un periodo programmato, oppure usa A3 su un altro computer. Non rimuovere l'altro sito web.

7. Sul sito, fai clic su Accedi e usa esattamente l'indirizzo di amministratore del passaggio 5. Apri il messaggio più recente in Mailpit e segui il suo link di accesso. Sei ancora un utente normale. Ora fai doppio clic su Manage-MK8DX-No-Docker.cmd nella cartella del pacchetto (lascia aperta la finestra MK8DX), digita 2 e premi Invio. Dietro viene eseguito: python tooling/install.py admin --state-dir "$env:LOCALAPPDATA\MK8DX\NoDocker".

Funziona solo per un account che ha già verificato la propria email. Aspettati “created” (creato), oppure “unchanged” (invariato) se ripetuto. Aggiorna il sito. Un altro primo iscritto non diventa automaticamente amministratore.

8. Apri un percorso e controlla Staff Nintendo e Record mondiali, compreso il Totale. Invia una Prova a tempo di prova e apri /scanner/ sullo stesso computer. Seleziona un'immagine per provare il caricamento. Un risultato dello scanner potrebbe richiedere un controllo; il caricamento non lo rende pubblico automaticamente.

9. Per l'uso quotidiano, avvia prima la finestra MK8DX, poi avvia Apache nel XAMPP Control Panel. Tieni aperta la finestra MK8DX mentre usi il sito. Dopo un riavvio di Windows, ripeti questi due avvii. Ferma Apache con Stop nel pannello, poi premi Ctrl+C nella finestra MK8DX. Si fermano solo i processi Node, Mailpit e MariaDB di questa installazione. Non terminare tutti i processi node.exe e non modificare un servizio XAMPP esistente.

10. Per un backup, tieni in esecuzione la finestra MK8DX e il suo database. Puoi fermare brevemente Apache per impedire nuovi invii dal web durante la copia finale. Fai doppio clic su Manage-MK8DX-No-Docker.cmd, digita 3 e premi Invio. Scrive il backup in Documents\MK8DX-backups\a3-<date and time> e lo verifica subito.

“Backup verificato” conferma la copia del database, il profilo e le chiavi. Conserva l'intera cartella anche su un supporto protetto fuori da questo computer. Per verificare di nuovo questo backup esatto, esegui:

python tooling/install.py verify-backup --state-dir "$env:LOCALAPPDATA\MK8DX\NoDocker" --backup-output "$env:USERPROFILE\Documents\MK8DX-backups\a3-2026-10-01"

Backup notturno: il primo avvio attiva anche un backup verificato ogni notte alle 03:15. L'Utilità di pianificazione di Windows lo crea con il tuo account, senza diritti di amministratore, in Documents\MK8DX-backups\automatic; se a quell'ora il computer è spento, viene eseguito appena possibile dopo. Se la finestra MK8DX è chiusa, il backup avvia e ferma da solo il proprio database. Controllalo in PowerShell nella cartella del pacchetto:

python tooling/install.py backup-status --state-dir "$env:LOCALAPPDATA\MK8DX\NoDocker"

Dovresti vedere "enabled": true e "scheduler": "windows-task"; dopo la prima notte anche "lastResult": "ok". Se compare "enabled": false anche se non l'hai mai disattivato (un pacchetto precedente non poteva attivarlo), esegui una volta lo stesso comando con backup-schedule al posto di backup-status; anche il prossimo aggiornamento con il passaggio 11 lo attiva. Per disattivarlo usa backup-unschedule.

11. Per un aggiornamento del software, ferma Apache e crea e verifica un backup mentre la vecchia finestra MK8DX è ancora in esecuzione. Poi premi Ctrl+C in quella finestra. Verifica ed estrai il nuovo ZIP A3 accanto al vecchio pacchetto. Continua a usare la stessa cartella dati %LOCALAPPDATA%\MK8DX\NoDocker. In PowerShell all'interno del nuovo pacchetto, avvia temporaneamente solo il suo database:

python tooling/install.py maintenance --state-dir "$env:LOCALAPPDATA\MK8DX\NoDocker"

Lascia aperta quella finestra. Apri una seconda finestra PowerShell nel nuovo pacchetto e aggiorna con una nuova cartella di backup diversa:

python tooling/install.py upgrade --state-dir "$env:LOCALAPPDATA\MK8DX\NoDocker" --backup-output "$env:USERPROFILE\Documents\MK8DX-backups\a3-update-2026-10-01"

Attendi “unchanged” (invariato) per entrambi gli insiemi di riferimento e “Backup verificato”. Premi Ctrl+C nella finestra di manutenzione. Avvia Start-MK8DX-No-Docker.cmd dal nuovo pacchetto e di nuovo Apache. L'assistente aggiorna i percorsi derivati del pacchetto senza azzerare account, chiavi o dati. Controlla lo stesso accesso, i riferimenti e il risultato di prova. Non trattare un cambio del motore di database come un normale aggiornamento di MK8DX.

12. Per provare un ripristino su un altro computer Windows, installa lì XAMPP Apache, Node 24 e Python come ai passaggi 1 e 2. Estrai lo stesso pacchetto A3 e configura Apache con configure_xampp.ps1 come al passaggio 4. Copia in modo privato l'intera cartella di backup verificata in Documents\MK8DX-backups. Non usare una cartella dati esistente su quel computer. Apri PowerShell nel nuovo pacchetto e crea solo il nuovo profilo:

python tooling/install.py wizard --state-dir "$env:LOCALAPPDATA\MK8DX\NoDocker"

Scegli A3 e per ora inserisci il tuo indirizzo di amministratore; il ripristino rimetterà il profilo dell'account originale. Apri una seconda PowerShell nello stesso pacchetto. Nella prima finestra avvia solo il nuovo MariaDB vuoto:

python tooling/install.py maintenance --state-dir "$env:LOCALAPPDATA\MK8DX\NoDocker"

Tieni aperta questa finestra. Nella seconda finestra usa il nome effettivo della tua cartella di backup, senza parentesi angolari:

python tooling/install.py restore-local --backup-input "$env:USERPROFILE\Documents\MK8DX-backups\a3-2026-10-01" --state-dir "$env:LOCALAPPDATA\MK8DX\NoDocker"

Aspettati “Backup verificato” e poi un controllo superato di tutte le migrazioni. Premi Ctrl+C nella finestra di manutenzione. Apri Start-MK8DX-No-Docker.cmd e avvia Apache nel XAMPP Control Panel. Accedi con un account esistente del backup e controlla l'accesso da amministratore e un risultato noto. Il primo amministratore non viene assegnato di nuovo. Se il computer di destinazione ha già un'installazione MK8DX o un altro processo sulla porta 18306, non usarlo come destinazione di questo ripristino; l'assistente non cancella un database esistente. Conserva intatto il backup originale.

13. Per rimuovere questa installazione A3 dal computer, fai prima un backup come nel passaggio 10 se forse vorrai riavere in seguito account e risultati. I backup in Documents\MK8DX-backups restano finché non li elimini tu. In PowerShell nella cartella del pacchetto, disattiva il backup notturno:

python tooling/install.py backup-unschedule --state-dir "$env:LOCALAPPDATA\MK8DX\NoDocker"

Ferma Apache in XAMPP Control Panel e premi Ctrl+C nella finestra MK8DX. Poi togli il sito MK8DX da Apache:

powershell -ExecutionPolicy Bypass -File .\tooling\configure_xampp.ps1 -XamppRoot 'C:\xampp' -Remove

Dovresti vedere “MK8DX Apache site removed” e “Syntax OK”. Vengono rimossi solo la riga Include e mk8dx-local.conf del passaggio 4; gli altri siti web e database di XAMPP restano come sono. Poi elimina le cartelle %LOCALAPPDATA%\MK8DX\NoDocker (database, account e chiavi) e %LOCALAPPDATA%\MK8DX\ApacheBackup e infine la cartella del pacchetto. XAMPP, Node.js e Python restano installati; rimuovili da Impostazioni di Windows → App solo se nient'altro li usa. Se usi XAMPP per altri siti web, avvia di nuovo Apache.

Usalo sulla tua rete domestica

Per una rete di casa o del club, usa il pacchetto A2. Scarica mk8dx-a2-windows-amd64-v0.2.10.zip (Linux: mk8dx-a2-linux-amd64 o mk8dx-a2-linux-arm64; macOS con Apple silicon: mk8dx-a2-macos-arm64; macOS con un processore Intel: mk8dx-a2-macos-amd64) e SHA256SUMS.txt, verifica il checksum come in “Provalo su un computer”, estrai il pacchetto e fai doppio clic su Start-MK8DX-LAN.cmd (Linux e macOS: sh tooling/start-mk8dx.sh). Nel browser si apre una configurazione che ti guida in tutto con Next (Avanti): l'indirizzo di rete, il tuo account amministratore, un codice di ripristino su carta per i backup notturni e le persone, ciascuna con una scheda di accesso per il proprio telefono o PC. Non servono internet, un server di posta né un file hosts.

La guida completa passo dopo passo, con immagini, è docs/install/A2_HOME_GUIDE_EN.md; all'interno del pacchetto è anche docs/install/guide/en.html, e la configurazione la apre dal suo link Manual (Manuale). Tratta la preparazione di Windows, Linux o macOS, di telefoni e PC, l'app Android, LiveTrial, le serate di torneo, i backup, il passaggio a un nuovo computer, un indirizzo fisso, un nuovo indirizzo di rete, gli aggiornamenti e la rimozione di MK8DX da un computer.

Avanzato: con il tuo server di posta

Il resto di questo capitolo descrive una variante più vecchia e avanzata con un nome host privato e link di accesso via email tramite il tuo server di posta. La maggior parte delle persone non ne ha bisogno. Usa il pacchetto mk8dx-host-local e la scelta A2 nella sua domanda di configurazione.

Questa via crea una seconda installazione MK8DX separata su un host Windows. La tua prova su un computer resta intatta. La prima via client documentata è un secondo PC Windows con Chrome o Edge, compreso il caricamento di immagini nello scanner. Un secondo PC fisico o un telefono non hanno ancora avuto un vero collaudo da parte di utenti. L'app Android generica non si fida automaticamente del certificato locale; per essa usa un indirizzo di community HTTPS pubblico su hosting condiviso o su un VPS.

Il sito web di rete usa la porta 443 sul suo host. Se XAMPP Apache gira sullo stesso computer, potrebbe già occupare quella porta. A2 e quel sito Apache non possono allora avviarsi insieme su questo host. Usa un altro host Windows per A2, oppure ferma Apache durante un periodo programmato nel XAMPP Control Panel. Gli altri siti web XAMPP non sono disponibili mentre è fermo.

Prepara prima sull'host Docker Desktop, Python e il pacchetto host verificato ed estratto, come nei primi tre passaggi di “Provalo su un computer”. Non devi creare un'installazione A1. Entrambi i PC devono essere sulla stessa rete privata attendibile. Non usare il Wi-Fi ospiti e non inoltrare una porta del router verso internet. Tieni l'host attivo.

1. Sull'host, trova il suo indirizzo IPv4 in Impostazioni → Rete e Internet → Ethernet o Wi-Fi → Proprietà. In questa guida, 192.168.0.50 è solo un esempio. Annota il tuo indirizzo effettivo. Imposta il profilo di rete di Windows su Privato solo se questa è davvero la tua rete attendibile. Se l'indirizzo cambia in seguito, aggiorna entrambi i PC; una prenotazione DHCP nel router può evitare i cambi.

2. Usa lo stesso nome privato su entrambi i PC Windows. Avvia Blocco note con “Esegui come amministratore”. Scegli File → Apri, vai in questa cartella e cambia il filtro in “Tutti i file”:

C:\Windows\System32\drivers\etc\

Apri hosts. Aggiungi una riga con il vero IP dell'host e il nome privato, per esempio:

192.168.0.50 mk8dx.home.arpa

Salvalo come hosts, senza .txt. Fai lo stesso sull'host e sul secondo PC. Controlla su entrambi in PowerShell:

ping -n 1 mk8dx.home.arpa

L'IP del tuo host dovrebbe comparire prima dei risultati del ping. Il firewall potrebbe bloccare il ping stesso. Ogni dispositivo ha bisogno della propria voce hosts, perché questo nome privato non ha un record DNS pubblico.

3. I link di accesso per gli altri utenti richiedono un vero servizio email. Ottieni dal tuo provider di posta il nome del server SMTP in uscita, la porta 465 con TLS implicito, il login, la password e l'indirizzo mittente autorizzato. Un servizio che offre solo STARTTLS sulla porta 587 non è adatto alla procedura guidata attuale. Il tuo futuro indirizzo di amministratore MK8DX è un valore separato. Non usare Mailpit come casella di accesso condivisa.

4. Sull'host, fai doppio clic su Start-MK8DX-LAN.cmd. Scegli A2 e conferma mk8dx.home.arpa, oppure inserisci esattamente il nome dei tuoi file hosts. Inserisci separatamente il vero indirizzo IPv4 dell'host. La procedura guidata chiede poi i valori della posta e il tuo futuro indirizzo di amministratore. La password della posta resta nascosta mentre la digiti. La prima configurazione parte da sola. La cartella dati separata è %LOCALAPPDATA%\MK8DX\LAN. L'indirizzo del sito web mostrato dovrebbe essere https://mk8dx.home.arpa.

Usa questo indirizzo HTTPS anche in LiveTrial sull'host e sul secondo PC. Non devi scrivere la sua porta standard 443 dopo il nome. Usa l'indirizzo IPv4 che hai trovato per la voce hosts e le impostazioni di rete, non come indirizzo della community in LiveTrial. Questa via di rete usa il tuo vero provider di posta: la posta di accesso arriva nella normale casella dell'indirizzo che hai inserito. Qui gli utenti non hanno un indirizzo Mailpit locale.

5. Sull'host, apri Sicurezza di Windows → Firewall e protezione della rete → Impostazioni avanzate → Regole connessioni in entrata → Nuova regola. Scegli Porta, TCP, porta locale specifica 443, “Consenti la connessione” e solo il profilo Privato. Dai un nome alla regola, per esempio “MK8DX LAN HTTPS”. In Ambito, limita gli indirizzi remoti alla tua rete se ne conosci la subnet. Non aprire il database o Mailpit alla rete pubblica.

6. Il secondo PC Windows deve fidarsi del certificato locale di questa specifica installazione. Fallo solo su un computer che gestisci tu. Apri PowerShell sull'host nella cartella del pacchetto estratto ed esegui queste tre righe una alla volta:

$state = Join-Path $env:LOCALAPPDATA 'MK8DX\LAN'
$compose = @('--env-file', (Join-Path $state 'compose.env'), '-f', 'compose.yaml', '-f', 'compose.lan.yaml', '-f', 'compose.images.yaml')
docker compose @compose cp web:/data/caddy/pki/authorities/local/root.crt (Join-Path $env:USERPROFILE 'Downloads\mk8dx-lan-root.crt')

Controlla l'impronta del certificato sull'host:

Get-FileHash (Join-Path $env:USERPROFILE 'Downloads\mk8dx-lan-root.crt') -Algorithm SHA256

Trasferisci solo mk8dx-lan-root.crt sul secondo PC con un metodo attendibile. Annota l'impronta separatamente. Non copiare mai root.key, l'intera cartella Caddy o i segreti di MK8DX. Sul secondo PC, verifica il file nella sua cartella di download:

Get-FileHash '.\mk8dx-lan-root.crt' -Algorithm SHA256

Quando i valori corrispondono esattamente, fai doppio clic sul certificato. Scegli Installa certificato → Utente corrente → Colloca tutti i certificati nel seguente archivio → Sfoglia → Autorità di certificazione radice attendibili → Fine. Riavvia il browser. Non installare un certificato la cui impronta è diversa. Non aggirare un avviso del browser.

7. Sul secondo PC, apri https://mk8dx.home.arpa. Non dovrebbe esserci nessun avviso sul certificato. Prova anche https://mk8dx.home.arpa/scanner/ con una tua immagine di prova. Accedi con il tuo indirizzo e segui il link nella tua vera casella di posta. Dopo quell'accesso, puoi riaprire Start-MK8DX-LAN.cmd sull'host e scegliere il menu 5 per assegnare una volta i diritti di amministratore all'indirizzo salvato. Gli utenti e gli amministratori di A1 non passano automaticamente ad A2.

Se l'IP dell'host cambia in seguito, aggiorna prima hosts su entrambi i PC. Sull'host, apri PowerShell nella cartella del pacchetto e sostituisci l'IP di esempio qui sotto con il nuovo indirizzo reale:

python tooling/install.py change-lan-address --state-dir (Join-Path $env:LOCALAPPDATA 'MK8DX\LAN') --lan-bind-address '192.168.0.51'
python tooling/install.py apply --state-dir (Join-Path $env:LOCALAPPDATA 'MK8DX\LAN')

Controlla di nuovo l'indirizzo, il sito web e la posta di accesso. Il secondo PC continua a fidarsi del certificato finché si tratta della stessa installazione A2. Il ripristino in un nuovo progetto crea una nuova autorità di certificazione locale; vedi “Ripristinare un backup”.

Hosting condiviso pubblico con Node.js, senza Docker

Questa via usa Node.js con Passenger e MariaDB, come offerto da hosting condivisi quali mijn.host Starter. Non richiede un VPS, Docker, accesso root o un tuo server Caddy. Il pacchetto è testato su una configurazione locale Linux e MariaDB. Dovrai comunque verificare i passaggi nel tuo account DirectAdmin e la consegna effettiva della posta. Usa un (sotto)dominio separato e un database vuoto. Non modificare un sito web o un database esistente. Starter indica attualmente 2 GB di RAM e 5 GB di spazio; controlla nel tuo pannello che ci sia spazio sufficiente per il caricamento, le dipendenze npm, i dati e i backup.

1. Scarica mk8dx-mijnhost-node-v0.2.10.zip e SHA256SUMS.txt dalla pagina delle release indicata in Benvenuto. Questo ZIP è il pacchetto da caricare. Lo ZIP host Docker e lo ZIP del codice sorgente completo sono file diversi. Metti i due file in una cartella sul tuo PC Windows. Apri PowerShell lì e confronta l'intero valore SHA-256 con la riga in SHA256SUMS.txt:

Get-FileHash '.\mk8dx-mijnhost-node-v0.2.10.zip' -Algorithm SHA256

Fermati se i valori sono diversi.

2. Sul tuo PC, accedi al pannello clienti di mijn.host. Apri il tuo piano di hosting, poi DirectAdmin. Seleziona in alto a destra il dominio o sottodominio per questo nuovo sito MK8DX. www.mijneigenwebsite.nl è solo un esempio; usa il tuo vero nome host. In Account Manager → SSL Certificates, controlla che “Get automatic certificate from ACME Provider” (ottieni un certificato automatico dal provider ACME) includa esattamente quel nome. In seguito il tuo browser non deve mostrare alcun avviso sul certificato. Se gestisci il DNS altrove, punta prima quel nome host a questo piano di hosting. Non modificare i record di posta esistenti solo per il sito web.

Guida Node.js di DirectAdmin: https://mijn.host/kb/web-apps/node-js-applicatie-draaien-op-je-hostingpakket
Let's Encrypt in DirectAdmin: https://mijn.host/kb/webhosting/lets-encrypt-ssl-certificaat-aanvragen

3. In DirectAdmin, in Account Manager → MySQL Management o Databases, crea un nuovo database vuoto e un utente limitato a quel database. Annota i nomi completi mostrati dal pannello, compreso un eventuale prefisso dell'account, come account_mk8dx e account_mk8dxuser. Tieni privata la password generata. Non usare un account root. Trova l'host del database nel tuo pannello o nei dettagli del tuo account. Può essere localhost, ma inserisci solo il valore effettivo mostrato. La porta 3306 è l'esempio abituale. MK8DX controlla il motore e la versione reali prima della migrazione. Questa release richiede MariaDB 11.4 o successivo oppure MySQL 8.4 o successivo; un'etichetta del pannello che dice “MySQL” non dimostra la versione.

4. Apri DirectAdmin → E-mail Manager → E-mail Accounts. Crea o scegli una casella di posta che puoi usare per questo sito. Annota il suo indirizzo completo, la password e il nome del server in uscita. Una forma comune è mail.mijneigenwebsite.nl sulla porta 465 con SSL/TLS; ottieni il nome effettivo del server dal tuo account. Il login SMTP, il mittente visibile e il futuro indirizzo di amministratore MK8DX hanno scopi separati. La casella inclusa basta quando il tuo account le permette di inviare.

Impostazioni di posta su mijn.host: https://mijn.host/kb/email/e-mail-account-instellen-in-gmail

5. In DirectAdmin, apri Extra Features → Setup Node.js App → Create Application. Seleziona Node.js 24 se il tuo pannello lo offre. Scegli Production per il sito definitivo, Application root apps/mk8dx fuori da public_html, Application URL alla radice del dominio scelto e Application startup file api/dist/composition/passenger-hosted-main.js. Il pannello potrebbe mostrare prima un app.js predefinito; cambia l'impostazione di avvio nel file indicato prima di riavviare MK8DX. Copia la riga esatta di attivazione dell'ambiente Node mostrata in cima al tuo pannello. Se Node 24 o l'impostazione di avvio non sono disponibili, non tentare con una versione di Node più vecchia; si tratta di una verifica specifica dell'account.

6. Trova il tuo nome server e il tuo nome utente SSH nel pannello di mijn.host. Sul tuo PC Windows, apri PowerShell e connettiti sulla porta SSH documentata 26. Confronta l'impronta della chiave host SSH con un valore fornito in modo indipendente da mijn.host prima di accettarla. B2 funziona su qualsiasi host Node.js condiviso che ti dia SSH; mijn.host è l'esempio testato, e la porta 26 è la porta SSH di quel provider, quindi altrove usa la porta del tuo host (spesso 22). Il pacchetto mantiene il nome mk8dx-mijnhost-node. Sostituisci gli esempi tra parentesi angolari con i tuoi valori, omettendo le parentesi:

ssh -p 26 <your-username>@<your-server-name>

Dovresti arrivare a un prompt Linux. Conserva la password dell'account nel tuo gestore di password. Questo non è un accesso root a un VPS. La stessa via SSH trasferisce lo ZIP verificato. Apri una seconda finestra PowerShell sul tuo PC nella cartella di download:

scp -P 26 '.\mk8dx-mijnhost-node-v0.2.10.zip' <your-username>@<your-server-name>:

Lo ZIP compare nella tua cartella home dell'hosting. Un'opzione SFTP separata potrebbe avere impostazioni diverse; questa via usa solo l'accesso SSH/SCP documentato.

SSH su mijn.host: https://mijn.host/kb/webhosting/verbinden-met-ssh

7. Torna alla finestra SSH. Controlla che ci siano Python 3.9 o successivo, unzip e un client di dump di MariaDB. L'applicazione è già compilata; Python esegue solo l'assistente di installazione esistente:

python3 --version
command -v unzip
command -v mariadb-dump || command -v mysqldump

Se manca un comando, confronta esattamente quello strumento mancante con il tuo pannello di hosting o con l'aiuto di mijn.host. Non creare un URL di configurazione pubblico non protetto. Estrai lo ZIP nella tua cartella privata dell'applicazione, non in public_html:

mkdir -p "$HOME/apps/mk8dx"
unzip "$HOME/mk8dx-mijnhost-node-v0.2.10.zip" -d "$HOME/apps/mk8dx"
cd "$HOME/apps/mk8dx"

Dovresti vedere api, web, scanner, assets, mysql e tooling. La cartella dell'applicazione è privata. Il programma di installazione conserva anche il profilo, i segreti e i backup fuori da public_html.

8. In quella finestra SSH, incolla la riga esatta di attivazione di Node mostrata dal tuo pannello Setup Node.js App. Di solito inizia con source e termina con cd nella tua Application root. Poi esegui:

node --version
cd "$HOME/apps/mk8dx/api"
npm ci --omit=dev --ignore-scripts --no-audit --no-fund
cd "$HOME/apps/mk8dx"

Aspettati Node 24 e un'installazione completata delle dipendenze di produzione bloccate. Questo non compila TypeScript. api/node_modules appartiene al tuo host Linux; non caricare node_modules di Windows. Se lo spazio è esaurito, fermati e controlla lo spazio libero invece di eliminare altri dati dell'account.

9. Avvia l'inserimento guidato dalla cartella dell'applicazione:

python3 tooling/install.py wizard --state-dir "$HOME/mk8dx-private"

Scegli B2. Inserisci il nome host esatto del tuo sito HTTPS senza https://, poi l'host del database, la porta, il nome completo del database e dell'utente, e la password nascosta del database del passaggio 3. Inserisci l'host SMTP, la porta 465, il login completo della casella, la password nascosta della casella e il mittente consentito del passaggio 4. Come indirizzo di amministratore, inserisci l'indirizzo email personale su cui riceverai il link di accesso. Può essere diverso dal login SMTP. L'assistente scrive operator-profile.json, secrets.json e operator.json in $HOME/mk8dx-private con permessi limitati. Non ripetere gli stessi valori in un altro file .env.

10. Controlla la versione del database, poi applica tutte le migrazioni ed entrambi gli insiemi di riferimento solo al tuo nuovo database vuoto:

python3 tooling/install.py check-database --state-dir "$HOME/mk8dx-private"
python3 tooling/install.py setup --state-dir "$HOME/mk8dx-private"
python3 tooling/install.py check --state-dir "$HOME/mk8dx-private"

La prima riga dovrebbe mostrare la versione misurata di MariaDB o MySQL e tableCount 0. Fermati se il motore è troppo vecchio o se il database contiene tabelle inattese. Dopo setup, aspettati tutte le migrazioni applicate, Staff Nintendo e Record mondiali segnati come applicati, poi ready (pronto). Il programma di installazione non azzera mai uno schema popolato sconosciuto.

11. Genera le impostazioni di Passenger e avvia tramite il pannello:

python3 tooling/install.py passenger-config --state-dir "$HOME/mk8dx-private"

Questo crea mk8dx-hosted.env.json nella Application root privata, fuori da public_html. Non spostare mai quella cartella o $HOME/mk8dx-private in una cartella di file pubblica. In DirectAdmin → Extra Features → Setup Node.js App, seleziona la tua app MK8DX e fai clic su Restart. Il provider gestisce il suo processo e HTTPS; non eseguire un server aggiuntivo con nohup o PM2. Con il tuo vero nome host, controlla /health/ready, la home page, /scanner/, /client-config.json e /.well-known/assetlinks.json. Un URL JSON o API sconosciuto non deve restituire la home page HTML. Le richieste di /secrets.json, /.env o di un backup non devono rivelare alcun contenuto.

12. Sul sito, fai clic su Accedi con l'indirizzo di amministratore del passaggio 9. Apri il link nella tua vera casella di posta e accedi. Solo allora torna a SSH, riattiva se necessario l'ambiente Node del pannello, vai nella cartella dell'applicazione ed esegui:

cd "$HOME/apps/mk8dx"
python3 tooling/install.py admin --state-dir "$HOME/mk8dx-private"

Aspettati created (creato), oppure unchanged (invariato) se ripetuto. Aggiorna il sito web. La sola prima iscrizione non concede mai l'amministrazione. Controlla un percorso, Staff Nintendo e il Totale dei Record mondiali, la tua Prova a tempo e un caricamento nello scanner. Se la vera posta di accesso non funziona, controlla il login della casella, il mittente e TLS; ready non dimostra la consegna a una casella esterna.

13. Per un backup, ferma brevemente il traffico dei visitatori con il pulsante Stop di questa app Node in DirectAdmin. Il database MariaDB resta disponibile. In SSH, dalla cartella dell'applicazione, scegli il nome di una nuova cartella privata:

python3 tooling/install.py backup --state-dir "$HOME/mk8dx-private" --backup-output "$HOME/mk8dx-backups/b2-2026-10-01"

L'assistente riporta Backup verificato. Conserva una copia protetta anche fuori da questo account di hosting. Riavvia l'app Node in DirectAdmin e controlla ready. Il backup include account, assegnazioni di amministratore e chiavi; non caricarlo mai in public_html o su un link pubblico.

14. Per un aggiornamento, verifica il nuovo ZIP B2 sul tuo PC. Ferma l'app Node in DirectAdmin e crea un backup verificato con la vecchia applicazione. Carica il nuovo ZIP con la stessa via SSH/SCP. In SSH, rinomina la vecchia cartella dell'applicazione, poi creane una nuova vuota. Usa questi comandi solo quando il nuovo ZIP è nella tua cartella home e non esiste ancora una cartella mk8dx-before-update:

cd "$HOME"
mv "$HOME/apps/mk8dx" "$HOME/apps/mk8dx-before-update"
mkdir -p "$HOME/apps/mk8dx"
unzip "$HOME/mk8dx-mijnhost-node-v0.2.10.zip" -d "$HOME/apps/mk8dx"

Incolla di nuovo la riga di attivazione di Node 24 da DirectAdmin. Installa le dipendenze Linux bloccate nella nuova cartella api e torna alla radice dell'applicazione:

cd "$HOME/apps/mk8dx/api"
npm ci --omit=dev --ignore-scripts --no-audit --no-fund
cd "$HOME/apps/mk8dx"

Mantieni la stessa cartella dati privata. Usa una nuova cartella di backup diversa:

python3 tooling/install.py upgrade --state-dir "$HOME/mk8dx-private" --backup-output "$HOME/mk8dx-backups/b2-update-2026-10-01"
python3 tooling/install.py passenger-config --state-dir "$HOME/mk8dx-private"

Poi riavvia solo questa app in DirectAdmin. Controlla il sito web, l'accesso, l'amministrazione e i risultati noti. Dopo una migrazione dello schema non ripristinare alla cieca solo i vecchi file Web. Un cambio di versione di MariaDB non è un normale aggiornamento di MK8DX.

15. Per il recupero, usa un nuovo database vuoto e un sottodominio di prova separato sullo stesso motore di database testato e sulla stessa serie di versioni. Metti il pacchetto B2 verificato e il backup privato completo in quell'installazione separata. In DirectAdmin crea un'app Node separata per la prova di ripristino con Application root apps/mk8dx-restore e Application URL sul sottodominio di prova. Estrai lo ZIP B2 in quella nuova cartella privata. Attiva Node 24 con la riga di questa nuova schermata dell'app, esegui npm ci --omit=dev --ignore-scripts --no-audit --no-fund all'interno di apps/mk8dx-restore/api, poi vai in apps/mk8dx-restore. Il ripristino guidato chiede i dati del nuovo database senza mostrare la password e riusa i vecchi account e le vecchie chiavi:

python3 tooling/install.py restore-wizard --backup-input "$HOME/mk8dx-backups/b2-2026-10-01" --state-dir "$HOME/mk8dx-private-restore"
python3 tooling/install.py passenger-config --state-dir "$HOME/mk8dx-private-restore"

In DirectAdmin, collega questa app Passenger separata al sottodominio di prova e alla Application root privata. Avviala e controlla ready, un accesso esistente, l'amministrazione e i risultati. Non creare un altro primo amministratore. Un vero cambio di dominio e un backup del provider sono passaggi separati che fai tu.

Crea un sito web pubblico su un VPS

Un VPS è un tuo computer su internet. Questa via usa Ubuntu 24.04 LTS su x86-64. La capacità consigliata è di 2 core CPU, 8 GB di RAM e 40 GB di SSD, più spazio per i dati e i backup futuri. Mijn.host unmanaged VPS M indica questa capacità e root/SSH sulla sua pagina VPS, ma MK8DX non è stato testato su quel piano esatto. Resti responsabile di Ubuntu, Docker, posta, aggiornamenti di sicurezza e backup.

Panoramica VPS di Mijn.host: https://mijn.host/vps

Mijn.host Starter usa la via separata Node/Passenger qui sopra. Questo capitolo sul VPS usa Docker e non si applica a un normale piano Starter.

Panoramica hosting condiviso di Mijn.host: https://mijn.host/webhosting

Prima della prima configurazione, ti servono un tuo dominio, un account VPS adatto con IPv4 e Ubuntu, l'accesso alla gestione DNS e un servizio di posta che usi SMTP 465 con TLS implicito. Sostituisci ovunque l'esempio www.mijneigenwebsite.nl con il tuo nome host. L'IP di esempio 203.0.113.10 non è un server reale. Il login del provider, la chiave SSH, l'indirizzo di amministratore MK8DX e il login SMTP servono a scopi diversi. Tieni private password e chiavi.

1. Sul tuo PC Windows, crea una chiave di accesso se il tuo VPS usa chiavi SSH. Apri PowerShell ed esegui:

New-Item -ItemType Directory -Force (Join-Path $env:USERPROFILE '.ssh')
ssh-keygen -t ed25519 -f (Join-Path $env:USERPROFILE '.ssh\mk8dx_vps_ed25519')

Quando richiesto, scegli una passphrase robusta. Il file senza .pub è privato. Apri il file .pub nel Blocco note e aggiungi solo quella chiave pubblica tramite la funzione chiavi SSH del portale di gestione del tuo VPS. Il pulsante esatto varia a seconda del provider; se non lo trovi, chiedi al provider dove si trova. Non mettere mai la chiave privata in una cartella web o sul server.

2. Installa WinSCP dal suo sito ufficiale. Apri WinSCP → New Site. Scegli SFTP. Inserisci il vero IP del VPS in Host name, la porta SSH effettiva in Port number e l'account VPS in User name. Usa root per la via root descritta solo se il tuo provider lo fornisce. Per l'accesso con chiave, apri Advanced → SSH → Authentication → Private key file e seleziona la chiave privata del passaggio 1. WinSCP propone di convertire la chiave OpenSSH in un file .ppk; salvalo accanto alla tua chiave privata e usalo in WinSCP. La passphrase serve comunque.

WinSCP: https://winscp.net/eng/download.php
Formati delle chiavi WinSCP: https://winscp.net/eng/docs/ui_login_authentication

Ottieni l'impronta della chiave host SSH tramite la console VPS indipendente del tuo provider o il supporto. Confrontala con il messaggio della prima connessione in WinSCP. Accetta solo una corrispondenza esatta. Trascina il file verificato mk8dx-host-local-v0.2.10-amd64.zip dal lato sinistro, il tuo PC, in /root/ sul lato destro, il server. Non caricare backup o segreti in public_html.

3. Apri PowerShell sul tuo PC per il terminale del server. Usa il tuo vero IP, la porta e il percorso della chiave. È la stessa chiave OpenSSH del passaggio 1, non il file .ppk convertito:

$serverIp = '203.0.113.10'
$sshPort = 22
$key = Join-Path $env:USERPROFILE '.ssh\mk8dx_vps_ed25519'
ssh -i $key -p $sshPort "root@$serverIp"

Confronta anche qui l'impronta della chiave host con il valore ottenuto in modo indipendente. Solo allora inserisci la passphrase della chiave. Se il tuo provider indica un altro utente VPS o un'altra porta SSH, sostituisci root o 22. Le porte dell'hosting condiviso non sono impostazioni del VPS.

Nel terminale Ubuntu, controlla la macchina:

cat /etc/os-release
uname -m
free -h
df -h /
python3 --version

Ti aspetti Ubuntu 24.04, x86_64 e Python dalla 3.12 alla 3.15. Se Python manca su un server Ubuntu 24.04 appena installato, esegui:

apt update
apt install python3
python3 --version

Non procedere se la macchina non è Linux x86-64; il pacchetto di immagini fornito è amd64.

4. Controlla se Docker funziona già:

command -v docker
docker compose version

Se manca, usa su questo server il metodo apt ufficiale di Docker per Ubuntu. Esegui ogni gruppo nello stesso terminale del server e fermati se un comando non riesce:

Docker per Ubuntu: https://docs.docker.com/engine/install/ubuntu/

apt update
apt install ca-certificates curl unzip
install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
chmod a+r /etc/apt/keyrings/docker.asc

Aggiungi la fonte ufficiale dei pacchetti. Copia queste righe insieme, compreso l'EOF finale:

cat > /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
apt update
apt install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

Controlla:

systemctl is-active docker
docker compose version

La prima risposta dovrebbe essere active. Se c'è un errore, non installare a caso una seconda variante di Docker; leggi l'errore e la pagina ufficiale.

5. Nel pannello DNS di chi gestisce il tuo dominio, apri i record del dominio. Per un nome come www.mijneigenwebsite.nl, crea un record A con nome www e come valore il vero indirizzo IPv4 del tuo VPS. Mantieni i record di posta esistenti. Usa il TTL predefinito o 300 secondi. Dopo che la modifica si è propagata, controlla sul tuo PC:

Resolve-DnsName www.mijneigenwebsite.nl -Type A

La risposta dovrebbe essere l'IP del tuo VPS. Controlla un eventuale record AAAA esistente per lo stesso nome: mantienilo solo se punta a un sito IPv6 funzionante. Nel pannello del provider del VPS, consenti TCP 80 e 443 in entrata. Mantieni raggiungibile la tua porta SSH e non pubblicare la porta MySQL 3306. Non fare modifiche ampie al firewall a meno che tu non sappia come riottenere l'accesso al server.

6. Ottieni dal tuo provider di posta l'host SMTP in uscita, la porta 465 con TLS implicito, il login, la password e l'indirizzo mittente autorizzato. Controlla che l'invio dal tuo VPS sia consentito. È diverso dal tuo indirizzo di amministratore MK8DX. Questa guida non ha testato la consegna tramite un provider reale; l'installazione riesce solo quando il tuo link di accesso raggiunge la tua vera casella di posta.

7. Nel terminale Ubuntu, lo ZIP trasferito con WinSCP si trova in /root/. Verificalo ed estrailo:

pwd
ls -lh /root/mk8dx-host-local-v0.2.10-amd64.zip
mkdir -p /opt/mk8dx/host /var/lib/mk8dx
unzip -q /root/mk8dx-host-local-v0.2.10-amd64.zip -d /opt/mk8dx/host
cd /opt/mk8dx/host
ls Start-MK8DX.cmd compose.yaml tooling/start-mk8dx.sh images/docker-images-amd64.tar

Se manca un nome, controlla di aver estratto lo ZIP corretto e completo. Avvia l'assistente di configurazione esistente:

sh tooling/start-mk8dx.sh /var/lib/mk8dx/instance

Scegli B1. Inserisci il tuo nome host esatto senza https://. Inserisci i cinque valori della posta e il tuo futuro indirizzo di amministratore MK8DX. La password SMTP resta nascosta. Scegli il menu 1. L'assistente crea il database interno, le chiavi e le connessioni. In caso di ripetizione, usa la stessa cartella /var/lib/mk8dx/instance; non creare un altro profilo per aggirare un problema di DNS o di posta.

8. Sul tuo PC, apri l'indirizzo di prontezza e poi il sito web, usando il tuo nome host al posto dell'esempio:

https://www.mijneigenwebsite.nl/health/ready
https://www.mijneigenwebsite.nl

Il browser non dovrebbe mostrare alcun avviso sul certificato. Fai clic su Accedi, usa il tuo indirizzo di amministratore salvato e apri il link nella tua vera casella di posta. Solo dopo quell'accesso verificato, torna alla cartella del pacchetto nel terminale del server e scegli il menu 5:

cd /opt/mk8dx/host
sh tooling/start-mk8dx.sh /var/lib/mk8dx/instance

La risposta è created (creato) oppure, in caso di ripetizione, unchanged (invariato). Aggiorna il sito. Controlla anche un percorso e il tuo invio di una Prova a tempo. I container in esecuzione da soli non dimostrano DNS, certificati o consegna della posta.

Usa Android, LiveTrial, lo scanner e Tournament

Per inviare risultati, questi strumenti usano l'indirizzo di una community esistente. LiveTrial e i Tournament Tools funzionano anche da soli, senza un sito web; l'app Android e lo scanner nel browser ne hanno bisogno. Sullo stesso computer Windows, LiveTrial e Tournament possono usare http://127.0.0.1:18080 (A1) o http://127.0.0.1:18090 (A3). Per un sito web pubblico, usa il suo indirizzo HTTPS attendibile. Android richiede HTTPS attendibile; una verifica locale su Windows non dimostra una connessione Android. L'app Android generica e i client Windows ti permettono di scegliere l'indirizzo della community; un dominio diverso non richiede una modifica del codice sorgente. Le impostazioni pubbliche dei client non contengono mai password del server. Non inserire mai in un client il nome interno mysql, l'indirizzo di un container API o un IP SSH.

Copia sempre l'indirizzo completo del sito web mostrato come “Website” (oppure “origin” o “Web origin”) per la tua installazione, compresa la porta quando è indicata. Non inserire mai in LiveTrial l'indirizzo della casella di test (“Sign-in mail” o “localMailInbox”): apre solo la casella di test locale. Su un secondo dispositivo, usa il nome di rete HTTPS o il tuo dominio pubblico, non l'indirizzo 127.0.0.1 del server.

Per Android ti serve Android 8.0 o successivo; è consigliato arm64. L'APK firmato localmente per il rilascio è di circa 530 MB. Tieni liberi almeno 1 GB come margine per l'installazione. Verifica mk8dx-android-release-v0.2.10.apk con SHA256SUMS.txt sul tuo PC, copialo sul telefono e aprilo da File o Download. Se Android chiede di consentire le installazioni da questa app di gestione file, consentilo solo per il pacchetto verificato. In seguito puoi disattivare quel permesso.

Al primo avvio, “Scegli la tua community” chiede come gioca la tua community. Per una community online, inserisci l'indirizzo completo e attendibile HTTPS della community in “Indirizzo del sito web”, come https://www.mijneigenwebsite.nl, senza percorso né barra finale, e tocca “Salva”. Per un'installazione a casa o al club (A2), tocca “Scansiona il codice QR” e scansiona la scheda “Prepara un dispositivo”; la guida A2 spiega questo passaggio passo dopo passo. In seguito, tocca il nome della community in alto nell'app per cambiare community o per aggiungerne una con “Aggiungi una community”. Ogni community conserva il proprio account e i propri tempi in attesa; nulla passa automaticamente dall'una all'altra. I tuoi tempi sono sotto il tuo nome → I miei tempi, anche offline. Per A2, segui il passaggio Fiducia nell'app: salva e installa il certificato MK8DX come certificato CA sul telefono. Poi scansiona la tua scheda personale nell'app e controlla il nome mostrato. Anche il browser ha bisogno del certificato; la guida A2 spiega i passaggi. Questo accesso non usa un codice dispositivo nel browser. I precedenti APK pubblici erano firmati in modalità debug. Salva i risultati non ancora inviati, disinstalla una volta quell'app di debug e poi installa questo APK firmato per il rilascio. Gli APK successivi firmati con la stessa chiave di rilascio possono aggiornarlo sul posto; questa non è una release del Play Store.

Un APK è firmato da chi lo crea, non separatamente per ogni dominio. Gli Android App Links automatici richiedono invece un'associazione pubblica tra la vera identità dell'app, il suo effettivo certificato di firma e il tuo dominio. Il file predefinito /.well-known/assetlinks.json contiene quindi [] come JSON. La scelta manuale del server e l'accesso funzionano senza quell'associazione automatica. Una build personalizzata firmata separatamente appartiene alla via per sviluppatori.

Per LiveTrial su Windows x86-64, verifica desktop-client-v0.2.10.zip con SHA256SUMS.txt ed estrai l'intero ZIP, per esempio in Documenti. Prevedi circa 2 GB per l'estrazione e le tue registrazioni; è un margine, non un minimo misurato. Apri LiveTrial.exe. L'acquisizione dal vivo da una scheda di acquisizione richiede anche FFmpeg, che non è incluso a causa della sua licenza: esegui una volta winget install Gyan.FFmpeg in PowerShell e riavvia LiveTrial (l'analisi dei video funziona senza). Vai in Impostazioni → Indirizzo del sito della community, inserisci l'indirizzo esatto della tua installazione e scegli Salva server. Conferma il cambio.

LiveTrial salva l'indirizzo e si riavvia da solo. Lascia aperta la finestra mentre succede. Dopo il riavvio, controlla che Impostazioni mostri il tuo indirizzo esatto. Solo allora accedi; l'accesso dovrebbe aprire la tua community. Quando apri Storico dei tempi, quella sezione attende brevemente il suo server locale se necessario, poi si carica da sola. Non dovrebbe servirti F5. Se LiveTrial dice che il riavvio automatico non è riuscito, scegli Esci da LiveTrial all'interno dell'app, attendi che si sia chiuso e apri di nuovo LiveTrial.exe. Chiudere solo la finestra del browser non basta: LiveTrial potrebbe continuare a funzionare in background.

Se il campo è ancora vuoto con l'esempio https://www.example.org oppure l'accesso apre il sito sbagliato, fermati. Chiudi l'istanza esistente di LiveTrial con Esci da LiveTrial. Potrebbe averla avviata un altro account Windows sullo stesso PC. Riaprilo e controlla l'indirizzo. Non modificare server.json a mano e non inviare un tempo al sito web sbagliato. Per un file video non ti serve una scheda di acquisizione. L'acquisizione dal vivo richiede una scheda e un driver compatibili. I risultati locali e le code restano separati per ogni server.

Lo scanner nel browser fa già parte del sito web. Apri /scanner/ sul tuo indirizzo HTTPS attendibile e inizia con il caricamento di un'immagine (“image upload” in inglese, “afbeelding uploaden” in olandese). Seleziona una tua immagine dei risultati, controlla i dati riconosciuti e conferma solo dopo averli verificati. L'uso della fotocamera dal vivo richiede il permesso del browser e HTTPS attendibile al di fuori di localhost. Il riconoscimento dipende anche dalla registrazione. La via descritta di A2 con un secondo browser Windows è documentata ma non è stata testata dall'inizio alla fine.

Per Tournament su Windows x86-64, verifica tournament-tools-v0.2.10.zip ed estrai lo ZIP completo. Apri Install-MK8DX-TournamentTools.cmd. Prevedi diversi GB di spazio libero: lo ZIP di circa 450 MB e circa 1,3 GB per l'estrazione non coprono tutte le dipendenze e i tuoi file multimediali. Il programma di installazione ha bisogno di internet una volta, per scaricare Python 3.12 e pacchetti pubblici; i modelli OCR sono inclusi, e dopo l'elaborazione funziona offline. Non è stato misurato un minimo esatto per tutte le dipendenze e i file multimediali. Non serve alcuna impostazione della GPU: con un driver NVIDIA recente il programma di installazione sceglie da solo la versione CUDA, e la scheda grafica velocizza poi la lettura di nomi, punti e tempi (OCR). La prima scansione di una registrazione gira sempre sul processore, perché la build di OpenCV nel pacchetto non ha il supporto CUDA; USING_MK8DX_TOURNAMENT_TOOLS.md nel pacchetto spiega entrambi i passaggi. Attendi SUCCESS e mantieni intatta runtime-assets. Se non riesce, leggi install.log nella cartella del pacchetto.

Trascina una registrazione .mp4 o .mkv su TournamentProcessor.cmd. Il programma crea accanto al video una cartella di sessione con Excel, CSV e un file che termina con _TournamentRaceResultsV1.json. TournamentLive.cmd richiede un hardware di acquisizione adatto e un driver per l'ingresso dal vivo.

Puoi anche provare Tournament Live con un video esistente e senza scheda di acquisizione. Apri TournamentLive.cmd, scegli Aggiungi file video, seleziona un file .mp4 o .mkv, poi scegli Avvia tutto. Attendi che il video e l'analisi finiscano. Controlla Classifiche confermate e scegli Apri le esportazioni per il file dei risultati. Questa normale via video usa la selezione del punteggio che attende che l'animazione dei punti e la classifica finale si stabilizzino. Controlla tu stesso nomi, posizioni e punti; l'OCR può sbagliare. Una riproduzione video non testa una scheda di acquisizione fisica. Il comando di riproduzione separato TournamentLiveCli.cmd è diagnostico e non sostituisce questa via.

Per consegnare l'esecuzione al tuo sito web, scegli Collegati a Tournament Manager in Tournament Live (Cambia Torneo una volta collegato), completa l'accesso nel browser e scegli il torneo dall'elenco. Questa scelta è solo un suggerimento. Sul sito web, apri il torneo, vai al passaggio 5 (passaggio 9 per i gruppi finali) e cerca l'esecuzione in Registrazioni Tournament Live disponibili. Scegli il suo gruppo in Collega al gruppo, poi Collega la registrazione controllata. Le gare restano in attesa come prove finché non le accetti. Tournament Live può aggiungere da solo una scheda di acquisizione che conosce già, come sorgente in più sul Gruppo 1. Se sul Gruppo 1 c'è anche un video, Avvia tutto si ferma e ti chiede di assegnare ogni feed a un gruppo diverso: seleziona la sorgente in più e scegli Rimuovi selezionati, oppure assegnale un gruppo proprio, poi riavvia.

Per il collegamento facoltativo al sito web, apri PowerShell nella cartella del pacchetto ed esegui:

.\TournamentConnect.cmd sign-in

La prima volta inserisci l'indirizzo esatto della tua installazione e completa l'accesso nel browser. Su A1 o A3 è l'indirizzo http://127.0.0.1 mostrato dalla finestra di MK8DX, per esempio http://127.0.0.1:18080; l'HTTP semplice è accettato solo per questi indirizzi su questo PC. Questi comandi mostrano o cambiano l'indirizzo; il cambio chiede una conferma:

.\TournamentConnect.cmd server
.\TournamentConnect.cmd server https://www.example.org

Sostituisci example.org con la tua vera community. I caricamenti in sospeso per il vecchio server restano con il vecchio server. Per inviare un file con TournamentConnect.cmd send, l'amministratore apre prima Amministrazione → Tornei → Direttori, cerca il Giocatore che ha effettuato l'accesso e seleziona il nome. Questo concede l'accesso ai Tornei, non l'amministrazione generale. Invia di nuovo; la gara resta in Risultati in arrivo finché non viene controllata. Sul sito web, un amministratore importa un risultato verificato tramite Amministrazione → Tornei → Importa i risultati canonici delle gare, oppure all'interno di un gruppo tramite Alternativa offline: importa un file di risultati Live / Processor salvato. Il caricamento non è una pubblicazione automatica.

Per un nuovo torneo, l'amministratore apre Amministrazione → Tornei e crea lì il torneo. Aggiungi i giocatori, segna chi è presente, assegna le Switch disponibili e conferma la disposizione dei gruppi. Poi apri Risultati in arrivo per quel gruppo. Abbina i nomi riconosciuti ai giocatori giusti, controlla il percorso e le posizioni d'arrivo e scegli Conferma per la gara controllata. Una tabella live provvisoria non è ancora un risultato ufficiale. Completa i passaggi finali del gruppo sul sito web. Prima di Controlla la conclusione, scegli Imposta numero di edizione in alto e inserisci il numero di questa edizione, per esempio 1. Controlla la tabella finale, poi scegli Controlla la conclusione → Concludi Torneo. Apri la pagina pubblica del torneo in una nuova finestra del browser per vedere il risultato pubblicato.

Modifica le impostazioni e gestisci il sito

L'assistente di configurazione chiede ogni valore logico una sola volta. Conserva il profilo in operator-profile.json e password e chiavi separatamente in secrets.json, all'interno della tua cartella dati privata. Ricava da solo le impostazioni Web, API, Docker e dei client pubblici. Non modificare separatamente api.env, compose.env, operator.json o public-client.json. Il file pubblico /client-config.json contiene solo l'indirizzo del sito web. Ripetere un avvio non crea nuovi account, un amministratore, chiavi o un database.

Su Windows, A1 usa per impostazione predefinita %LOCALAPPDATA%\MK8DX\Server e A2 usa %LOCALAPPDATA%\MK8DX\LAN. Sul VPS, B1 usa /var/lib/mk8dx/instance. Queste sono cartelle dati, non cartelle da sostituire durante un aggiornamento del software. Il login del provider e la chiave SSH del VPS restano fuori da MK8DX. Ogni dispositivo Android o Windows memorizza la propria scelta di community e la propria sessione.

Per avvio, stato, arresto, amministratore e backup su Windows, riapri lo Start-MK8DX.cmd o lo Start-MK8DX-LAN.cmd appropriato (aggiungi -SkipCountdown per togliere il conto alla rovescia, oppure imposta MK8DX_SOUND=0 per nessun segnale acustico; su Ubuntu --skip-countdown). Su Ubuntu, vai in /opt/mk8dx/host ed esegui sh tooling/start-mk8dx.sh /var/lib/mk8dx/instance. Il menu usa 2 per l'avvio, 3 per lo stato, 4 per l'arresto, 5 per il primo amministratore verificato, 6 per il backup e 7 per un aggiornamento con prima un backup verificato. L'opzione 1 può riprendere una prima configurazione interrotta. Non usare mai docker compose down -v su un'installazione che vuoi conservare: -v rimuove il volume del database. Per rimuovere completamente un'installazione di prova (questo elimina il suo database, gli account e le chiavi; scegli prima 6 per un backup se potresti volerli riavere): scegli 4 per fermarla, poi apri PowerShell nella cartella del pacchetto ed esegui docker compose --env-file "$env:LOCALAPPDATA\MK8DX\Server\compose.env" -f compose.yaml -f compose.local.yaml -f compose.images.yaml down -v ed elimina la cartella %LOCALAPPDATA%\MK8DX\Server (usa compose.lan.yaml per la via della rete domestica). Su Ubuntu esegui lo stesso comando con --env-file /var/lib/mk8dx/instance/compose.env (compose.production.yaml per un VPS) e poi elimina /var/lib/mk8dx/instance.

Per cambiare il servizio di posta o la password su A2 o B1, crea prima un backup con il menu 6. Su A2, apri PowerShell nella cartella host estratta ed esegui:

python tooling/install.py change-smtp --state-dir (Join-Path $env:LOCALAPPDATA 'MK8DX\LAN')
python tooling/install.py apply --state-dir (Join-Path $env:LOCALAPPDATA 'MK8DX\LAN')
python tooling/install.py check --state-dir (Join-Path $env:LOCALAPPDATA 'MK8DX\LAN')

Su Ubuntu, esegui le stesse azioni in /opt/mk8dx/host con python3 e --state-dir /var/lib/mk8dx/instance. Le richieste nominano smtp.host, smtp.port, smtp.username e smtp.fromAddress, e chiedono la password nascosta. Invio mantiene un valore esistente. Dopo controlla un nuovo messaggio di accesso nella tua vera casella di posta; check da solo non dimostra la consegna della posta. L'indirizzo di amministratore, l'indirizzo mittente e il login SMTP non devono per forza essere uguali.

Cambia l'indirizzo di un sito web pubblico solo dopo che il nuovo indirizzo DNS e HTTPS sono pronti. Crea prima un backup. Questo esempio A1 mostra l'azione di cambio esatta; sostituisci la porta di esempio con la porta libera che vuoi:

python tooling/install.py change-origin --state-dir (Join-Path $env:LOCALAPPDATA 'MK8DX\Server') --origin 'http://127.0.0.1:18090'
python tooling/install.py apply --state-dir (Join-Path $env:LOCALAPPDATA 'MK8DX\Server')
python tooling/install.py check --state-dir (Join-Path $env:LOCALAPPDATA 'MK8DX\Server')

Per B1, usa python3, /var/lib/mk8dx/instance e il tuo nuovo indirizzo https:// completo. Controlla lo stato, /client-config.json e un nuovo link di accesso. Punta anche ogni dispositivo al nuovo indirizzo. Puoi correggere un indirizzo di amministratore sbagliato nell'assistente di configurazione prima della prima assegnazione; questo non riapre una prima assegnazione già usata. Un amministratore esistente può aggiungere un altro amministratore verificato solo tramite la procedura di recupero limitata e una decisione esplicita del proprietario.

Sul sito web, Amministrazione → Impostazioni dell'installazione contiene le scelte valide per tutto il sito. Nome della community (per esempio “Club Noord”) viene mostrato nelle app al posto dell'indirizzo web; lascialo vuoto per nessun nome. Tempi di altre community decide se un tempo che un giocatore porta da un'altra community viene rifiutato (Disattivato, l'impostazione predefinita), attende finché un amministratore non fa clic su Pubblica accanto a esso in Amministrazione → Prova a tempo (Con approvazione), oppure segue le normali regole di pubblicazione (Consentito). Quando abbandoni Con approvazione mentre ci sono ancora tempi portati in attesa, la pagina chiede cosa farne. Ogni modifica viene registrata con il nome dell'amministratore.

Confermare le azioni pericolose: modificare i diritti di amministratore, di direttore o di resoconto, collegare direttamente un account a un giocatore, le impostazioni dell'installazione, ricalcolare i rating, rimuovere, riaprire o ripristinare una serata e aprire l'elenco di tutti gli account chiedono prima “Conferma con un nuovo link via e-mail”. Premi “Invia il link”; il link arriva al tuo indirizzo, funziona una sola volta per 10 minuti e conferma solo questo browser o questa app. Aprilo su qualsiasi dispositivo e premi “Conferma questa azione”; l'azione prosegue da sola. Un'email che non hai chiesto significa che qualcun altro ha una sessione del tuo account: non confermarla e usa “Disconnetti da tutti i dispositivi”. Se l'email non funziona, premi comunque “Invia il link” e, entro 10 minuti, esegui sul server python tooling/install.py step-up-link --state-dir <cartella di installazione> (python3 su Linux e sull'hosting condiviso); il comando mostra un nuovo link monouso per quella richiesta. A2 non invia email e non chiede questa conferma.

Backup, ripristino e aggiornamento

Backup automatico: MK8DX fa anche da sé ogni notte un backup verificato (A1, A3 e B1 lo attivano alla prima configurazione; B2 lo chiede una volta, Invio è sì; A2 ha il proprio in MK8DX beheer). Finisce in Documents\MK8DX-backups\automatic su Windows e in ~/mk8dx-backups/automatic su Linux e sull'hosting condiviso, conserva 14 giorni e 4 settimane, e una notte fallita non cancella mai i backup più vecchi. Il menu 3 (controlla) mostra sotto automaticBackup (A3: backup-status) età e risultato dell'ultimo. Tieni comunque una copia fuori dal computer o dal server: su Windows con python tooling/install.py backup-schedule --state-dir <cartella di installazione> --copy-to <cartella> (un altro disco o un NAS); da un server, python3 tooling/install.py backup-latest --state-dir <cartella di installazione> --print-path indica la cartella verificata più recente da prendere con scp. Si disattiva con backup-unschedule al posto di backup-schedule. Se il tuo hosting fa già backup giornalieri dell'account (DirectAdmin, JetBackup), può bastare; con un backup tuo torni comunque da solo a ieri, chiavi del sito comprese.

Account del database: il sito accede al proprio database con un account che può solo leggere e scrivere dati, così un errore del sito non può mai eliminare le tabelle; gli aggiornamenti del database e i backup usano un secondo account. A1, A2, A3 e B1 lo configurano da soli, un'installazione esistente al prossimo aggiornamento (menu 7); se il sito non si avvia con il nuovo account, l'aggiornamento torna a quello vecchio e non si perde nulla. Su B2, crea in DirectAdmin o cPanel un secondo utente del database con solo SELECT, INSERT, UPDATE e DELETE e inseriscilo nella procedura guidata, oppure più tardi con python3 tooling/install.py database-accounts --state-dir <cartella di installazione>; con un solo utente B2 continua a funzionare ma mostra un avviso.

Scegli il menu 6 sull'host appropriato. Su Windows, il backup va in Documents\MK8DX-backups\<timestamp>. Su Ubuntu, va in /root/mk8dx-backups/<timestamp> se lavori come root. Contiene il database, gli account, i diritti di amministratore, le impostazioni e le chiavi. Tieni privata l'intera cartella e copiala anche su un supporto protetto fuori dall'host. Una copia sullo stesso VPS guasto non basta.

Verifica la cartella effettivamente creata. Sostituisci <ACTUAL_FOLDER> qui sotto con il nome della cartella mostrato dall'assistente. Su Windows, in PowerShell dal pacchetto host:

python tooling/lifecycle.py verify --backup "$env:USERPROFILE\Documents\MK8DX-backups\<ACTUAL_FOLDER>"

Su Ubuntu, nella cartella del pacchetto host:

python3 tooling/lifecycle.py verify --backup '/root/mk8dx-backups/<ACTUAL_FOLDER>'

“Backup verified” (backup verificato) è la risposta attesa. Non condividere mai il backup in una issue, un'email o un link cloud pubblico.

Ripristinare un backup

Una prova di ripristino usa una nuova cartella dati e un nuovo progetto Docker. Lascia intatta l'installazione esistente. L'operazione di ripristino avvia all'inizio solo un nuovo database. Avvia poi il sito web recuperato secondo la tua via. Conserva il backup originale dopo la prova.

Per A1, apri PowerShell nel pacchetto host. Scegli una cartella di destinazione che non esiste ancora ed esegui:

python tooling/lifecycle.py restore-new --backup "$env:USERPROFILE\Documents\MK8DX-backups\<ACTUAL_FOLDER>" --state-dir (Join-Path $env:LOCALAPPDATA 'MK8DX\Herstelproef')
python tooling/install.py status --state-dir (Join-Path $env:LOCALAPPDATA 'MK8DX\Herstelproef')
python tooling/install.py start --state-dir (Join-Path $env:LOCALAPPDATA 'MK8DX\Herstelproef')
python tooling/install.py check --state-dir (Join-Path $env:LOCALAPPDATA 'MK8DX\Herstelproef')

Il sito A1 recuperato riceve le proprie porte locali libere. Apri la sua nuova Web origin indicata da status. Controlla un account noto, la vista di amministrazione e i tuoi risultati. Il sito originale può continuare a funzionare. Non assegnare un nuovo primo amministratore alla prova di ripristino.

Per una sostituzione pubblica B1, usa un nuovo VPS Ubuntu 24.04 con il pacchetto host verificato, Docker, Python e le porte 80/443 aperte. Per ora conserva il vecchio VPS. Organizza una breve finestra di manutenzione. Sul vecchio VPS, ferma prima solo Web e API in modo che non possano arrivare nuovi risultati dopo il backup finale. Nella cartella del vecchio pacchetto host, esegui:

docker compose --env-file /var/lib/mk8dx/instance/compose.env -f compose.yaml -f compose.production.yaml -f compose.images.yaml stop web api

Il sito web è ora temporaneamente non disponibile. Sul vecchio VPS, scegli il menu 6 per un nuovo backup mentre MySQL è ancora in esecuzione. Verifica questo esatto nuovo backup con il comando verify qui sopra. Se non riesce, riprendi il vecchio sito con il menu 2 e indaga. Trasferisci l'intera cartella di backup verificata tramite la connessione WinSCP verificata in una cartella privata sul nuovo VPS, mai in una cartella web. Mettila per esempio in /root/mk8dx-backups/. Sul nuovo server, in /opt/mk8dx/host, esegui con il vero nome della tua cartella di backup:

docker load --input images/docker-images-amd64.tar
python3 tooling/lifecycle.py restore-new --backup '/root/mk8dx-backups/<ACTUAL_FOLDER>' --state-dir /var/lib/mk8dx/herstelproef
python3 tooling/install.py status --state-dir /var/lib/mk8dx/herstelproef

Il nuovo database è ora pronto nel suo progetto. Controlla i dati ripristinati rispetto al tuo backup privato esistente e allo stato. Pianifica un breve passaggio. Nel pannello DNS, cambia solo il record A del nome host di MK8DX con il nuovo indirizzo IPv4 del VPS. Mantieni i record di posta. Attendi che Resolve-DnsName sul tuo PC mostri il nuovo IP. Poi avvia i servizi recuperati sul nuovo VPS:

python3 tooling/install.py start --state-dir /var/lib/mk8dx/herstelproef
python3 tooling/install.py check --state-dir /var/lib/mk8dx/herstelproef

Sul tuo PC, apri https://<your-real-host-name>/health/ready e il sito web. Controlla il certificato valido, la tua email di accesso nella tua vera casella di posta, un account noto, la vista di amministrazione e i risultati. La nuova installazione Docker richiede il proprio certificato pubblico; le porte 80/443 e la nuova destinazione DNS devono essere raggiungibili. Tieni il vecchio VPS fuori dal percorso dei visitatori e conservalo per indagini o per un ritorno. Se un controllo non riesce, lascia intatto il backup, indaga su DNS, porte, certificato e SMTP, e pianifica un ritorno deliberato del record A al vecchio IP. Non rimuovere un volume come soluzione rapida. Un vero passaggio con servizi esterni non è stato eseguito per questo candidato locale.

Per A2, ripristina su un altro host Windows sulla stessa rete attendibile. Prepara Docker, Python e il pacchetto host. Durante una breve finestra di manutenzione, ferma solo Web e API sul vecchio host. Il database resta in esecuzione per il backup finale. Apri PowerShell nella cartella del vecchio pacchetto:

$state = Join-Path $env:LOCALAPPDATA 'MK8DX\LAN'
$compose = @('--env-file', (Join-Path $state 'compose.env'), '-f', 'compose.yaml', '-f', 'compose.lan.yaml', '-f', 'compose.images.yaml')
docker compose @compose stop web api

Poi scegli il menu 6 sul vecchio host e verifica il nuovo backup. Se non riesce, riprendi la vecchia installazione con il menu 2. Trasferisci in modo privato la cartella di backup verificata sul nuovo host. Mettila in Documents\MK8DX-backups\ con lo stesso nome di cartella, oppure adatta il percorso del backup nel comando successivo. Lì, esegui restore-new in una cartella di recupero LAN che non esiste ancora. Prima dell'avvio, cambia l'indirizzo di binding memorizzato con il vero IPv4 del nuovo host:

docker load --input images/docker-images-amd64.tar
python tooling/lifecycle.py restore-new --backup "$env:USERPROFILE\Documents\MK8DX-backups\<ACTUAL_FOLDER>" --state-dir (Join-Path $env:LOCALAPPDATA 'MK8DX\LAN-Herstel')
python tooling/install.py change-lan-address --state-dir (Join-Path $env:LOCALAPPDATA 'MK8DX\LAN-Herstel') --lan-bind-address '192.168.0.51'
python tooling/install.py start --state-dir (Join-Path $env:LOCALAPPDATA 'MK8DX\LAN-Herstel')
python tooling/install.py check --state-dir (Join-Path $env:LOCALAPPDATA 'MK8DX\LAN-Herstel')

Sostituisci l'IP di esempio e consenti TCP 443 sul nuovo host solo per il profilo Privato. Sull'host e sul secondo PC, cambia la voce hosts per mk8dx.home.arpa con il nuovo IP. Questo nuovo progetto Docker ha una nuova autorità di certificazione locale. Ottieni il nuovo root.crt da questo progetto di recupero con i comandi per il certificato del capitolo sulla rete domestica, ma usa LAN-Herstel come $state. Confronta di nuovo lo SHA-256 e installa il nuovo certificato sul secondo PC. Rimuovi il vecchio certificato tramite certmgr.msc in Autorità di certificazione radice attendibili → Certificati, usando la vecchia impronta per identificarlo. Solo allora apri il sito senza avvisi e controlla l'accesso e i risultati esistenti. Un passaggio fisico di A2 non è ancora stato testato; conserva l'host originale e il backup.

Per un aggiornamento del software, controlla prima lo SHA-256 del nuovo pacchetto host. Estrailo accanto alla vecchia cartella del software. Usa la stessa cartella dati privata e scegli il menu 7 nel nuovo pacchetto. L'assistente crea e verifica prima un backup, esegue le migrazioni mancanti e sostituisce solo i programmi server forniti. Dopo controlla la stessa identità del progetto, il sito web, l'accesso e i dati. Se non riesce, conserva il backup e non eseguire alla cieca un'immagine più vecchia dopo una modifica dello schema del database.

L'aggiornamento alla 0.2.3 sposta il database Docker da MySQL 8.4 a MySQL 9.7 LTS. MySQL aggiorna i file di dati una volta, al primo avvio sulla nuova versione; solo il ripristino di un backup può annullarlo. Quindi nella cartella del nuovo pacchetto scegli prima 7 (aggiornamento): crea un backup verificato e applica gli aggiornamenti del database. Dalla 0.2.4, 2 (avvio) si rifiuta di partire finché l'aggiornamento non è stato eseguito; con un pacchetto 0.2.3, 2 salterebbe il backup. Il menu 3 (controllo) è innocuo. Nel pacchetto A2, Update (Aggiorna) nel browser crea prima da solo il backup; il primo aggiornamento richiede solo un po' più di tempo, e il backup si trova in Documents\MK8DX-backups. A3 e B2 usano il proprio MariaDB o MySQL e non sono interessati.

Risoluzione dei problemi e compilazione in proprio

Per un sito web vuoto, inizia con il menu 3 e controlla che Docker sia in esecuzione. Su A1, la posta di accesso va a Mailpit; su A2 e B1 dovrebbe andare a una vera casella di posta. Controlla sempre di usare la stessa installazione, lo stesso indirizzo e la stessa email. La mancanza di posta di accesso su una via pubblica richiede di controllare i veri valori SMTP e la raggiungibilità del provider. /health/ready riporta la prontezza dell'API e del database, non la consegna nella casella di posta.

Se Start-MK8DX.cmd si ferma su A1 con “all predefined address pools have been fully subnetted”, le vecchie reti Docker hanno esaurito i suoi intervalli di indirizzi. Esegui docker network ls in PowerShell per vederle. Rimuovi solo le reti che sai con certezza essere inutilizzate, per esempio con docker network prune, che rimuove solo le reti non usate da alcun container. Poi riapri Start-MK8DX.cmd.

Su A2, controlla prima la voce hosts su entrambi i PC, la rete privata, la porta del firewall e l'impronta del certificato. Su B1, controlla il record A del DNS, le porte 80/443 del provider, un HTTPS valido e poi la posta. Non ignorare un avviso sul certificato. Quando chiedi aiuto, non condividere mai secrets.json, un backup, link di accesso, chiavi SSH o righe di log che contengono password.

Per compilare il tuo codice, il tuo branding o un APK firmato definitivo, scarica il pacchetto mk8dx-full-local dalla stessa pagina delle release. Contiene il codice sorgente, la raccolta interna di risorse e le ricette di compilazione. Le istruzioni per sviluppatori sono in docs/DEVELOPMENT.md e docs/CLIENT_BUILDS.md. Da un clone del repository (git clone https://github.com/fromthelake/MK8DX-Ecosystem.git) o da quel pacchetto, docs/guides/HOSTING.md (“Build the host package from a clone”) compila il pacchetto host Docker e i pacchetti per hosting condiviso e XAMPP, e docs/CLIENT_BUILDS.md compila i pacchetti Android, LiveTrial e Tournament. La normale installazione e la scelta del server non richiedono Android Studio, modifiche al codice sorgente né un'immagine Docker compilata da te. Il materiale di gioco nei pacchetti mantiene le proprie condizioni; vedi docs/THIRD_PARTY_MATERIALS.md.

Usa Linux

Cosa puoi provare ora in locale

Ti serve solo il tuo computer Linux, senza un computer Windows. Se usa Ubuntu 24.04 su x86-64, il pacchetto host Docker incluso è la via per il server locale. Esegui prima uname -m e controlla che dica x86_64. Installa Docker Engine con il plugin Compose, Python dalla 3.12 alla 3.15 e unzip. L'installazione di Docker su Ubuntu è spiegata passo dopo passo in “Crea un sito web pubblico su un VPS”; per questa prova locale, salta il DNS, l'apertura delle porte del firewall verso internet e il vero SMTP. Scarica mk8dx-host-local-v0.2.10-amd64.zip e il suo SHA256SUMS.txt dalla stessa release. Apri il Terminale nella cartella di download e verifica lo ZIP. Confronta il risultato con la sua riga in SHA256SUMS.txt. Fermati se sono diversi:

sha256sum mk8dx-host-local-v0.2.10-amd64.zip

Estrai il pacchetto ed entra nella sua cartella:

mkdir -p "$HOME/MK8DX/host"
unzip -q mk8dx-host-local-v0.2.10-amd64.zip -d "$HOME/MK8DX/host"
cd "$HOME/MK8DX/host"

L'avviatore Linux esistente è:

sh tooling/start-mk8dx.sh "$HOME/mk8dx-data"

Digita A1; la prima configurazione parte da sola. L'avviatore mostra l'indirizzo completo del sito web come “Origine web” e Mailpit come “Posta in arrivo locale”. Entrambi gli indirizzi 127.0.0.1 funzionano su questo computer Linux. Apri il sito web nel browser e Mailpit in una seconda scheda per il link di accesso. Se il sito si avvia, puoi usare lì in locale il sito web e lo scanner nel browser. Controlla tu stesso che l'accesso, un invio e la sua visualizzazione sul sito web funzionino davvero. Quella catena locale completa non è stata eseguita su Linux per questa release; i container in esecuzione da soli non lo dimostrano.

Cosa richiede ancora sviluppo

I programmi LiveTrial e Tournament inclusi sono programmi per Windows. Non si avviano direttamente come applicazioni Linux. Nemmeno lo ZIP XAMPP e il suo assistente Apache per Windows sono un programma di installazione per Linux. Non esiste un client Linux nativo precompilato né un collaudo dell'acquisizione su Linux. Per usare l'intero ecosistema senza Windows, uno sviluppatore esperto di Linux deve portare e impacchettare i client desktop, le loro dipendenze OCR ed eventuali interfacce di acquisizione, poi testare l'accesso e la consegna attraverso il database fino al sito web. L'APK Android si installa su Android, non su Linux. Il pacchetto host A1/B1 è solo amd64; su Linux ARM (arm64) usa il pacchetto A2 mk8dx-a2-linux-arm64.

Usa macOS

Cosa puoi provare ora in locale

Ti serve solo il tuo Mac, senza un computer Windows o un altro server. Su un Mac Intel, uno sviluppatore può provare a eseguire in locale le immagini Docker Linux/amd64 incluse. Se il sito web, l'API e il database si avviano davvero, apri gli indirizzi A1 del sito web e di Mailpit mostrati nel browser sullo stesso Mac. Lo scanner fa parte del sito web. Nessuna prova su Mac ha ancora mostrato un nuovo account, un invio, un record nel database e un risultato visibile sul sito web. Una home page funzionante da sola non dimostra un'installazione completa.

Su un Mac Intel, installa Docker Desktop per Mac e Python dalla 3.12 alla 3.15. Scarica lo stesso ZIP host e SHA256SUMS.txt. Apri il Terminale nella cartella di download, esegui shasum -a 256 mk8dx-host-local-v0.2.10-amd64.zip e confronta il risultato con SHA256SUMS.txt. Fermati se sono diversi. Poi usa i comandi mkdir, unzip e cd del capitolo su Linux. Avvia lo stesso avviatore shell e scegli A1. Questa è una prova per sviluppatori, non una via accettata per gli utenti Mac. Su Apple Silicon, questo pacchetto host A1 richiede l'emulazione per le sue immagini amd64; non esiste un pacchetto A1 nativo arm64, e funzionamento e velocità in emulazione non sono stati dimostrati. Su un Mac con Apple Silicon, usa invece il pacchetto A2 mk8dx-a2-macos-arm64 (vedi “Usalo sulla tua rete domestica”).

Docker Desktop per Mac: https://docs.docker.com/desktop/setup/install/mac-install/

Cosa richiede ancora sviluppo

Lo ZIP XAMPP/Node e i client precompilati LiveTrial e Tournament sono pacchetti per Windows; non forniscono applicazioni per Mac. Uno sviluppatore esperto di macOS deve portare e compilare questi client, comprese le loro dipendenze OCR ed eventuali integrazioni con schede di acquisizione, poi testare l'intera catena di consegna. Una VM Windows o un livello di compatibilità non sono stati accettati come via client alternativa. L'APK Android resta per un dispositivo Android.
