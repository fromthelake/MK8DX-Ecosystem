Установка и использование MK8DX

Это машинный перевод английского руководства MK8DX_User_Guide_EN.txt; основной считается английская версия. Исправления приветствуются через форму issue «Translation correction».

Руководство для MK8DX 0.2.12 · 17 ноября 2026

Добро пожаловать

MK8DX — это сайт для гонок на время и турниров Mario Kart 8 Deluxe. Вы можете просматривать трассы и эталонные времена, входить по ссылке из письма и отправлять собственные результаты. Администратор может проверять отправленные результаты. Сканер, приложение для Android и программы для Windows — это отдельные инструменты.

Пакеты релиза прикреплены к GitHub Releases проекта. Откройте страницу релизов, https://github.com/fromthelake/MK8DX-Ecosystem/releases, и выберите самый новый релиз. В разделе Assets скачайте пакет для вашего способа установки и SHA256SUMS.txt. Кнопка GitHub «Source code (zip)» — это не установочный пакет. Если вы работаете с клоном исходного кода, пакеты можно собрать самостоятельно; см. «Устранение неполадок и самостоятельная сборка». Обозначение v0.2.12 в имени файла пакета указывает на этот релиз; образы Docker внутри серверного пакета имеют соответствующие версионные теги. Храните все файлы из одного и того же релиза.

Выберите один способ использования сайта. На одном компьютере с Windows используйте либо Docker, либо XAMPP, Node.js и входящую в комплект актуальную MariaDB. Описанный сетевой способ с Docker позволяет подключить второй компьютер с Windows в вашей доверенной сети. Для публичного домена выберите либо виртуальный хостинг с Node.js (в главе в качестве примера используется mijn.host Starter), либо собственный VPS с Docker. Эти главы — альтернативы, а не курс, который нужно пройти по порядку. Клиенты для телефона и Windows описаны после способов установки сайта.

A1 (Docker на одном компьютере) и A3 (XAMPP/Node.js в Windows) поддерживаются после проверок новой установки и обновления с сохранением данных. У A2 (домашняя или клубная сеть, новинка 0.2.0) есть собственный пакет с пошаговой настройкой в браузере, и он проверен от начала до конца в Windows 11. B1 (VPS с Docker) описан, но не проверен от начала до конца. B2 (виртуальный хостинг с Node.js): так работает сайт нашего собственного сообщества; публичный пакет ещё не устанавливался с нуля на новом аккаунте хостинга. Локальные установки A1 и A3 проверены в Windows 11 x86-64, включая аккаунты, результаты LiveTrial и Tournament Processor/Connect в базе данных и на сайте. Физический захват Tournament Live прошёл полную приёмочную проверку на скорости 1× с пакетом 0.2.2. Если у вас есть только Linux или macOS, без компьютера с Windows или другого сервера, выбор уже. Две главы в конце объясняют, что можно попробовать локально на том же компьютере и каких продуктов для вашей операционной системы пока нет.

Попробуйте на одном компьютере

Это пробная установка на одном компьютере с Windows 11 и процессором x86-64. В качестве рекомендуемого запаса предусмотрите 8 ГБ памяти и около 15 ГБ свободного рабочего места. Это не измеренные жёсткие минимумы. В Windows процессор и память можно найти в Settings → System → About (Параметры → Система → О системе). Свободное место — в File Explorer → This PC (Проводник → Этот компьютер). Домен или платный почтовый сервис не нужны.

1. Установите Docker Desktop с официальной страницы для Windows. Выберите WSL2 и Linux-контейнеры. Перезагрузите Windows, если установщик попросит. Откройте Docker Desktop и дождитесь «Engine running» (движок работает).

Docker Desktop для Windows: https://docs.docker.com/desktop/setup/install/windows-install/

Откройте PowerShell из меню «Пуск». Эта команда должна показать версию:

docker compose version

Если Docker не запускается, сначала выполните указания его сообщения о WSL или виртуализации. MK8DX не может запуститься, пока Docker Desktop закрыт.

2. Установите Python от 3.12 до 3.15 для Windows x86-64 с официальной страницы. В установщике отметьте «Add python.exe to PATH» (добавить python.exe в PATH) и выберите «Install Now» (установить сейчас). Закройте и снова откройте PowerShell. Проверьте версию:

Python для Windows: https://www.python.org/downloads/windows/

python --version

Если вы не видите версию от 3.12 до 3.15, восстановите Python тем же установщиком. Также проверьте, не открыла ли Windows псевдоним Microsoft Store вместо установленного Python. Python здесь только запускает помощник установки; собирать программы не нужно.

3. Поместите mk8dx-host-local-v0.2.12-amd64.zip и SHA256SUMS.txt в одну папку загрузок. Откройте PowerShell в этой папке и проверьте серверный пакет:

Get-FileHash '.\mk8dx-host-local-v0.2.12-amd64.zip' -Algorithm SHA256

Сравните значение целиком со строкой этого файла в SHA256SUMS.txt. Если они различаются, остановитесь и запросите правильную копию. Щёлкните ZIP правой кнопкой и выберите «Extract All» (Извлечь все). Подходящее место — Documents\MK8DX-A1. Откройте извлечённую папку, в которой есть Start-MK8DX.cmd и compose.yaml.

4. Дважды щёлкните Start-MK8DX.cmd. Окно открывается коротким гоночным вступлением: логотип MK8DX и обратный отсчёт 3-2-1-GO со звуковыми сигналами (Start-MK8DX.cmd -SkipCountdown пропускает отсчёт; все параметры перечислены в руководстве по хостингу). Затем оно спрашивает «Где будет работать MK8DX?» и перечисляет A1, A2 и B1. Введите A1 и нажмите Enter. Введите адрес электронной почты, с которым вы позже будете входить и станете администратором. Затем первая настройка начнётся сама. MK8DX загружает входящие в комплект программы и создаёт собственные ключи, базу данных и стандартные эталонные данные. Первый запуск может занять некоторое время.

Запишите адрес, показанный как «Веб-источник (origin)», и адрес, показанный как «Локальный почтовый ящик». Адрес сайта может выглядеть как http://127.0.0.1:18080, а тестовый ящик — как http://127.0.0.1:18025. Последние цифры у вас могут отличаться. Всегда используйте адреса, которые действительно показаны.

Потеряли адреса позже? Снова откройте Start-MK8DX.cmd и выберите 3 для статуса. «origin» — полный адрес сайта для браузера и LiveTrial. «localMailInbox» — адрес Mailpit. Открывайте этот второй адрес только в браузере, чтобы читать локальные письма для входа. Цифры после двоеточия — это порт. «127.0.0.1» означает этот компьютер, поэтому эти адреса A1 не работают на другом компьютере или телефоне.

Личные данные установки хранятся вне извлечённого пакета, в %LOCALAPPDATA%\MK8DX\Server. Сохраняйте эту папку и том базы данных Docker, когда получаете более новый пакет программы.

5. Откройте показанный адрес сайта в браузере на том же компьютере. Нажмите «Войти» (на английском «Sign in», на нидерландском «Aanmelden») и введите в точности адрес из шага 4. В другой вкладке браузера откройте «Локальный почтовый ящик». Это Mailpit, тестовый почтовый ящик на вашем компьютере. Откройте там последнее письмо для входа и перейдите по ссылке. Не ищите это пробное письмо в своём обычном почтовом ящике.

Вы вошли, но прав администратора у вас пока нет. Снова откройте Start-MK8DX.cmd и выберите 5. Первая выдача прав сообщает «created» (создано); повторная — «unchanged» (без изменений). Обновите сайт или войдите снова. Должен появиться раздел администрирования. Произвольный первый зарегистрировавшийся никогда не получает права администратора автоматически.

6. Откройте «Трассы», выберите трассу и посмотрите на «Сотрудники Nintendo» и «Мировые рекорды». Свой пробный заезд можно отправить через «Опубликуйте своё время» на странице трассы (затем «Опубликовать» и «Подтвердить и опубликовать»). Проверьте данные перед отправкой. Отправка — это не то же самое, что публичное одобрение.

В Mailpit находятся ссылки для входа. Не открывайте этот тестовый ящик другим людям. Для публичного сайта выберите способ с виртуальным хостингом или VPS с настоящей исходящей почтой.

На одном компьютере без Docker: XAMPP и Node.js

Это отдельная пробная установка на одном компьютере с Windows 11. Docker не нужен. XAMPP предоставляет Apache и окно управления, которое запускает ваш локальный сайт. Сам MK8DX работает на Node.js. Текущая загрузка XAMPP содержит MariaDB 10.4.32; этот способ установки её не использует. Пакет MK8DX включает отдельный, поддерживаемый экземпляр MariaDB 11.4.13, привязанный только к 127.0.0.1:18306. Существующие базы данных XAMPP и другие сайты не изменяются. Предусмотрите 8 ГБ оперативной памяти и несколько ГБ свободного места для пакета, базы данных, сканера и резервных копий.

1. Скачайте XAMPP для Windows с официального сайта и установите его в место, которое легко найти, например C:\xampp. В XAMPP Control Panel (панели управления XAMPP) используйте только Apache. Не запускайте для MK8DX MySQL, FileZilla, Mercury или Tomcat. Если вы уже используете XAMPP для других проектов, сохраните их базы данных и настройки.

XAMPP для Windows: https://www.apachefriends.org/download.html

2. Установите Node.js 24 для Windows с официального сайта Node.js. Установите Python 3.12 или новее с официальной страницы загрузки для Windows и выберите «Add python.exe to PATH» (добавить python.exe в PATH). Закройте и снова откройте PowerShell. Проверьте:

Node.js: https://nodejs.org/en/download
Python: https://www.python.org/downloads/windows/
node --version
python --version

Вы должны увидеть Node 24 и Python 3.12 или новее. Они запускают готовые файлы MK8DX; собирать приложение не нужно. Если команда неизвестна, снова откройте PowerShell, а при необходимости восстановите эту установку.

3. Поместите mk8dx-xampp-node-windows-v0.2.12.zip и SHA256SUMS.txt в одну папку загрузок. В PowerShell сравните значение SHA-256 целиком со строкой для этого ZIP:

Get-FileHash '.\mk8dx-xampp-node-windows-v0.2.12.zip' -Algorithm SHA256

Если они совпадают, щёлкните ZIP правой кнопкой и выберите «Extract All» (Извлечь все). Подходящая папка — Documents\MK8DX\nodocker-v0.2.12. Откройте извлечённую папку, в которой есть Start-MK8DX-No-Docker.cmd. В ней уже есть bin\mailpit.exe и bin\mariadb-11.4.13-winx64.zip. Вы не компилируете исходный код и не заменяете старую базу данных XAMPP. Не помещайте этот пакет в htdocs.

4. Подготовьте Apache только для этого локального сайта. Откройте PowerShell в извлечённой папке MK8DX. Укажите в -XamppRoot ваше фактическое расположение XAMPP:

powershell -ExecutionPolicy Bypass -File .\tooling\configure_xampp.ps1 -XamppRoot 'C:\xampp'

Помощник сначала сохраняет apache\conf\httpd.conf в %LOCALAPPDATA%\MK8DX\ApacheBackup. Он добавляет только «Include conf/extra/mk8dx-local.conf» и отдельный порт 18090, затем проверяет синтаксис Apache. Ожидайте «Apache syntax OK» (синтаксис Apache в порядке). Если порт 18090 уже занят или настройки отличаются, остановитесь и прочитайте ошибку; не удаляйте другой сайт XAMPP. Для другого расположения XAMPP, в том числе с пробелами, замените в этой команде только C:\xampp.

5. Дважды щёлкните Start-MK8DX-No-Docker.cmd. Выберите способ A3 и введите адрес электронной почты, который вы позже будете использовать как администратор. Окно создаёт одну частную установку в %LOCALAPPDATA%\MK8DX\NoDocker. При первом запуске оно распаковывает MariaDB 11.4.13 только в эту папку, создаёт отдельную базу данных и пользователя с ограниченными правами, применяет миграции, а также данные «Сотрудники Nintendo» и «Мировые рекорды», и запускает Node.js и Mailpit. Это может занять несколько минут. Оставьте это окно MK8DX открытым. Перезапуск сохраняет ключи, аккаунты, результаты и базу данных.

При каждом запуске это окно также показывает «Сайт:» и «Письма для входа - тестовый ящик:». «Сайт» — полный адрес для браузера и LiveTrial: http://127.0.0.1:18090. «Письма для входа - тестовый ящик» — локальный тестовый ящик: http://127.0.0.1:18227. Открывайте Mailpit только в браузере. Цифры после двоеточия — это порты. «127.0.0.1» означает этот компьютер, поэтому эти адреса не работают на другом устройстве. Если вы их забудете, посмотрите в верхней части того же окна MK8DX при следующем запуске.

6. Откройте XAMPP Control Panel. Если Apache уже зелёный, нажмите Stop (Остановить) только для Apache, подождите, пока его строка перестанет быть зелёной, затем снова нажмите Start (Запустить). Так загружается новая настройка сайта из шага 4. Если Apache был остановлен, сразу нажмите Start. Откройте http://127.0.0.1:18090 в браузере. Локальный тестовый ящик — http://127.0.0.1:18227. Если сайт недоступен, сначала посмотрите в окно MK8DX, затем убедитесь, что Apache зелёный. Во втором окне PowerShell, открытом в папке пакета, проверьте базу данных и API:

python tooling/install.py check-database --state-dir "$env:LOCALAPPDATA\MK8DX\NoDocker"
python tooling/install.py check --state-dir "$env:LOCALAPPDATA\MK8DX\NoDocker"

Ожидайте «MariaDB 11.4.13» и «ready» (готово). Сайт, сканер, база данных и тестовый ящик привязаны к этому компьютеру. Не пробрасывайте порт на роутере и не открывайте phpMyAdmin или тестовый ящик другим людям.

Apache не становится зелёным? Apache из XAMPP без изменений занимает ещё и порты 80 и 443, кроме 18090. Если установка A2, IIS или другой веб-сервер на этом компьютере уже использует один из них, Apache не запускается, а журнал в XAMPP Control Panel называет занятый порт. Остановите ту программу на запланированный период или используйте A3 на другом компьютере. Не удаляйте другой сайт.

7. На сайте нажмите «Войти» и используйте в точности адрес администратора из шага 5. Откройте самое новое письмо в Mailpit и перейдите по ссылке для входа. Пока вы всё ещё обычный пользователь. Теперь дважды щёлкните Manage-MK8DX-No-Docker.cmd в папке пакета (оставьте окно MK8DX открытым), введите 2 и нажмите Enter. За этим выполняется: python tooling/install.py admin --state-dir "$env:LOCALAPPDATA\MK8DX\NoDocker".

Это работает только для аккаунта, который уже подтвердил свой адрес почты. Ожидайте «created» (создано) или «unchanged» (без изменений) при повторе. Обновите сайт. Другой первый зарегистрировавшийся не становится администратором автоматически.

8. Откройте трассу и проверьте «Сотрудники Nintendo» и «Мировые рекорды», включая «Сумма». Отправьте одну пробную гонку на время и откройте /scanner/ на том же компьютере. Выберите изображение, чтобы попробовать путь загрузки. Результат сканера может требовать проверки; загрузка не делает его публичным автоматически.

9. Для ежедневного использования сначала запускайте окно MK8DX, затем запускайте Apache в XAMPP Control Panel. Держите окно MK8DX открытым, пока пользуетесь сайтом. После перезагрузки Windows выполните эти два запуска снова. Остановите Apache кнопкой Stop в панели, затем нажмите Ctrl+C в окне MK8DX. Останавливаются только процессы Node, Mailpit и MariaDB этой установки. Не завершайте все процессы node.exe и не изменяйте существующую службу XAMPP.

10. Для резервной копии оставьте окно MK8DX и его базу данных работающими. Можно ненадолго остановить Apache, чтобы во время окончательного копирования не поступали новые результаты с сайта. Дважды щёлкните Manage-MK8DX-No-Docker.cmd, введите 3 и нажмите Enter. Резервная копия записывается в Documents\MK8DX-backups\a3-<date and time> и сразу проверяется.

«Резервная копия проверена» подтверждает копию базы данных, профиль и ключи. Храните всю папку также в защищённом хранилище вне этого компьютера. Чтобы снова проверить именно эту резервную копию, выполните:

python tooling/install.py verify-backup --state-dir "$env:LOCALAPPDATA\MK8DX\NoDocker" --backup-output "$env:USERPROFILE\Documents\MK8DX-backups\a3-2026-10-01"

Ночная резервная копия: первый запуск также включает проверенную резервную копию каждую ночь в 03:15. Планировщик заданий Windows создаёт её под вашей учётной записью, без прав администратора, в Documents\MK8DX-backups\automatic; если в это время компьютер выключен, копия создаётся как можно скорее после этого. Если окно MK8DX закрыто, резервное копирование само запускает и останавливает свою базу данных. Проверьте это в PowerShell в папке пакета:

python tooling/install.py backup-status --state-dir "$env:LOCALAPPDATA\MK8DX\NoDocker"

Ожидайте "enabled": true и "scheduler": "windows-task"; после первой ночи также "lastResult": "ok". Если там "enabled": false, хотя вы её никогда не отключали (более старый пакет не мог её включить), выполните один раз ту же команду с backup-schedule вместо backup-status; следующее обновление по шагу 11 тоже её включит. Отключить её можно командой backup-unschedule.

11. Для обновления программы остановите Apache и создайте и проверьте резервную копию, пока старое окно MK8DX ещё работает. Затем нажмите Ctrl+C в этом окне. Проверьте и извлеките новый ZIP A3 рядом со старым пакетом. Продолжайте использовать ту же папку данных %LOCALAPPDATA%\MK8DX\NoDocker. В PowerShell внутри нового пакета временно запустите только его собственную базу данных:

python tooling/install.py maintenance --state-dir "$env:LOCALAPPDATA\MK8DX\NoDocker"

Оставьте это окно открытым. Откройте второе окно PowerShell в новом пакете и выполните обновление с другой, новой папкой резервной копии:

python tooling/install.py upgrade --state-dir "$env:LOCALAPPDATA\MK8DX\NoDocker" --backup-output "$env:USERPROFILE\Documents\MK8DX-backups\a3-update-2026-10-01"

Дождитесь «unchanged» для обоих эталонных наборов и «Резервная копия проверена». Нажмите Ctrl+C в окне обслуживания. Запустите Start-MK8DX-No-Docker.cmd из нового пакета и снова Apache. Помощник обновляет производные пути пакета, не сбрасывая аккаунты, ключи или данные. Проверьте тот же вход, эталонные данные и пробный результат. Не считайте смену движка базы данных обычным обновлением MK8DX.

12. Чтобы попробовать восстановление на другом компьютере с Windows, установите там XAMPP Apache, Node 24 и Python, как в шагах 1 и 2. Извлеките тот же пакет A3 и настройте Apache с помощью configure_xampp.ps1, как в шаге 4. Скопируйте всю проверенную папку резервной копии частным образом в Documents\MK8DX-backups. Не используйте существующую папку данных на этом компьютере. Откройте PowerShell в новом пакете и создайте только новый профиль:

python tooling/install.py wizard --state-dir "$env:LOCALAPPDATA\MK8DX\NoDocker"

Выберите A3 и пока введите собственный адрес администратора; восстановление вернёт исходный профиль аккаунтов. Откройте второе окно PowerShell в том же пакете. В первом окне запустите только новую, пустую MariaDB:

python tooling/install.py maintenance --state-dir "$env:LOCALAPPDATA\MK8DX\NoDocker"

Держите это окно открытым. Во втором окне используйте фактическое имя папки резервной копии, без угловых скобок:

python tooling/install.py restore-local --backup-input "$env:USERPROFILE\Documents\MK8DX-backups\a3-2026-10-01" --state-dir "$env:LOCALAPPDATA\MK8DX\NoDocker"

Ожидайте «Резервная копия проверена», а затем успешную проверку всех миграций. Нажмите Ctrl+C в окне обслуживания. Откройте Start-MK8DX-No-Docker.cmd и запустите Apache в XAMPP Control Panel. Войдите с существующим аккаунтом из резервной копии и проверьте доступ администратора и известный результат. Права первого администратора повторно не выдаются. Если на целевом компьютере уже есть установка MK8DX или другой процесс на порту 18306, не используйте его как цель этого восстановления; помощник не стирает существующую базу данных. Сохраняйте исходную резервную копию нетронутой.

13. Чтобы удалить эту установку A3 с компьютера, сначала сделайте резервную копию как в шаге 10, если вам, возможно, позже понадобятся учётные записи и результаты. Копии в Documents\MK8DX-backups остаются, пока вы сами их не удалите. В PowerShell в папке пакета отключите ночную резервную копию:

python tooling/install.py backup-unschedule --state-dir "$env:LOCALAPPDATA\MK8DX\NoDocker"

Остановите Apache в XAMPP Control Panel и нажмите Ctrl+C в окне MK8DX. Затем уберите сайт MK8DX из Apache:

powershell -ExecutionPolicy Bypass -File .\tooling\configure_xampp.ps1 -XamppRoot 'C:\xampp' -Remove

Ожидайте «MK8DX Apache site removed» и «Syntax OK». Удаляются только строка Include и mk8dx-local.conf из шага 4; другие сайты и базы данных XAMPP остаются как есть. Затем удалите папки %LOCALAPPDATA%\MK8DX\NoDocker (база данных, учётные записи и ключи) и %LOCALAPPDATA%\MK8DX\ApacheBackup, а в конце папку пакета. XAMPP, Node.js и Python остаются установленными; удаляйте их в Параметры Windows → Приложения, только если они больше ничем не используются. Если вы используете XAMPP для других сайтов, снова запустите Apache.

Использование в домашней сети

Для домашней или клубной сети используйте пакет A2. Скачайте mk8dx-a2-windows-amd64-v0.2.12.zip (Linux: mk8dx-a2-linux-amd64 или mk8dx-a2-linux-arm64; macOS с Apple silicon: mk8dx-a2-macos-arm64; macOS с процессором Intel: mk8dx-a2-macos-amd64) и SHA256SUMS.txt, проверьте контрольную сумму, как в «Попробуйте на одном компьютере», распакуйте пакет и дважды щёлкните Start-MK8DX-LAN.cmd (Linux и macOS: sh tooling/start-mk8dx.sh). В браузере откроется программа установки, которая проведёт вас через всё кнопкой Next (Далее): сетевой адрес, ваш аккаунт администратора, бумажный код восстановления для ночных резервных копий и люди, каждый со своей карточкой входа для телефона или компьютера. Интернет, почтовый сервер и файл hosts не нужны.

Полное пошаговое руководство с иллюстрациями — docs/install/A2_HOME_GUIDE_EN.md; внутри пакета это также docs/install/guide/en.html, и программа установки открывает его по ссылке Manual (Руководство). В нём описаны подготовка Windows, Linux или macOS, телефонов и компьютеров, приложение для Android, LiveTrial, турнирные вечера, резервные копии, переезд на новый компьютер, фиксированный адрес, новый сетевой адрес, обновления и удаление MK8DX с компьютера.

Исторический расширенный вариант: с собственным почтовым сервером

Инструкции для текущего автономного пакета A2 заканчиваются выше. Продолжайте по ссылке в иллюстрированном руководстве A2. Остальная часть этой главы описывает более старый, продвинутый вариант с частным именем хоста и ссылками для входа по электронной почте через ваш собственный почтовый сервер. Большинству людей он не нужен. В нём используется пакет mk8dx-host-local и вариант A2 в его вопросе при настройке. Не сочетайте следующие шаги для файла hosts, SMTP, сертификата или установщика с текущим пакетом mk8dx-a2 и данными его установки.

Этот способ создаёт вторую, отдельную установку MK8DX на хосте с Windows. Ваша пробная установка на одном компьютере остаётся нетронутой. Описанный первый клиентский путь — второй компьютер с Windows с Chrome или Edge, включая загрузку изображения в сканер. Физический второй компьютер или телефон ещё не проходил настоящую пользовательскую приёмочную проверку. Обычное приложение для Android не доверяет локальному сертификату автоматически; для него используйте публичный HTTPS-адрес сообщества на виртуальном хостинге или VPS.

Сетевой сайт использует порт 443 на своём хосте. Если на том же компьютере работает XAMPP Apache, этот порт может быть уже занят. Тогда A2 и этот сайт Apache не могут работать на этом хосте одновременно. Используйте для A2 другой хост с Windows или останавливайте Apache на запланированный период в XAMPP Control Panel. Пока он остановлен, другие сайты XAMPP недоступны.

Сначала подготовьте на хосте Docker Desktop, Python и проверенный и извлечённый серверный пакет, как в первых трёх шагах «Попробуйте на одном компьютере». Создавать установку A1 не нужно. Оба компьютера должны быть в одной доверенной частной сети. Не используйте гостевой Wi-Fi и не пробрасывайте порт роутера в интернет. Не давайте хосту засыпать.

1. На хосте найдите его IPv4-адрес в Settings → Network & internet → Ethernet или Wi-Fi → Properties (Параметры → Сеть и Интернет → Ethernet или Wi-Fi → Свойства). В этом руководстве 192.168.0.50 — лишь пример. Запишите свой фактический адрес. Установите для сетевого профиля Windows значение Private (Частная), только если это действительно ваша доверенная сеть. Если адрес позже изменится, обновите оба компьютера; резервирование DHCP в роутере может предотвратить изменения.

2. Используйте одно и то же частное имя на обоих компьютерах с Windows. Запустите Блокнот через «Run as administrator» (Запуск от имени администратора). Выберите File → Open (Файл → Открыть), перейдите в эту папку и смените фильтр на «All Files» (Все файлы):

C:\Windows\System32\drivers\etc\

Откройте hosts. Добавьте одну строку с реальным IP хоста и частным именем, например:

192.168.0.50 mk8dx.home.arpa

Сохраните как hosts, без .txt. Сделайте то же самое на хосте и на втором компьютере. Проверьте на обоих в PowerShell:

ping -n 1 mk8dx.home.arpa

Перед результатами ping должен появиться IP вашего хоста. Брандмауэр может блокировать сам ping. Каждому устройству нужна своя запись в hosts, потому что у этого частного имени нет публичной записи DNS.

3. Для ссылок входа других пользователей нужен настоящий почтовый сервис. Получите у своего почтового провайдера имя сервера исходящей почты SMTP, порт 465 с неявным TLS, логин, пароль и разрешённый адрес отправителя. Сервис, предлагающий только STARTTLS на порту 587, не подходит для текущего мастера настройки. Адрес вашего будущего администратора MK8DX — отдельное значение. Не используйте Mailpit как общий ящик для входа.

4. На хосте дважды щёлкните Start-MK8DX-LAN.cmd. Выберите A2 и подтвердите mk8dx.home.arpa или введите в точности имя из ваших файлов hosts. Отдельно введите реальный IPv4-адрес хоста. Затем мастер настройки спросит почтовые значения и адрес вашего будущего администратора. Почтовый пароль при вводе скрыт. Первая настройка начнётся сама. Отдельная папка данных — %LOCALAPPDATA%\MK8DX\LAN. Показанный адрес сайта должен быть https://mk8dx.home.arpa.

Используйте этот HTTPS-адрес в LiveTrial и на хосте, и на втором компьютере. Стандартный порт 443 после имени писать не нужно. IPv4-адрес, который вы нашли, используйте для записи hosts и сетевых настроек, а не как адрес сообщества в LiveTrial. Этот сетевой способ использует вашего настоящего почтового провайдера: письма для входа приходят в обычный ящик указанного адреса. Локального адреса Mailpit у пользователей здесь нет.

5. На хосте откройте Windows Security → Firewall & network protection → Advanced settings → Inbound Rules → New Rule (Безопасность Windows → Брандмауэр и защита сети → Дополнительные параметры → Правила для входящих подключений → Создать правило). Выберите Port (Для порта), TCP, определённый локальный порт 443, «Allow the connection» (разрешить подключение) и только профиль Private (частный). Назовите правило, например «MK8DX LAN HTTPS». В разделе Scope (Область) ограничьте удалённые адреса своей сетью, если вы знаете её подсеть. Не открывайте базу данных или Mailpit для общественной сети.

6. Второй компьютер с Windows должен доверять локальному сертификату именно этой установки. Делайте это только на компьютере, которым управляете вы. Откройте PowerShell на хосте в извлечённой папке пакета и выполните эти три строки по одной:

$state = Join-Path $env:LOCALAPPDATA 'MK8DX\LAN'
$compose = @('--env-file', (Join-Path $state 'compose.env'), '-f', 'compose.yaml', '-f', 'compose.lan.yaml', '-f', 'compose.images.yaml')
docker compose @compose cp web:/data/caddy/pki/authorities/local/root.crt (Join-Path $env:USERPROFILE 'Downloads\mk8dx-lan-root.crt')

Проверьте отпечаток сертификата на хосте:

Get-FileHash (Join-Path $env:USERPROFILE 'Downloads\mk8dx-lan-root.crt') -Algorithm SHA256

Передайте на второй компьютер только mk8dx-lan-root.crt доверенным способом. Запишите отпечаток отдельно. Никогда не копируйте root.key, всю папку Caddy или секреты MK8DX. На втором компьютере проверьте файл в его папке загрузок:

Get-FileHash '.\mk8dx-lan-root.crt' -Algorithm SHA256

Когда значения в точности совпадают, дважды щёлкните сертификат. Выберите Install Certificate → Current User → Place all certificates in the following store → Browse → Trusted Root Certification Authorities → Finish (Установить сертификат → Текущий пользователь → Поместить все сертификаты в следующее хранилище → Обзор → Доверенные корневые центры сертификации → Готово). Перезапустите браузер. Не устанавливайте сертификат, отпечаток которого отличается. Не обходите предупреждение браузера.

7. На втором компьютере откройте https://mk8dx.home.arpa. Предупреждения о сертификате быть не должно. Также попробуйте https://mk8dx.home.arpa/scanner/ со своим тестовым изображением. Войдите со своим адресом и перейдите по ссылке в своём настоящем почтовом ящике. После этого входа можно снова открыть Start-MK8DX-LAN.cmd на хосте и выбрать пункт меню 5, чтобы один раз выдать права администратора сохранённому адресу. Пользователи и администраторы A1 не переносятся в A2 автоматически.

Если IP хоста позже изменится, сначала обновите hosts на обоих компьютерах. На хосте откройте PowerShell в папке пакета и замените пример IP ниже новым реальным адресом:

python tooling/install.py change-lan-address --state-dir (Join-Path $env:LOCALAPPDATA 'MK8DX\LAN') --lan-bind-address '192.168.0.51'
python tooling/install.py apply --state-dir (Join-Path $env:LOCALAPPDATA 'MK8DX\LAN')

Снова проверьте адрес, сайт и почту для входа. Второй компьютер продолжает доверять сертификату, пока это та же установка A2. Восстановление в новый проект создаёт новый локальный центр сертификации; см. «Восстановление резервной копии».

Публичный виртуальный хостинг с Node.js, без Docker

Этот способ использует Node.js с Passenger и MariaDB, как это предлагает виртуальный хостинг, например mijn.host Starter. Ему не нужны VPS, Docker, доступ root или собственный сервер Caddy. Пакет проверен на локальной установке Linux и MariaDB. Шаги в собственном аккаунте DirectAdmin и фактическую доставку почты вам всё равно нужно проверить самим. Используйте отдельный (под)домен и пустую базу данных. Не изменяйте существующий сайт или базу данных. Starter сейчас предлагает 2 ГБ оперативной памяти и 5 ГБ хранилища; проверьте в своей панели, хватит ли места для загрузки, зависимостей npm, данных и резервных копий.

1. Скачайте mk8dx-mijnhost-node-v0.2.12.zip и SHA256SUMS.txt со страницы релиза, указанной в разделе «Добро пожаловать». Этот ZIP — пакет для загрузки. ZIP для Docker-хоста и полный ZIP с исходным кодом — другие файлы. Поместите оба файла в одну папку на вашем компьютере с Windows. Откройте там PowerShell и сравните полное значение SHA-256 со строкой в SHA256SUMS.txt:

Get-FileHash '.\mk8dx-mijnhost-node-v0.2.12.zip' -Algorithm SHA256

Остановитесь, если значения различаются.

2. На своём компьютере войдите в клиентскую панель mijn.host. Откройте свой тариф хостинга, затем DirectAdmin. Выберите в правом верхнем углу домен или поддомен для этого нового сайта MK8DX. www.mijneigenwebsite.nl — только пример; используйте своё настоящее имя хоста. В разделе Account Manager → SSL Certificates проверьте, что «Get automatic certificate from ACME Provider» (получить автоматический сертификат от провайдера ACME) включает в точности это имя. Позже ваш браузер не должен показывать предупреждение о сертификате. Если DNS вы ведёте в другом месте, сначала направьте это имя хоста на этот тариф хостинга. Не меняйте существующие почтовые записи ради сайта.

Руководство DirectAdmin по Node.js: https://mijn.host/kb/web-apps/node-js-applicatie-draaien-op-je-hostingpakket
Let's Encrypt в DirectAdmin: https://mijn.host/kb/webhosting/lets-encrypt-ssl-certificaat-aanvragen

3. В DirectAdmin в разделе Account Manager → MySQL Management или Databases создайте новую пустую базу данных и пользователя, ограниченного этой базой. Запишите полные имена, которые показывает панель, включая возможный префикс аккаунта, например account_mk8dx и account_mk8dxuser. Держите сгенерированный пароль в секрете. Не используйте аккаунт root. Найдите хост базы данных в своей панели или в данных аккаунта. Это может быть localhost, но вводите только фактическое показанное значение. Порт 3306 — обычный пример. MK8DX проверяет фактический движок и версию перед миграцией. Этому релизу нужна MariaDB 11.4 или новее либо MySQL 8.4 или новее; надпись «MySQL» в панели не доказывает версию.

4. Откройте DirectAdmin → E-mail Manager → E-mail Accounts. Создайте или выберите почтовый ящик, который можно использовать для этого сайта. Запишите его полный адрес, пароль и имя сервера исходящей почты. Распространённый вариант — mail.mijneigenwebsite.nl на порту 465 с SSL/TLS; фактическое имя сервера узнайте в своём аккаунте. Логин SMTP, видимый отправитель и адрес будущего администратора MK8DX служат разным целям. Входящего в тариф почтового ящика достаточно, если ваш аккаунт позволяет с него отправлять.

Настройки почты в mijn.host: https://mijn.host/kb/email/e-mail-account-instellen-in-gmail

5. В DirectAdmin откройте Extra Features → Setup Node.js App → Create Application. Выберите Node.js 24, если панель его предлагает. Выберите Production для итогового сайта, Application root apps/mk8dx вне public_html, Application URL в корне выбранного домена и Application startup file api/dist/composition/passenger-hosted-main.js. Панель может сначала показать стандартный app.js; смените настройку запуска на указанный файл, прежде чем перезапускать MK8DX. Скопируйте точную строку активации окружения Node, показанную вверху вашей панели. Если Node 24 или настройка запуска недоступны, не угадывайте со старой версией Node; это отдельная проверка вашего аккаунта.

6. Найдите имя своего сервера и имя пользователя SSH в панели mijn.host. На компьютере с Windows откройте PowerShell и подключитесь по описанному порту SSH 26. Перед тем как принять отпечаток ключа хоста SSH, сравните его со значением, независимо предоставленным mijn.host. B2 работает на любом виртуальном хостинге с Node.js, который даёт доступ по SSH; mijn.host — проверенный пример, а порт 26 — это порт SSH этого провайдера, поэтому в других местах используйте порт своего хоста (часто 22). Пакет сохраняет название mk8dx-mijnhost-node. Замените примеры в угловых скобках своими значениями, без скобок:

ssh -p 26 <your-username>@<your-server-name>

Вы должны попасть в командную строку Linux. Храните пароль аккаунта в менеджере паролей. Это не доступ root к VPS. Тот же путь SSH передаёт проверенный ZIP. Откройте второе окно PowerShell на компьютере в папке загрузок:

scp -P 26 '.\mk8dx-mijnhost-node-v0.2.12.zip' <your-username>@<your-server-name>:

ZIP появится в вашем домашнем каталоге хостинга. Отдельный вариант SFTP может иметь другие настройки; этот способ использует только описанный доступ SSH/SCP.

SSH в mijn.host: https://mijn.host/kb/webhosting/verbinden-met-ssh

7. Вернитесь в окно SSH. Проверьте наличие Python 3.9 или новее, unzip и клиента дампа MariaDB. Приложение уже собрано; Python только запускает существующий помощник установки:

python3 --version
command -v unzip
command -v mariadb-dump || command -v mysqldump

Если команды нет, сверьте именно этот отсутствующий инструмент с панелью хостинга или справкой mijn.host. Не создавайте незащищённый публичный адрес настройки. Распакуйте ZIP в свою частную папку приложения, не в public_html:

mkdir -p "$HOME/apps/mk8dx"
unzip "$HOME/mk8dx-mijnhost-node-v0.2.12.zip" -d "$HOME/apps/mk8dx"
cd "$HOME/apps/mk8dx"

Вы должны увидеть api, web, scanner, assets, mysql и tooling. Папка приложения частная. Установщик также хранит профиль, секреты и резервные копии вне public_html.

8. В этом окне SSH вставьте точную строку активации Node, показанную в панели Setup Node.js App. Обычно она начинается с source и заканчивается cd в ваш Application root. Затем выполните:

node --version
cd "$HOME/apps/mk8dx/api"
npm ci --omit=dev --ignore-scripts --no-audit --no-fund
cd "$HOME/apps/mk8dx"

Ожидайте Node 24 и завершённую установку зафиксированных производственных зависимостей. Это не компилирует TypeScript. api/node_modules принадлежит вашему Linux-хосту; не загружайте node_modules из Windows. Если место закончилось, остановитесь и проверьте свободное место, вместо того чтобы удалять другие данные аккаунта.

9. Запустите пошаговый ввод из папки приложения:

python3 tooling/install.py wizard --state-dir "$HOME/mk8dx-private"

Выберите B2. Введите точное имя хоста вашего HTTPS-сайта без https://, затем хост базы данных, порт, полные имена базы данных и пользователя и скрытый пароль базы данных из шага 3. Введите хост SMTP, порт 465, полный логин почтового ящика, скрытый пароль ящика и разрешённого отправителя из шага 4. В качестве адреса администратора введите личный адрес электронной почты, на который вы получите ссылку для входа. Он может отличаться от логина SMTP. Помощник записывает operator-profile.json, secrets.json и operator.json в $HOME/mk8dx-private с ограниченными правами доступа. Не повторяйте те же значения в другом файле .env.

10. Проверьте версию базы данных, затем примените все миграции и оба эталонных набора только к вашей новой пустой базе данных:

python3 tooling/install.py check-database --state-dir "$HOME/mk8dx-private"
python3 tooling/install.py setup --state-dir "$HOME/mk8dx-private"
python3 tooling/install.py check --state-dir "$HOME/mk8dx-private"

Первая строка должна показать измеренную версию MariaDB или MySQL и tableCount 0. Остановитесь, если движок слишком старый или в базе данных есть неожиданные таблицы. После setup ожидайте, что все миграции применены, «Сотрудники Nintendo» и «Мировые рекорды» отмечены как applied (применено), а затем ready (готово). Установщик никогда не сбрасывает неизвестную заполненную схему.

11. Сгенерируйте настройки Passenger и запустите через панель:

python3 tooling/install.py passenger-config --state-dir "$HOME/mk8dx-private"

Это создаёт mk8dx-hosted.env.json в частном Application root, вне public_html. Никогда не перемещайте эту папку или $HOME/mk8dx-private в публичный каталог файлов. В DirectAdmin → Extra Features → Setup Node.js App выберите своё приложение MK8DX и нажмите Restart. Провайдер управляет его процессом и HTTPS; не запускайте дополнительный сервер через nohup или PM2. Со своим настоящим именем хоста проверьте /health/ready, главную страницу, /scanner/, /client-config.json и /.well-known/assetlinks.json. Неизвестный адрес JSON или API не должен возвращать HTML главной страницы. Запросы к /secrets.json, /.env или резервной копии не должны раскрывать никакого содержимого.

12. На сайте нажмите «Войти» с адресом администратора из шага 9. Откройте ссылку в своём настоящем почтовом ящике и войдите. Только после этого вернитесь в SSH, при необходимости снова активируйте окружение Node из панели, перейдите в папку приложения и выполните:

cd "$HOME/apps/mk8dx"
python3 tooling/install.py admin --state-dir "$HOME/mk8dx-private"

Ожидайте created (создано) или unchanged (без изменений) при повторе. Обновите сайт. Сама по себе первая регистрация никогда не даёт прав администрирования. Проверьте трассу, «Сотрудники Nintendo» и «Мировые рекорды» с «Сумма», свою гонку на время и загрузку в сканер. Если настоящая почта для входа не приходит, проверьте логин почтового ящика, отправителя и TLS; ready не доказывает доставку во внешний почтовый ящик.

13. Для резервной копии ненадолго остановите посетительский трафик кнопкой Stop этого приложения Node в DirectAdmin. База данных MariaDB остаётся доступной. В SSH из папки приложения выберите новое имя частной папки:

python3 tooling/install.py backup --state-dir "$HOME/mk8dx-private" --backup-output "$HOME/mk8dx-backups/b2-2026-10-01"

Помощник сообщает Резервная копия проверена. Храните защищённую копию также вне этого аккаунта хостинга. Перезапустите приложение Node в DirectAdmin и проверьте ready. Резервная копия включает аккаунты, права администраторов и ключи; никогда не загружайте её в public_html или по публичной ссылке.

14. Для обновления проверьте новый ZIP B2 на своём компьютере. Остановите приложение Node в DirectAdmin и создайте проверенную резервную копию со старым приложением. Загрузите новый ZIP тем же путём SSH/SCP. В SSH переименуйте старую папку приложения, затем создайте новую пустую. Используйте эти команды, только когда новый ZIP находится в вашей домашней папке и папки mk8dx-before-update ещё нет:

cd "$HOME"
mv "$HOME/apps/mk8dx" "$HOME/apps/mk8dx-before-update"
mkdir -p "$HOME/apps/mk8dx"
unzip "$HOME/mk8dx-mijnhost-node-v0.2.12.zip" -d "$HOME/apps/mk8dx"

Снова вставьте строку активации Node 24 из DirectAdmin. Установите зафиксированные зависимости Linux в новой папке api и вернитесь в корень приложения:

cd "$HOME/apps/mk8dx/api"
npm ci --omit=dev --ignore-scripts --no-audit --no-fund
cd "$HOME/apps/mk8dx"

Оставьте ту же частную папку данных. Используйте другую, новую папку резервной копии:

python3 tooling/install.py upgrade --state-dir "$HOME/mk8dx-private" --backup-output "$HOME/mk8dx-backups/b2-update-2026-10-01"
python3 tooling/install.py passenger-config --state-dir "$HOME/mk8dx-private"

Затем перезапустите в DirectAdmin только это приложение. Проверьте сайт, вход, администрирование и известные результаты. Не откатывайте вслепую только старые веб-файлы после миграции схемы. Смена версии MariaDB — это не обычное обновление MK8DX.

15. Для восстановления используйте новую пустую базу данных и отдельный тестовый поддомен на том же проверенном движке базы данных и той же серии версий. Поместите проверенный пакет B2 и полную частную резервную копию в эту отдельную установку. В DirectAdmin создайте отдельное приложение Node для пробного восстановления с Application root apps/mk8dx-restore и Application URL на тестовом поддомене. Распакуйте ZIP B2 в эту новую частную папку. Активируйте Node 24 строкой с экрана этого нового приложения, выполните npm ci --omit=dev --ignore-scripts --no-audit --no-fund внутри apps/mk8dx-restore/api, затем перейдите в apps/mk8dx-restore. Пошаговое восстановление запрашивает данные новой базы данных, не показывая пароль, и повторно использует старые аккаунты и ключи:

python3 tooling/install.py restore-wizard --backup-input "$HOME/mk8dx-backups/b2-2026-10-01" --state-dir "$HOME/mk8dx-private-restore"
python3 tooling/install.py passenger-config --state-dir "$HOME/mk8dx-private-restore"

В DirectAdmin подключите это отдельное приложение Passenger к тестовому поддомену и частному Application root. Запустите его и проверьте ready, существующий вход, администрирование и результаты. Не создавайте ещё одного первого администратора. Настоящее переключение домена и резервная копия у провайдера — отдельные шаги, которые вы выполняете сами.

Публичный сайт на VPS

VPS — это ваш собственный компьютер в интернете. Этот способ использует Ubuntu 24.04 LTS на x86-64. Рекомендуемая мощность — 2 ядра процессора, 8 ГБ оперативной памяти и 40 ГБ SSD, плюс место для будущих данных и резервных копий. Неуправляемый VPS M от Mijn.host указывает на своей странице VPS такую мощность и root/SSH, но MK8DX на этом конкретном тарифе не проверялся. Вы по-прежнему отвечаете за Ubuntu, Docker, почту, обновления безопасности и резервные копии.

Обзор VPS Mijn.host: https://mijn.host/vps

Mijn.host Starter использует отдельный способ с Node/Passenger, описанный выше. Эта глава про VPS использует Docker и не относится к обычному тарифу Starter.

Обзор виртуального хостинга Mijn.host: https://mijn.host/webhosting

Перед первой настройкой вам нужны собственный домен, подходящий аккаунт VPS с IPv4 и Ubuntu, доступ к управлению DNS и почтовый сервис с SMTP 465 и неявным TLS. Замените пример www.mijneigenwebsite.nl везде своим именем хоста. Пример IP 203.0.113.10 — не настоящий сервер. Ваш логин у провайдера, ключ SSH, адрес администратора MK8DX и логин SMTP служат разным целям. Держите пароли и ключи в секрете.

1. На компьютере с Windows создайте ключ доступа, если ваш VPS использует ключи SSH. Откройте PowerShell и выполните:

New-Item -ItemType Directory -Force (Join-Path $env:USERPROFILE '.ssh')
ssh-keygen -t ed25519 -f (Join-Path $env:USERPROFILE '.ssh\mk8dx_vps_ed25519')

Когда спросят, выберите надёжную парольную фразу. Файл без .pub — частный. Откройте файл .pub в Блокноте и добавьте только этот открытый ключ через функцию ключей SSH на портале управления VPS. Точная кнопка зависит от провайдера; если не можете её найти, спросите у провайдера, где она. Никогда не помещайте частный ключ в веб-папку или на сервер.

2. Установите WinSCP с его официального сайта. Откройте WinSCP → New Site (Новый сайт). Выберите SFTP. Введите реальный IP VPS в поле Host name (Имя хоста), фактический порт SSH в поле Port number (Номер порта) и аккаунт VPS в поле User name (Имя пользователя). Используйте root для описанного пути root, только если ваш провайдер его предоставляет. Для входа по ключу откройте Advanced → SSH → Authentication → Private key file (Дополнительно → SSH → Аутентификация → Файл закрытого ключа) и выберите частный ключ из шага 1. WinSCP предложит преобразовать ключ OpenSSH в файл .ppk; сохраните его рядом с частным ключом и используйте в WinSCP. Парольная фраза по-прежнему нужна.

WinSCP: https://winscp.net/eng/download.php
Форматы ключей WinSCP: https://winscp.net/eng/docs/ui_login_authentication

Получите отпечаток ключа хоста SSH через независимую консоль VPS вашего провайдера или поддержку. Сравните его с сообщением при первом подключении в WinSCP. Принимайте только точное совпадение. Перетащите проверенный mk8dx-host-local-v0.2.12-amd64.zip с левой стороны, вашего компьютера, в /root/ справа, на сервер. Не загружайте резервные копии или секреты в public_html.

3. Откройте PowerShell на компьютере для терминала сервера. Используйте свой реальный IP, порт и путь к ключу. Это тот же ключ OpenSSH из шага 1, а не преобразованный файл .ppk:

$serverIp = '203.0.113.10'
$sshPort = 22
$key = Join-Path $env:USERPROFILE '.ssh\mk8dx_vps_ed25519'
ssh -i $key -p $sshPort "root@$serverIp"

Здесь тоже сравните отпечаток ключа хоста с независимо полученным значением. Только после этого вводите парольную фразу ключа. Если провайдер указывает другого пользователя VPS или порт SSH, замените root или 22. Порты виртуального хостинга — это не настройки VPS.

В терминале Ubuntu проверьте машину:

cat /etc/os-release
uname -m
free -h
df -h /
python3 --version

Вы ожидаете Ubuntu 24.04, x86_64 и Python от 3.12 до 3.15. Если на свежем сервере Ubuntu 24.04 нет Python, выполните:

apt update
apt install python3
python3 --version

Не продолжайте, если машина не Linux x86-64; входящий в комплект пакет образов — amd64.

4. Проверьте, работает ли уже Docker:

command -v docker
docker compose version

Если его нет, используйте официальный метод Docker через apt для Ubuntu на этом сервере. Выполняйте каждую группу в том же терминале сервера и остановитесь, если команда завершится с ошибкой:

Docker для Ubuntu: https://docs.docker.com/engine/install/ubuntu/

apt update
apt install ca-certificates curl unzip
install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
chmod a+r /etc/apt/keyrings/docker.asc

Добавьте официальный источник пакетов. Скопируйте эти строки вместе, включая последнюю строку EOF:

cat > /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
apt update
apt install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

Проверьте:

systemctl is-active docker
docker compose version

Первым ответом должно быть active. Если есть ошибка, не устанавливайте наугад второй вариант Docker; прочитайте ошибку и официальную страницу.

5. В панели DNS той стороны, которая управляет вашим доменом, откройте записи домена. Для имени вроде www.mijneigenwebsite.nl создайте запись A с именем www и значением — реальным IPv4-адресом вашего VPS. Сохраните существующие почтовые записи. Используйте TTL по умолчанию или 300 секунд. Когда изменение распространится, проверьте на своём компьютере:

Resolve-DnsName www.mijneigenwebsite.nl -Type A

В ответе должен быть IP вашего VPS. Проверьте существующую запись AAAA для того же имени: оставляйте её, только если она указывает на работающий сайт с IPv6. В панели провайдера VPS разрешите входящие TCP 80 и 443. Сохраните доступность порта SSH и не публикуйте порт MySQL 3306. Не вносите широких изменений в брандмауэр, если не знаете, как вернёте себе доступ к серверу.

6. Получите у почтового провайдера хост исходящей почты SMTP, порт 465 с неявным TLS, логин, пароль и разрешённый адрес отправителя. Проверьте, что отправка с вашего VPS разрешена. Это отличается от адреса вашего администратора MK8DX. Доставка через настоящего провайдера в этом руководстве не проверялась; установка успешна только тогда, когда ваша собственная ссылка для входа доходит до вашего настоящего почтового ящика.

7. В терминале Ubuntu ZIP, переданный через WinSCP, находится в /root/. Проверьте и распакуйте его:

pwd
ls -lh /root/mk8dx-host-local-v0.2.12-amd64.zip
mkdir -p /opt/mk8dx/host /var/lib/mk8dx
unzip -q /root/mk8dx-host-local-v0.2.12-amd64.zip -d /opt/mk8dx/host
cd /opt/mk8dx/host
ls Start-MK8DX.cmd compose.yaml tooling/start-mk8dx.sh images/docker-images-amd64.tar

Если какого-то имени нет, проверьте, что вы распаковали правильный полный ZIP. Запустите существующий помощник установки:

sh tooling/start-mk8dx.sh /var/lib/mk8dx/instance

Выберите B1. Введите точное имя хоста без https://. Введите пять почтовых значений и адрес своего будущего администратора MK8DX. Пароль SMTP скрыт. Выберите пункт меню 1. Помощник создаёт внутреннюю базу данных, ключи и подключения. При повторе используйте ту же папку /var/lib/mk8dx/instance; не создавайте другой профиль, чтобы обойти проблему с DNS или почтой.

8. На своём компьютере откройте адрес готовности, а затем сайт, используя своё имя хоста вместо примера:

https://www.mijneigenwebsite.nl/health/ready
https://www.mijneigenwebsite.nl

Браузер не должен показывать предупреждение о сертификате. Нажмите «Войти», используйте сохранённый адрес администратора и откройте ссылку в своём настоящем почтовом ящике. Только после этого подтверждённого входа вернитесь в папку пакета в терминале сервера и выберите пункт меню 5:

cd /opt/mk8dx/host
sh tooling/start-mk8dx.sh /var/lib/mk8dx/instance

Ответ — created (создано) или, при повторе, unchanged (без изменений). Обновите сайт. Также проверьте трассу и отправку своей гонки на время. Одни лишь работающие контейнеры не доказывают работу DNS, сертификатов или доставки почты.

Android, LiveTrial, сканер и Tournament

Для отправки результатов эти инструменты используют адрес существующего сообщества. LiveTrial и Tournament Tools работают и сами по себе, без сайта; приложению для Android и браузерному сканеру сайт нужен. На том же компьютере с Windows LiveTrial и Tournament могут использовать http://127.0.0.1:18080 (A1) или http://127.0.0.1:18090 (A3). Для публичного сайта используйте его доверенный HTTPS-адрес. Android нужен доверенный HTTPS; локальная проверка в Windows не доказывает подключение Android. Обычное приложение для Android и клиенты для Windows позволяют выбрать адрес сообщества; другой домен не требует изменения исходного кода. Публичные настройки клиента никогда не содержат паролей сервера. Никогда не вводите в клиенте внутреннее имя mysql, адрес контейнера API или IP для SSH.

Всегда копируйте полный адрес сайта, показанный как «Website» (или «origin», или «Web origin») для вашей собственной установки, включая порт, если он показан. Никогда не вводите в LiveTrial адрес тестового ящика («Sign-in mail» или «localMailInbox»): он открывает только локальный тестовый ящик. На втором устройстве используйте сетевое HTTPS-имя или свой публичный домен, а не адрес 127.0.0.1 сервера.

Для Android нужен Android 8.0 или новее; рекомендуется arm64. Локально подписанный релизный APK весит около 530 МБ. Держите свободным не меньше 1 ГБ как запас для установки. Проверьте mk8dx-android-release-v0.2.12.apk по SHA256SUMS.txt на компьютере, скопируйте его на телефон и откройте из Files (Файлы) или Downloads (Загрузки). Если Android просит разрешить установку из этого файлового приложения, разрешите это только для проверенного пакета. Потом это разрешение можно отключить.

При первом запуске экран «Выбери своё сообщество» спрашивает, как играет ваше сообщество. Для онлайн-сообщества введите полный доверенный HTTPS-адрес сообщества в поле «Адрес сайта», например https://www.mijneigenwebsite.nl, без пути и без косой черты в конце, и нажмите «Сохранить». Для установки дома или в клубе (A2) нажмите «Сканировать QR-код» и отсканируйте карточку «Подготовить устройство»; руководство A2 объясняет этот шаг подробно. Позже нажмите название сообщества вверху приложения, чтобы переключить сообщество или добавить новое кнопкой «Добавить сообщество». У каждого сообщества свой аккаунт и свои ожидающие заезды; ничего не переходит между ними автоматически. Ваши собственные времена находятся под вашим именем → «Мои результаты», в том числе без сети. Для A2 выполните шаг доверия в приложении: сохраните сертификат MK8DX и установите его на телефон как сертификат УЦ. Затем отсканируйте личную карточку входа прямо в приложении и проверьте показанное имя. Браузеру тоже нужен сертификат; шаги описаны в руководстве A2. Код устройства в браузере для этого входа не используется. Ранние публичные APK были подписаны отладочным ключом. Сохраните ещё не отправленные результаты, один раз удалите это отладочное приложение, а затем установите этот релизный APK. Последующие APK, подписанные тем же релизным ключом, могут обновлять его поверх; это не релиз в Play Store.

APK подписывается его создателем, а не отдельно для каждого домена. Автоматическим Android App Links нужна публичная связь между настоящей идентичностью приложения, его фактическим сертификатом подписи и вашим доменом. Поэтому стандартный /.well-known/assetlinks.json содержит [] в формате JSON. Ручной выбор сервера и вход работают без этой автоматической связи. Отдельно подписанная собственная сборка относится к пути для разработчиков.

Для LiveTrial в Windows x86-64 проверьте desktop-client-v0.2.12.zip по SHA256SUMS.txt и распакуйте ZIP целиком, например в «Документы». Предусмотрите около 2 ГБ для распаковки и собственных записей; это запас, а не измеренный минимум. Откройте LiveTrial.exe. Для захвата в реальном времени с карты захвата нужен также FFmpeg, который не входит в комплект из-за своей лицензии: один раз выполните winget install Gyan.FFmpeg в PowerShell и перезапустите LiveTrial (анализ видео работает и без него). Перейдите в «Настройки» → «Адрес сайта сообщества», введите точный адрес своей установки и выберите «Сохранить сервер». Подтвердите переключение.

LiveTrial сохраняет адрес и перезапускается сам. Не закрывайте окно, пока это происходит. После перезапуска проверьте, что «Настройки» показывают ваш точный адрес. Только после этого входите; вход должен открыть ваше сообщество. Когда вы открываете «История заездов», этот раздел при необходимости немного ждёт свой локальный сервер, а затем загружается сам. Нажимать F5 не должно быть нужно. Если LiveTrial сообщает, что автоматический перезапуск не удался, выберите «Выйти из LiveTrial» внутри приложения, дождитесь, пока оно закроется, и снова откройте LiveTrial.exe. Закрыть только окно браузера недостаточно: LiveTrial может продолжать работать в фоне.

Если поле всё ещё пустое с примером https://www.example.org или вход открывает не тот сайт, остановитесь. Закройте запущенный экземпляр LiveTrial через «Выйти из LiveTrial». Возможно, его запустила другая учётная запись Windows на том же компьютере. Откройте его снова и проверьте адрес. Не редактируйте server.json вручную и не отправляйте заезд не на тот сайт. Для видеофайла карта захвата не нужна. Для захвата в реальном времени нужны совместимая карта и драйвер. Локальные результаты и очереди хранятся отдельно для каждого сервера.

Подключение позже: выберите адрес сообщества в настройках до записи, даже если у вас ещё нет учётной записи. Заезды остаются на сервере, для которого были записаны. Чтобы перенести заезд в другое сообщество, подключитесь к нему и обработайте видео заново через «Анализ видео». Заезды, записанные без входа, не отправляются автоматически: назначьте их вошедшей учётной записи через «Отправить как <учётная запись>». «Отправить сейчас» отправляет каждый ожидающий заезд с его исходной учётной записью; заезды вышедшей учётной записи ждут, пока она снова войдёт.

Браузерный сканер уже входит в состав сайта. Откройте /scanner/ по своему доверенному HTTPS-адресу и начните с «image upload» (загрузка изображения; на нидерландском «afbeelding uploaden»). Выберите собственное изображение с результатами, проверьте распознанные данные и подтверждайте только после проверки. Для камеры в реальном времени нужны разрешение браузера и доверенный HTTPS вне localhost. Распознавание также зависит от записи. Описанный для A2 путь со вторым браузером в Windows задокументирован, но не проверен от начала до конца.

Для Tournament в Windows x86-64 проверьте tournament-tools-v0.2.12.zip и распакуйте ZIP полностью. Откройте Install-MK8DX-TournamentTools.cmd. Предусмотрите несколько ГБ свободного места: ZIP размером около 450 МБ и около 1,3 ГБ для распаковки не покрывают все зависимости и ваши собственные медиафайлы. Установщику один раз нужен интернет, чтобы скачать Python 3.12 и публичные пакеты; модели OCR входят в комплект, и после этого обработка работает без сети. Точный минимум для всех зависимостей и медиафайлов не измерялся. Настройка GPU не нужна: с актуальным драйвером NVIDIA установщик сам выбирает версию CUDA, и тогда видеокарта ускоряет распознавание имён, очков и времён (OCR). Первое сканирование записи всегда выполняется на процессоре, потому что сборка OpenCV в пакете не поддерживает CUDA; USING_MK8DX_TOURNAMENT_TOOLS.md в пакете объясняет оба шага. Дождитесь SUCCESS и не трогайте runtime-assets. Если не получилось, прочитайте install.log в папке пакета.

Перетащите запись .mp4 или .mkv на TournamentProcessor.cmd. Программа создаёт рядом с видео папку сеанса с Excel, CSV и файлом, имя которого заканчивается на _TournamentRaceResultsV1.json. TournamentLive.cmd требует подходящего оборудования захвата и драйвера для живого сигнала.

Tournament Live можно попробовать и с готовым видео, без карты захвата. Откройте TournamentLive.cmd, выберите «Добавить видеофайл», выберите файл .mp4 или .mkv, затем «Запустить все». Дождитесь окончания видео и анализа. Проверьте «Подтверждённое положение» и выберите «Открыть экспорты» для файла результатов. Этот обычный путь с видео использует выбор очков, который ждёт, пока анимация очков и итоговое положение установятся. Проверьте имена, места и очки сами; OCR может ошибаться. Повтор видео не проверяет физическую карту захвата. Отдельная команда повтора TournamentLiveCli.cmd диагностическая и не заменяет этот путь.

Чтобы передать прогон на свой сайт, выберите в Tournament Live «Подключиться к Tournament Manager» (после подключения — «Сменить турнир»), завершите вход в браузере и выберите турнир из списка. Этот выбор — только предложение. На сайте откройте турнир, перейдите к шагу 5 (к шагу 9 для финальных групп) и найдите прогон в разделе «Доступные записи Tournament Live». Выберите его группу в «Привязать к группе», затем «Привязать проверенную запись». Гонки ждут как ожидающие доказательства, пока вы их не примете. Tournament Live может сам добавить знакомую ему карту захвата как дополнительный источник на «Группа 1». Если на «Группа 1» стоит ещё и видео, «Запустить все» останавливается и просит назначить каждому потоку другую группу: выделите дополнительный источник и выберите «Удалить выбранное» или дайте ему собственную группу, затем запустите снова.

Для необязательного подключения к сайту откройте PowerShell в папке пакета и выполните:

.\TournamentConnect.cmd sign-in

В первый раз введите точный адрес своей установки и завершите вход в браузере. На A1 или A3 это адрес http://127.0.0.1, который показывает окно MK8DX, например http://127.0.0.1:18080; обычный HTTP принимается только для таких адресов на этом ПК. Эти команды показывают или меняют адрес; изменение запрашивает подтверждение:

.\TournamentConnect.cmd server
.\TournamentConnect.cmd server https://www.example.org

Замените example.org своим настоящим сообществом. Ожидающие загрузки для старого сервера остаются у старого сервера. Чтобы отправить файл с помощью TournamentConnect.cmd send, администратор сначала открывает «Администрирование» → «Турниры» → «Директора», ищет вошедшего игрока и выбирает имя. Это даёт доступ к турнирам, а не общее администрирование. Отправьте снова; гонка остаётся во «Входящие результаты», пока её не проверят. На сайте администратор импортирует проверенный результат через «Администрирование» → «Турниры» → «Импорт канонических результатов гонок» или внутри группы через «Запасной офлайн-вариант: импортировать сохранённый файл результатов Live / Processor». Загрузка не означает автоматическую публикацию.

Для нового турнира администратор открывает «Администрирование» → «Турниры» и создаёт там турнир. Добавьте игроков, отметьте присутствующих, назначьте доступные Switch и подтвердите распределение по группам. Затем откройте «Входящие результаты» для этой группы. Сопоставьте распознанные имена с нужными игроками, проверьте трассу и места на финише и выберите «Подтвердить» для проверенной гонки. Предварительная живая таблица — ещё не официальный результат. Завершите последние шаги группы на сайте. Перед «Проверить завершение» выберите вверху «Задать номер выпуска» и введите номер этого выпуска, например 1. Проверьте итоговую таблицу, затем выберите «Проверить завершение» → «Завершить турнир». Откройте публичную страницу турнира в новом окне браузера, чтобы увидеть опубликованный результат.

Изменение настроек и управление сайтом

Помощник установки спрашивает каждое логическое значение один раз. Он хранит профиль в operator-profile.json, а пароли и ключи отдельно в secrets.json, внутри вашей частной папки данных. Настройки Web, API, Docker и публичного клиента он выводит сам. Не редактируйте api.env, compose.env, operator.json или public-client.json по отдельности. Публичный /client-config.json содержит только адрес сайта. Повторный запуск не создаёт новых аккаунтов, администратора, ключей или базы данных.

В Windows A1 по умолчанию использует %LOCALAPPDATA%\MK8DX\Server, а A2 — %LOCALAPPDATA%\MK8DX\LAN. На VPS B1 использует /var/lib/mk8dx/instance. Это папки данных, а не папки, которые нужно заменять при обновлении программы. Ваш логин у провайдера и ключ SSH для VPS остаются вне MK8DX. Каждое устройство с Android или Windows хранит собственный выбор сообщества и сеанс.

Для запуска, статуса, остановки, администратора и резервной копии в Windows снова откройте соответствующий Start-MK8DX.cmd или Start-MK8DX-LAN.cmd (добавьте -SkipCountdown, чтобы пропустить отсчёт, или задайте MK8DX_SOUND=0, чтобы не было сигналов; в Ubuntu --skip-countdown). В Ubuntu перейдите в /opt/mk8dx/host и выполните sh tooling/start-mk8dx.sh /var/lib/mk8dx/instance. В меню 2 — запуск, 3 — статус, 4 — остановка, 5 — подтверждённый первый администратор, 6 — резервная копия и 7 — обновление с предварительной проверенной резервной копией. Пункт 1 может продолжить прерванную первую настройку. Никогда не используйте docker compose down -v для установки, которую хотите сохранить: -v удаляет том базы данных. Чтобы полностью удалить пробную установку (это удаляет её базу данных, аккаунты и ключи; если они могут понадобиться, сначала выберите 6 для резервной копии): выберите 4 для остановки, затем откройте PowerShell в папке пакета и выполните docker compose --env-file "$env:LOCALAPPDATA\MK8DX\Server\compose.env" -f compose.yaml -f compose.local.yaml -f compose.images.yaml down -v и удалите папку %LOCALAPPDATA%\MK8DX\Server (для способа с домашней сетью используйте compose.lan.yaml). В Ubuntu выполните ту же команду с --env-file /var/lib/mk8dx/instance/compose.env (compose.production.yaml для VPS), а затем удалите /var/lib/mk8dx/instance.

Чтобы сменить почтовый сервис или пароль на A2 или B1, сначала создайте резервную копию пунктом меню 6. На A2 откройте PowerShell в извлечённой папке хоста и выполните:

python tooling/install.py change-smtp --state-dir (Join-Path $env:LOCALAPPDATA 'MK8DX\LAN')
python tooling/install.py apply --state-dir (Join-Path $env:LOCALAPPDATA 'MK8DX\LAN')
python tooling/install.py check --state-dir (Join-Path $env:LOCALAPPDATA 'MK8DX\LAN')

В Ubuntu выполните те же действия в /opt/mk8dx/host с python3 и --state-dir /var/lib/mk8dx/instance. Запросы называют smtp.host, smtp.port, smtp.username и smtp.fromAddress и спрашивают скрытый пароль. Enter сохраняет существующее значение. Потом проверьте новое письмо для входа в своём настоящем почтовом ящике; одна лишь проверка check не доказывает доставку почты. Адрес администратора, адрес отправителя и логин SMTP не обязаны совпадать.

Меняйте адрес публичного сайта только после того, как его новый адрес в DNS и HTTPS готовы. Сначала создайте резервную копию. Этот пример для A1 показывает точное действие изменения; замените пример порта нужным свободным портом:

python tooling/install.py change-origin --state-dir (Join-Path $env:LOCALAPPDATA 'MK8DX\Server') --origin 'http://127.0.0.1:18090'
python tooling/install.py apply --state-dir (Join-Path $env:LOCALAPPDATA 'MK8DX\Server')
python tooling/install.py check --state-dir (Join-Path $env:LOCALAPPDATA 'MK8DX\Server')

Для B1 используйте python3, /var/lib/mk8dx/instance и свой полный новый адрес https://. Проверьте статус, /client-config.json и новую ссылку для входа. Также направьте каждое устройство на новый адрес. Неправильный адрес администратора можно исправить в помощнике установки до первой выдачи прав; это не открывает заново уже использованную первую выдачу. Существующий администратор может добавить ещё одного подтверждённого администратора только через ограниченную процедуру восстановления и явное решение владельца.

На сайте в разделе «Администрирование» → «Настройки установки» находятся общие для сайта параметры. «Название сообщества» (например, «Club Noord») показывается в приложениях вместо веб-адреса; оставьте пустым, если название не нужно. «Времена из других сообществ» определяет, будет ли время, которое игрок переносит из другого сообщества, отклонено («Выключено», по умолчанию), ждать, пока администратор не нажмёт «Опубликовать» рядом с ним в разделе «Администрирование» → «Гонки на время» («С одобрением»), или следовать обычным правилам публикации («Разрешено»). Если вы уходите с варианта «С одобрением», пока перенесённые времена ещё ждут, страница спросит, что с ними делать. Каждое изменение записывается с именем администратора.

Подтверждение опасных действий: изменение прав администратора, директора или отчётов, прямая привязка аккаунта к игроку, настройки установки, пересчёт рейтингов, удаление, повторное открытие или восстановление вечера и открытие списка всех аккаунтов сначала требуют «Подтвердить новой ссылкой из письма». Нажмите «Отправить ссылку»; ссылка придёт на ваш собственный адрес, сработает один раз в течение 10 минут и подтвердит только этот браузер или приложение. Откройте её на любом устройстве и нажмите «Подтвердить это действие»; действие продолжится само. Если вы получили такое письмо, не запрашивая его, значит, у кого-то другого есть сеанс вашего аккаунта: не подтверждайте и используйте «Выйти на всех устройствах». Если почта не работает, всё равно нажмите «Отправить ссылку» и в течение 10 минут выполните на сервере python tooling/install.py step-up-link --state-dir <папка установки> (python3 в Linux и на общем хостинге); команда выведет новую одноразовую ссылку для этого запроса. A2 не отправляет писем и не запрашивает такое подтверждение.

Резервное копирование, восстановление и обновление

Автоматическая резервная копия: MK8DX также каждую ночь сам делает проверенную резервную копию (A1, A3 и B1 включают её при первой настройке; B2 спрашивает один раз, Enter означает «да»; у A2 своя копия в MK8DX beheer). Она сохраняется в Documents\MK8DX-backups\automatic в Windows и в ~/mk8dx-backups/automatic в Linux и на виртуальном хостинге, хранятся 14 дней и 4 недели, а неудачная ночь никогда не удаляет более старые копии. Меню 3 (проверка) показывает в automaticBackup (A3: backup-status) возраст и результат последней. Всё равно храните копию вне компьютера или сервера: в Windows с помощью python tooling/install.py backup-schedule --state-dir <папка установки> --copy-to <папка> (другой диск или NAS); на сервере python3 tooling/install.py backup-latest --state-dir <папка установки> --print-path называет самую новую проверенную папку, которую можно забрать через scp. Отключение: backup-unschedule вместо backup-schedule. Если хостинг уже ежедневно копирует аккаунт (DirectAdmin, JetBackup), этого может хватить; собственная копия всё равно позволяет самому вернуть вчерашнее состояние, включая ключи сайта.

Учётные записи базы данных: сайт входит в свою базу данных под учётной записью, которая может только читать и записывать данные, поэтому ошибка сайта никогда не сможет удалить таблицы; обновления базы данных и резервные копии используют вторую учётную запись. A1, A2, A3 и B1 настраивают это сами, существующая установка — при следующем обновлении (меню 7); если сайт не запускается с новой учётной записью, обновление возвращается к старой и ничего не теряется. Для B2 создайте в DirectAdmin или cPanel второго пользователя базы данных только с SELECT, INSERT, UPDATE и DELETE и укажите его в мастере или позже командой python3 tooling/install.py database-accounts --state-dir <папка установки>; с одним пользователем B2 продолжает работать, но показывает предупреждение.

Выберите пункт меню 6 на соответствующем хосте. В Windows резервная копия попадает в Documents\MK8DX-backups\<timestamp>. В Ubuntu — в /root/mk8dx-backups/<timestamp>, если вы работаете как root. Она содержит базу данных, аккаунты, права администраторов, настройки и ключи. Держите всю папку в секрете и также копируйте её в защищённое хранилище вне хоста. Копии на том же вышедшем из строя VPS недостаточно.

Проверьте фактически созданную папку. Замените <ACTUAL_FOLDER> ниже именем папки, которое показал помощник. В Windows, в PowerShell из серверного пакета:

python tooling/lifecycle.py verify --backup "$env:USERPROFILE\Documents\MK8DX-backups\<ACTUAL_FOLDER>"

В Ubuntu, в папке серверного пакета:

python3 tooling/lifecycle.py verify --backup '/root/mk8dx-backups/<ACTUAL_FOLDER>'

Ожидаемый ответ — «Backup verified» (резервная копия проверена). Никогда не передавайте резервную копию в issue, по электронной почте или по публичной облачной ссылке.

Восстановление резервной копии

Пробное восстановление использует новую папку данных и новый проект Docker. Существующая установка остаётся нетронутой. Операция восстановления сначала запускает только новую базу данных. Восстановленный сайт запускайте затем в соответствии со своим способом установки. После пробы сохраните исходную резервную копию.

Для A1 откройте PowerShell в серверном пакете. Выберите целевую папку, которой ещё нет, и выполните:

python tooling/lifecycle.py restore-new --backup "$env:USERPROFILE\Documents\MK8DX-backups\<ACTUAL_FOLDER>" --state-dir (Join-Path $env:LOCALAPPDATA 'MK8DX\Herstelproef')
python tooling/install.py status --state-dir (Join-Path $env:LOCALAPPDATA 'MK8DX\Herstelproef')
python tooling/install.py start --state-dir (Join-Path $env:LOCALAPPDATA 'MK8DX\Herstelproef')
python tooling/install.py check --state-dir (Join-Path $env:LOCALAPPDATA 'MK8DX\Herstelproef')

Восстановленный сайт A1 получает собственные свободные локальные порты. Откройте его новый Web origin из статуса. Проверьте известный аккаунт, раздел администрирования и свои результаты. Исходный сайт может продолжать работать. Не выдавайте пробному восстановлению нового первого администратора.

Для публичной замены B1 используйте новый VPS с Ubuntu 24.04 с проверенным серверным пакетом, Docker, Python и открытыми портами 80/443. Старый VPS пока сохраните. Запланируйте короткое окно обслуживания. На старом VPS сначала остановите только Web и API, чтобы после окончательной резервной копии не поступали новые результаты. В папке старого серверного пакета выполните:

docker compose --env-file /var/lib/mk8dx/instance/compose.env -f compose.yaml -f compose.production.yaml -f compose.images.yaml stop web api

Сайт теперь временно недоступен. На старом VPS выберите пункт меню 6 для новой резервной копии, пока MySQL ещё работает. Проверьте именно эту новую резервную копию командой verify выше. Если проверка не прошла, возобновите старый сайт пунктом меню 2 и разберитесь. Перенесите всю проверенную папку резервной копии через проверенное подключение WinSCP в частную папку на новом VPS, никогда не в веб-папку. Поместите её, например, в /root/mk8dx-backups/. На новом сервере в /opt/mk8dx/host выполните с настоящим именем папки резервной копии:

docker load --input images/docker-images-amd64.tar
python3 tooling/lifecycle.py restore-new --backup '/root/mk8dx-backups/<ACTUAL_FOLDER>' --state-dir /var/lib/mk8dx/herstelproef
python3 tooling/install.py status --state-dir /var/lib/mk8dx/herstelproef

Новая база данных теперь готова в собственном проекте. Сверьте восстановленные данные со своей существующей частной резервной копией и статусом. Запланируйте короткое переключение. В панели DNS измените только запись A для имени хоста MK8DX на IPv4-адрес нового VPS. Сохраните почтовые записи. Дождитесь, пока Resolve-DnsName на вашем компьютере не покажет новый IP. Затем запустите восстановленные службы на новом VPS:

python3 tooling/install.py start --state-dir /var/lib/mk8dx/herstelproef
python3 tooling/install.py check --state-dir /var/lib/mk8dx/herstelproef

На своём компьютере откройте https://<your-real-host-name>/health/ready и сайт. Проверьте действительный сертификат, собственное письмо для входа в своём настоящем почтовом ящике, известный аккаунт, раздел администрирования и результаты. Новая установка Docker запрашивает собственный публичный сертификат; порты 80/443 и новое назначение DNS должны быть доступны. Держите старый VPS вне пути посетителей и сохраните его для расследования или возврата. Если проверка не прошла, сохраните резервную копию, разберитесь с DNS, портами, сертификатом и SMTP и запланируйте обдуманное возвращение записи A на старый IP. Не удаляйте том в качестве быстрого решения. Настоящее переключение с внешними службами для этого локального кандидата не выполнялось.

Для A2 выполняйте восстановление на другом хосте с Windows в той же доверенной сети. Подготовьте Docker, Python и серверный пакет. Во время короткого окна обслуживания остановите на старом хосте только Web и API. База данных продолжает работать для окончательной резервной копии. Откройте PowerShell в папке старого пакета:

$state = Join-Path $env:LOCALAPPDATA 'MK8DX\LAN'
$compose = @('--env-file', (Join-Path $state 'compose.env'), '-f', 'compose.yaml', '-f', 'compose.lan.yaml', '-f', 'compose.images.yaml')
docker compose @compose stop web api

Затем выберите пункт меню 6 на старом хосте и проверьте новую резервную копию. Если не получилось, возобновите старую установку пунктом меню 2. Перенесите проверенную папку резервной копии частным образом на новый хост. Поместите её в Documents\MK8DX-backups\ с тем же именем папки или исправьте путь к резервной копии в следующей команде. Там выполните restore-new в папку восстановления LAN, которой ещё нет. Перед запуском измените сохранённый адрес привязки на реальный IPv4 нового хоста:

docker load --input images/docker-images-amd64.tar
python tooling/lifecycle.py restore-new --backup "$env:USERPROFILE\Documents\MK8DX-backups\<ACTUAL_FOLDER>" --state-dir (Join-Path $env:LOCALAPPDATA 'MK8DX\LAN-Herstel')
python tooling/install.py change-lan-address --state-dir (Join-Path $env:LOCALAPPDATA 'MK8DX\LAN-Herstel') --lan-bind-address '192.168.0.51'
python tooling/install.py start --state-dir (Join-Path $env:LOCALAPPDATA 'MK8DX\LAN-Herstel')
python tooling/install.py check --state-dir (Join-Path $env:LOCALAPPDATA 'MK8DX\LAN-Herstel')

Замените пример IP и разрешите TCP 443 на новом хосте только для профиля Private (частный). На хосте и втором компьютере измените запись hosts для mk8dx.home.arpa на новый IP. У этого нового проекта Docker новый локальный центр сертификации. Получите новый root.crt из этого проекта восстановления с помощью команд для сертификата из главы о домашней сети, но используйте LAN-Herstel в качестве $state. Снова сравните SHA-256 и установите новый сертификат на втором компьютере. Удалите старый сертификат через certmgr.msc в разделе Trusted Root Certification Authorities → Certificates (Доверенные корневые центры сертификации → Сертификаты), опознав его по старому отпечатку. Только после этого откройте сайт без предупреждения и проверьте вход и существующие результаты. Физический переезд A2 ещё не проверялся; сохраните исходный хост и резервную копию.

Для обновления программы сначала проверьте SHA-256 нового серверного пакета. Распакуйте его рядом со старой папкой программы. Используйте ту же частную папку данных и выберите пункт меню 7 в новом пакете. Помощник сначала создаёт и проверяет резервную копию, выполняет недостающие миграции и заменяет только входящие в комплект серверные программы. После этого проверьте ту же идентичность проекта, сайт, вход и данные. Если что-то не получилось, сохраните резервную копию и не запускайте вслепую более старый образ после изменения схемы базы данных.

Обновление до 0.2.3 переводит базу данных Docker с MySQL 8.4 на MySQL 9.7 LTS. MySQL один раз обновляет файлы данных при первом запуске на новой версии; отменить это можно только восстановлением резервной копии. Поэтому в папке нового пакета сначала выберите 7 (обновление): он создаёт проверенную резервную копию и применяет обновления базы данных. Начиная с 0.2.4, пункт 2 (запуск) отказывается запускаться, пока обновление не выполнено; с пакетом 0.2.3 пункт 2 пропустил бы резервную копию. Пункт меню 3 (проверка) безвреден. В пакете A2 кнопка Update (Обновить) в браузере сама сначала создаёт резервную копию; первое обновление просто длится немного дольше, а резервная копия находится в Documents\MK8DX-backups. A3 и B2 используют собственную MariaDB или MySQL, и их это не затрагивает.

Устранение неполадок и самостоятельная сборка

Если сайт пустой, проверьте Docker: на A1 и B1 используйте пункт меню 3, на A2 откройте MK8DX beheer. На A1 письма для входа приходят в Mailpit; на B1 они должны приходить в настоящий почтовый ящик. A2 использует карточки для входа, а не электронную почту. Проверьте установку и адрес сайта; для способов с почтой также проверьте адрес входа. Если на публичном способе письма не приходят, проверьте настройки SMTP и доступность провайдера. /health/ready сообщает о готовности API и базы данных, а не о доставке писем.

Только B2: если общий хостинг отклоняет скачивание большого файла приложения, администратор может включить краткосрочные статические ссылки с возможностью возобновления скачивания. См. раздел «App downloads on hosts that limit application responses» в docs/install/B2_WEBHOSTING_EN.md. Уведомления браузера необязательны и требуют собственных ключей VAPID и поддерживаемых push-служб; см. там же «Browser notifications (Web Push)». Где находятся дополнительные настройки и как их применить, описано в docs/install/SETTINGS_EN.md.

Если Start-MK8DX.cmd на A1 останавливается с сообщением «all predefined address pools have been fully subnetted», старые сети Docker исчерпали его диапазоны адресов. Посмотрите их командой docker network ls в PowerShell. Удаляйте только сети, о которых точно знаете, что они не используются, например командой docker network prune: она удаляет только сети, которые не использует ни один контейнер. Затем снова откройте Start-MK8DX.cmd.

На A2 сначала проверьте, что устройство находится в той же частной локальной сети, что и компьютер MK8DX, адрес Website и доступ через брандмауэр верны, а устройство доверяет сертификату, соответствующему коду на карточке «Подготовить устройство». См. главу 11 руководства A2. На B1 проверьте запись A в DNS, порты провайдера 80/443, действительный HTTPS, а затем почту. Не игнорируйте предупреждение о сертификате. Обращаясь за помощью, никогда не передавайте secrets.json, резервную копию, ссылки для входа, ключи SSH или строки журнала с паролями.

Чтобы собрать собственный код, оформление или итоговый подписанный APK, скачайте пакет mk8dx-full-local с той же страницы релиза. Он содержит исходный код, внутреннюю коллекцию ресурсов и рецепты сборки. Инструкции для разработчиков находятся в docs/DEVELOPMENT.md и docs/CLIENT_BUILDS.md. Из клона репозитория (git clone https://github.com/fromthelake/MK8DX-Ecosystem.git) или этого пакета docs/guides/HOSTING.md («Build the host package from a clone») собирает серверный пакет Docker и пакеты для виртуального хостинга и XAMPP, а docs/CLIENT_BUILDS.md собирает пакеты Android, LiveTrial и Tournament. Для обычной установки и выбора сервера не нужны Android Studio, правка исходного кода или самостоятельно собранный образ Docker. Игровые материалы в пакетах сохраняют собственные условия; см. docs/THIRD_PARTY_MATERIALS.md.

Использование Linux

Что можно попробовать локально уже сейчас

Вам нужен только собственный компьютер с Linux, без компьютера с Windows. Если на нём Ubuntu 24.04 на x86-64, входящий в комплект серверный пакет Docker — это способ запустить локальный сервер. Сначала выполните uname -m и проверьте, что выводится x86_64. Установите Docker Engine с плагином Compose, Python от 3.12 до 3.15 и unzip. Установка Docker в Ubuntu пошагово описана в «Публичный сайт на VPS»; для этой локальной пробы пропустите DNS, открытие портов брандмауэра в интернет и настоящий SMTP. Скачайте mk8dx-host-local-v0.2.12-amd64.zip и его SHA256SUMS.txt из того же релиза. Откройте Терминал в папке загрузок и проверьте ZIP. Сравните результат с его строкой в SHA256SUMS.txt. Остановитесь, если они различаются:

sha256sum mk8dx-host-local-v0.2.12-amd64.zip

Распакуйте пакет и перейдите в его папку:

mkdir -p "$HOME/MK8DX/host"
unzip -q mk8dx-host-local-v0.2.12-amd64.zip -d "$HOME/MK8DX/host"
cd "$HOME/MK8DX/host"

Существующий запускающий скрипт для Linux:

sh tooling/start-mk8dx.sh "$HOME/mk8dx-data"

Введите A1; первая настройка начнётся сама. Скрипт показывает полный адрес сайта как «Веб-источник (origin)», а Mailpit — как «Локальный почтовый ящик». Оба адреса 127.0.0.1 работают на этом компьютере с Linux. Откройте сайт в браузере, а Mailpit — во второй вкладке, чтобы получить ссылку для входа. Если сайт запустится, вы сможете локально пользоваться там сайтом и браузерным сканером. Сами проверьте, что вход, отправка результата и его отображение на сайте действительно работают. Эта полная локальная цепочка для этого релиза в Linux не прогонялась; одни лишь работающие контейнеры этого не доказывают.

Что ещё требует разработки

Входящие в комплект программы LiveTrial и Tournament — это программы для Windows. Они не запускаются напрямую как приложения Linux. ZIP для XAMPP и его помощник для Apache в Windows тоже не являются установщиком для Linux. Готового нативного клиента для Linux или приёмочной проверки захвата в Linux нет. Чтобы использовать всю экосистему без Windows, разработчик, знакомый с Linux, должен портировать и упаковать настольные клиенты, их зависимости OCR и интерфейс захвата, а затем проверить вход и доставку через базу данных на сайт. APK для Android устанавливается на Android, а не на Linux. Серверный пакет A1/B1 существует только для amd64; на Linux ARM (arm64) используйте пакет A2 mk8dx-a2-linux-arm64.

Использование macOS

Что можно попробовать локально уже сейчас

Вам нужен только собственный Mac, без компьютера с Windows или другого сервера. На Mac с Intel разработчик может попробовать запустить входящие в комплект образы Docker Linux/amd64 локально. Если сайт, API и база данных действительно запустятся, откройте показанные адреса сайта A1 и Mailpit в браузере на том же Mac. Сканер входит в состав сайта. Ни одна проба на Mac пока не показала новый аккаунт, отправку результата, запись в базе данных и видимый результат на сайте. Одна лишь работающая главная страница не доказывает полную установку.

На Mac с Intel установите Docker Desktop для Mac и Python от 3.12 до 3.15. Скачайте тот же серверный ZIP и SHA256SUMS.txt. Откройте Терминал в папке загрузок, выполните shasum -a 256 mk8dx-host-local-v0.2.12-amd64.zip и сравните результат с SHA256SUMS.txt. Остановитесь, если они различаются. Затем используйте команды mkdir, unzip и cd из главы о Linux. Запустите тот же скрипт оболочки и выберите A1. Это проба для разработчиков, а не принятый пользовательский путь для Mac. На Apple Silicon этому серверному пакету A1 нужна эмуляция для его образов amd64; нативного пакета A1 для arm64 нет, а работоспособность и скорость под эмуляцией не доказаны. На Mac с Apple Silicon используйте вместо этого пакет A2 mk8dx-a2-macos-arm64 (см. «Использование в домашней сети»).

Docker Desktop для Mac: https://docs.docker.com/desktop/setup/install/mac-install/

Что ещё требует разработки

ZIP для XAMPP/Node и готовые клиенты LiveTrial и Tournament — это пакеты для Windows; приложений для Mac они не дают. Разработчик, знакомый с macOS, должен портировать и собрать эти клиенты, включая их зависимости OCR и интеграцию с картой захвата, а затем проверить всю цепочку доставки. Виртуальная машина с Windows или слой совместимости не приняты как замена клиентского пути. APK для Android остаётся для устройства на Android.
