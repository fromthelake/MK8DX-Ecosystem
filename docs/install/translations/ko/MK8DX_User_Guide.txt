MK8DX 설치와 사용

MK8DX 0.2.3 안내서 · 2026년 11월 14일

환영합니다

MK8DX는 마리오 카트 8 디럭스의 타임 어택과 토너먼트를 위한 웹사이트입니다. 코스와 기준 기록을 둘러보고, 이메일 링크로 로그인하고, 내 결과를 제출할 수 있습니다. 관리자는 제출된 기록을 검토할 수 있습니다. 스캐너, Android 앱, Windows 프로그램은 별도의 도구입니다.

릴리스 패키지는 프로젝트의 GitHub Releases에 첨부되어 있습니다. 릴리스 페이지 https://github.com/fromthelake/MK8DX-Ecosystem/releases 를 열고 가장 최근 릴리스를 고르세요. Assets 아래에서 내 설치 방법에 맞는 패키지와 SHA256SUMS.txt를 다운로드합니다. GitHub의 Source code (zip) 버튼은 설치 패키지가 아닙니다. 대신 소스 클론에서 작업한다면 패키지를 직접 빌드할 수 있습니다. “문제 해결과 직접 빌드하기”를 참고하세요. 패키지 파일 이름의 v0.2.3은 이 릴리스를 나타내며, 호스트 패키지 안의 Docker 이미지에도 그에 맞는 버전 태그가 붙어 있습니다. 같은 릴리스의 파일은 모두 함께 보관하세요.

웹사이트를 쓰는 방법을 하나 고르세요. Windows 컴퓨터 한 대에서는 Docker, 또는 XAMPP·Node.js와 포함된 최신 MariaDB 중 하나를 씁니다. 문서화된 Docker 네트워크 방법으로는 신뢰할 수 있는 네트워크의 두 번째 Windows PC에서도 접속할 수 있습니다. 공개 도메인에는 Node.js가 있는 공유 웹 호스팅(이 장에서는 mijn.host Starter를 예로 듦)이나 자체 Docker VPS 중 하나를 고르세요. 이 장들은 서로 대안이며, 순서대로 모두 마쳐야 하는 과정이 아닙니다. 휴대폰과 Windows 클라이언트는 웹사이트 설치 방법 다음에 나옵니다.

A1(컴퓨터 한 대의 Docker)과 A3(Windows의 XAMPP/Node.js)은 새로 설치한 경우와 데이터를 유지한 업그레이드 테스트를 거쳐 지원됩니다. A2(집이나 클럽 네트워크, 0.2.0의 새 기능)는 브라우저에서 안내하는 설치가 있는 자체 패키지가 있으며, Windows 11에서 처음부터 끝까지 테스트되었습니다. B1(Docker VPS)은 문서화되어 있지만 처음부터 끝까지 테스트되지는 않았습니다. B2(공유 Node.js 호스팅): 우리 커뮤니티 사이트가 이 방식으로 운영되지만, 공개 패키지를 새 호스팅 계정에 처음부터 설치해 본 적은 아직 없습니다. 로컬 A1과 A3 설치는 Windows 11 x86-64에서 계정, LiveTrial, 데이터베이스와 웹사이트의 Tournament Processor/Connect 결과까지 포함해 테스트되었습니다. 실제 Tournament Live 캡처는 0.2.2 패키지로 1배속 전체 인수 테스트를 통과했습니다. Windows 컴퓨터나 다른 서버 없이 Linux나 macOS만 있다면 선택지가 더 좁습니다. 마지막 두 장에서 같은 컴퓨터에서 로컬로 시험해 볼 수 있는 것과, 내 운영 체제용으로 아직 없는 제품을 설명합니다.

컴퓨터 한 대에서 시험해 보기

x86-64 프로세서가 있는 Windows 11 컴퓨터 한 대에서 하는 시험입니다. 권장 여유분으로 메모리 8 GB와 약 15 GB의 작업 공간을 확보하세요. 측정된 엄격한 최소값은 아닙니다. Windows에서는 Settings → System → About(설정 → 시스템 → 정보)에서 프로세서와 메모리를 확인합니다. 여유 공간은 File Explorer → This PC(파일 탐색기 → 내 PC)에 있습니다. 도메인이나 유료 이메일 서비스는 필요 없습니다.

1. 공식 Windows 페이지에서 Docker Desktop을 설치합니다. WSL2와 Linux 컨테이너를 고르세요. 설치 프로그램이 요청하면 Windows를 다시 시작합니다. Docker Desktop을 열고 “Engine running”(엔진 실행 중)이 나올 때까지 기다립니다.

Docker Desktop for Windows: https://docs.docker.com/desktop/setup/install/windows-install/

시작 메뉴에서 PowerShell을 엽니다. 이 명령은 버전을 보여 줘야 합니다:

docker compose version

Docker가 시작되지 않으면 먼저 WSL이나 가상화에 관한 메시지를 따르세요. Docker Desktop이 닫혀 있으면 MK8DX가 시작할 수 없습니다.

2. 공식 페이지에서 Windows x86-64용 Python 3.12~3.15를 설치합니다. 설치 프로그램에서 “Add python.exe to PATH”(PATH에 python.exe 추가)를 체크하고 “Install Now”(지금 설치)를 고르세요. PowerShell을 닫고 다시 엽니다. 버전을 확인합니다:

Python for Windows: https://www.python.org/downloads/windows/

python --version

3.12~3.15 버전이 보이지 않으면 같은 설치 프로그램으로 Python을 복구하세요. 설치한 Python 대신 Windows가 Microsoft Store 별칭을 열었는지도 확인하세요. 여기서 Python은 설치 도우미만 실행하며, 소프트웨어를 빌드할 필요는 없습니다.

3. mk8dx-host-local-v0.2.3-amd64.zip과 SHA256SUMS.txt를 같은 다운로드 폴더에 둡니다. 그 폴더에서 PowerShell을 열고 호스트 패키지를 확인합니다:

Get-FileHash '.\mk8dx-host-local-v0.2.3-amd64.zip' -Algorithm SHA256

값 전체를 SHA256SUMS.txt에 있는 그 파일의 줄과 비교합니다. 다르면 중단하고 올바른 사본을 요청하세요. ZIP을 마우스 오른쪽 단추로 클릭하고 “Extract All”(압축 풀기)을 고릅니다. 적당한 위치는 Documents\MK8DX\host입니다. Start-MK8DX.cmd와 compose.yaml이 들어 있는, 압축을 푼 폴더를 엽니다.

4. Start-MK8DX.cmd를 두 번 클릭합니다. 짧은 레이스 인트로와 함께 창이 열립니다: MK8DX 로고와 신호음이 있는 3-2-1-GO 카운트다운(Start-MK8DX.cmd -SkipCountdown은 카운트다운을 생략하며, 호스팅 안내서에 모든 옵션이 나와 있음). 그다음 “Where will MK8DX run?”(MK8DX를 어디서 실행할까요?)이라고 묻고 A1, A2, B1을 보여 줍니다. A1을 입력하고 Enter를 누릅니다. 나중에 로그인해 관리자가 될 때 쓸 이메일 주소를 입력합니다. 그러면 첫 설정이 저절로 시작됩니다. MK8DX가 함께 제공된 프로그램을 불러오고 자체 키, 데이터베이스, 표준 기준 데이터를 만듭니다. 첫 시작은 시간이 좀 걸릴 수 있습니다.

“Web origin”(웹 주소)과 “Local mail inbox”(로컬 메일 받은편지함)로 표시된 주소를 적어 두세요. 웹사이트 주소는 http://127.0.0.1:18080, 테스트 받은편지함은 http://127.0.0.1:18025 처럼 보일 수 있습니다. 마지막 숫자는 다를 수 있습니다. 항상 실제로 표시된 주소를 쓰세요.

나중에 주소를 잊었나요? Start-MK8DX.cmd를 다시 열고 상태를 보려면 3을 고르세요. “origin”은 브라우저와 LiveTrial에서 쓰는 전체 웹사이트 주소입니다. “localMailInbox”는 Mailpit 주소입니다. 로컬 로그인 메일을 읽으려면 이 두 번째 주소를 브라우저에서만 여세요. 콜론 뒤의 숫자가 포트입니다. “127.0.0.1”은 이 컴퓨터를 뜻하므로, 이 A1 주소는 다른 PC나 휴대폰에서는 작동하지 않습니다.

개인 설치 데이터는 압축을 푼 패키지 밖의 %LOCALAPPDATA%\MK8DX\Server에 보관됩니다. 더 새로운 소프트웨어 패키지를 받을 때 이 폴더와 Docker 데이터베이스 볼륨을 유지하세요.

5. 같은 컴퓨터의 브라우저에서 표시된 웹사이트 주소를 엽니다. “로그인”을 클릭하고(영어 화면은 “Sign in”, 네덜란드어 화면은 “Aanmelden”) 4단계의 주소를 정확히 입력합니다. 다른 브라우저 탭에서 “Local mail inbox”(로컬 메일 받은편지함)를 엽니다. 이것은 내 컴퓨터에 있는 테스트 받은편지함인 Mailpit입니다. 그곳에서 가장 최근의 로그인 이메일을 열고 링크를 따라갑니다. 이 시험용 이메일을 평소 쓰는 받은편지함에서 찾지 마세요.

로그인되었지만 아직 관리자 권한은 없습니다. Start-MK8DX.cmd를 다시 열고 5를 고릅니다. 처음 부여하면 “created”(생성됨), 반복하면 “unchanged”(변경 없음)라고 나옵니다. 웹사이트를 새로 고치거나 다시 로그인하세요. 관리 화면이 나타나야 합니다. 임의의 첫 가입자가 자동으로 관리자 권한을 받는 일은 절대 없습니다.

6. “코스”를 열고 코스를 하나 고른 다음 Nintendo 스태프와 세계 기록을 봅니다. “타임 어택 제출”로 시험 주행을 제출해도 됩니다. 보내기 전에 세부 정보를 확인하세요. 제출은 공개 승인과 같은 것이 아닙니다.

Mailpit에는 로그인 링크가 들어 있습니다. 이 테스트 받은편지함을 다른 사람과 공유하지 마세요. 공개 사이트에는 실제 발신 메일이 있는 공유 호스팅이나 VPS 방법을 고르세요.

Docker 없이 컴퓨터 한 대에서: XAMPP와 Node.js

Windows 11 컴퓨터 한 대에서 하는 별도의 시험입니다. Docker는 필요 없습니다. XAMPP가 Apache와 로컬 웹사이트를 시작하는 제어 창을 제공합니다. MK8DX 자체는 Node.js에서 실행됩니다. 현재 XAMPP 다운로드에는 MariaDB 10.4.32가 들어 있지만, 이 방법은 그 버전을 쓰지 않습니다. MK8DX 패키지에는 127.0.0.1:18306 에만 연결되는, 유지 관리되는 별도의 MariaDB 11.4.13 인스턴스가 포함되어 있습니다. 기존 XAMPP 데이터베이스와 다른 웹사이트는 바뀌지 않습니다. 패키지, 데이터베이스, 스캐너, 백업을 위해 RAM 8 GB와 몇 GB의 여유 공간을 확보하세요.

1. 공식 웹사이트에서 Windows용 XAMPP를 다운로드하고 C:\xampp 처럼 찾기 쉬운 곳에 설치합니다. XAMPP Control Panel(XAMPP 제어판)에서는 Apache만 쓰세요. MK8DX를 위해 MySQL, FileZilla, Mercury, Tomcat을 시작하지 마세요. 다른 프로젝트에 이미 XAMPP를 쓰고 있다면 그 데이터베이스와 설정은 그대로 두세요.

XAMPP for Windows: https://www.apachefriends.org/download.html

2. 공식 Node.js 웹사이트에서 Windows용 Node.js 24를 설치합니다. 공식 Windows 다운로드 페이지에서 Python 3.12 이상을 설치하고 “Add python.exe to PATH”(PATH에 python.exe 추가)를 선택합니다. PowerShell을 닫고 다시 엽니다. 확인합니다:

Node.js: https://nodejs.org/en/download
Python: https://www.python.org/downloads/windows/
node --version
python --version

Node 24와 Python 3.12 이상이 보여야 합니다. 이 프로그램들은 미리 빌드된 MK8DX 파일을 실행하며, 애플리케이션을 빌드하지는 않습니다. 명령을 알 수 없다고 나오면 PowerShell을 다시 열고, 필요하면 그 설치를 복구하세요.

3. mk8dx-xampp-node-windows-v0.2.3.zip과 SHA256SUMS.txt를 같은 다운로드 폴더에 둡니다. PowerShell에서 SHA-256 값 전체를 이 ZIP의 줄과 비교합니다:

Get-FileHash '.\mk8dx-xampp-node-windows-v0.2.3.zip' -Algorithm SHA256

일치하면 ZIP을 마우스 오른쪽 단추로 클릭하고 “Extract All”(압축 풀기)을 고릅니다. 적당한 폴더는 Documents\MK8DX\nodocker-v0.2.3입니다. Start-MK8DX-No-Docker.cmd가 들어 있는, 압축을 푼 폴더를 엽니다. 여기에는 이미 bin\mailpit.exe와 bin\mariadb-11.4.13-winx64.zip이 들어 있습니다. 소스 코드를 컴파일하거나 기존 XAMPP 데이터베이스를 바꿀 필요는 없습니다. 이 패키지를 htdocs에 넣지 마세요.

4. 이 로컬 사이트만을 위해 Apache를 준비합니다. 압축을 푼 MK8DX 폴더에서 PowerShell을 엽니다. -XamppRoot를 실제 XAMPP 위치로 설정합니다:

powershell -ExecutionPolicy Bypass -File .\tooling\configure_xampp.ps1 -XamppRoot 'C:\xampp'

도우미는 먼저 apache\conf\httpd.conf를 %LOCALAPPDATA%\MK8DX\ApacheBackup에 저장합니다. “Include conf/extra/mk8dx-local.conf” 한 줄과 별도의 포트 18090만 추가한 다음 Apache 구문을 확인합니다. “Apache syntax OK”가 나와야 합니다. 포트 18090이 이미 사용 중이거나 설정이 다르면 중단하고 오류를 읽으세요. 다른 XAMPP 사이트를 지우지 마세요. XAMPP 위치가 다르면(공백이 있는 위치 포함) 이 명령에서 C:\xampp 부분만 바꾸세요.

5. Start-MK8DX-No-Docker.cmd를 두 번 클릭합니다. A3 방법을 고르고 나중에 관리자로 쓸 이메일 주소를 입력합니다. 창이 %LOCALAPPDATA%\MK8DX\NoDocker에 개인 설치 하나를 만듭니다. 첫 시작에서는 MariaDB 11.4.13을 그 폴더에만 압축 해제하고, 전용 데이터베이스와 제한된 사용자를 만들고, 마이그레이션과 Nintendo 스태프 및 세계 기록을 적용한 다음 Node.js와 Mailpit을 시작합니다. 몇 분 걸릴 수 있습니다. 이 MK8DX 창을 열어 두세요. 다시 시작해도 키, 계정, 결과, 데이터베이스는 유지됩니다.

이 창은 시작할 때마다 “Website:”(웹사이트)와 “Sign-in mail - a test inbox:”(로그인 메일 - 테스트 받은편지함)도 보여 줍니다. “Website”는 브라우저와 LiveTrial에서 쓰는 전체 주소입니다: http://127.0.0.1:18090. “Sign-in mail - a test inbox”는 로컬 테스트 받은편지함입니다: http://127.0.0.1:18227. Mailpit은 브라우저에서만 여세요. 콜론 뒤의 숫자가 포트입니다. “127.0.0.1”은 이 컴퓨터를 뜻하므로, 이 주소는 다른 기기에서는 작동하지 않습니다. 잊어버렸다면 다음에 시작할 때 같은 MK8DX 창의 위쪽을 보세요.

6. XAMPP Control Panel(XAMPP 제어판)을 엽니다. Apache가 이미 초록색이면 Apache의 Stop(중지)만 클릭하고, 그 줄이 더 이상 초록색이 아닐 때까지 기다린 다음 다시 Start(시작)를 클릭합니다. 이렇게 하면 4단계의 새 사이트 설정을 불러옵니다. Apache가 중지되어 있었다면 바로 Start를 클릭합니다. 브라우저에서 http://127.0.0.1:18090 을 엽니다. 로컬 테스트 받은편지함은 http://127.0.0.1:18227 입니다. 사이트에 접속할 수 없으면 먼저 MK8DX 창을 살펴보고, 그다음 Apache가 초록색인지 확인하세요. 패키지 폴더에서 연 두 번째 PowerShell 창에서 데이터베이스와 API를 확인합니다:

python tooling/install.py check-database --state-dir "$env:LOCALAPPDATA\MK8DX\NoDocker"
python tooling/install.py check --state-dir "$env:LOCALAPPDATA\MK8DX\NoDocker"

“MariaDB 11.4.13”과 “ready”(준비됨)가 나와야 합니다. 웹사이트, 스캐너, 데이터베이스, 테스트 받은편지함은 이 컴퓨터에만 연결되어 있습니다. 공유기 포트를 포워딩하거나 phpMyAdmin이나 테스트 받은편지함을 다른 사람에게 노출하지 마세요.

Apache가 초록색이 되지 않나요? 변경하지 않은 XAMPP Apache는 18090 외에 포트 80과 443도 쓰려고 합니다. 이 컴퓨터에서 A2 설치, IIS 또는 다른 웹 서버가 이미 그중 하나를 쓰고 있으면 Apache가 시작되지 않고, XAMPP Control Panel의 로그에 사용 중인 포트가 표시됩니다. 계획한 시간 동안 그 다른 프로그램을 멈추거나, A3는 다른 컴퓨터에서 쓰세요. 다른 웹사이트는 지우지 마세요.

7. 사이트에서 로그인을 클릭하고 5단계의 관리자 주소를 정확히 사용합니다. Mailpit에서 가장 최근 메시지를 열고 로그인 링크를 따라갑니다. 아직은 일반 사용자입니다. 이제 패키지 폴더의 Manage-MK8DX-No-Docker.cmd를 두 번 클릭하고(MK8DX 창은 열어 둠) 2를 입력한 뒤 Enter를 누릅니다. 뒤에서 실행되는 명령은 python tooling/install.py admin --state-dir "$env:LOCALAPPDATA\MK8DX\NoDocker" 입니다.

이메일 인증을 이미 마친 계정에만 작동합니다. “created”(생성됨), 반복하면 “unchanged”(변경 없음)가 나와야 합니다. 사이트를 새로 고치세요. 다른 첫 가입자가 자동으로 관리자가 되지는 않습니다.

8. 코스를 열고 Nintendo 스태프와 세계 기록을 합계까지 확인합니다. 시험용 타임 어택 기록을 하나 제출하고 같은 컴퓨터에서 /scanner/ 를 엽니다. 업로드 경로를 시험해 보려면 이미지를 선택하세요. 스캐너 결과는 검토가 필요할 수 있으며, 업로드했다고 자동으로 공개되지는 않습니다.

9. 매일 사용할 때는 MK8DX 창을 먼저 시작한 다음 XAMPP Control Panel에서 Apache를 시작합니다. 사이트를 쓰는 동안 MK8DX 창을 열어 두세요. Windows를 다시 시작한 뒤에는 이 두 가지를 다시 시작합니다. 제어판의 Stop(중지)으로 Apache를 멈춘 다음 MK8DX 창에서 Ctrl+C를 누릅니다. 이 설치의 Node, Mailpit, MariaDB 프로세스만 멈춥니다. 모든 node.exe 프로세스를 강제 종료하거나 기존 XAMPP 서비스를 바꾸지 마세요.

10. 백업할 때는 MK8DX 창과 그 데이터베이스를 실행 중인 상태로 둡니다. 마지막 복사 중에 새 웹 제출을 막으려면 Apache를 잠깐 멈춰도 됩니다. Manage-MK8DX-No-Docker.cmd를 두 번 클릭하고 3을 입력한 뒤 Enter를 누릅니다. 백업을 Documents\MK8DX-backups\a3-<date and time>에 쓰고 바로 확인합니다.

“Backup verified”(백업 검증됨)는 데이터베이스 사본, 프로필, 키를 확인했다는 뜻입니다. 폴더 전체를 이 컴퓨터 밖의 보호된 저장소에도 보관하세요. 바로 이 백업을 다시 확인하려면 다음을 실행합니다:

python tooling/install.py verify-backup --state-dir "$env:LOCALAPPDATA\MK8DX\NoDocker" --backup-output "$env:USERPROFILE\Documents\MK8DX-backups\a3-2026-10-01"

11. 소프트웨어를 업데이트할 때는 Apache를 멈추고, 이전 MK8DX 창이 아직 실행 중일 때 백업을 만들어 검증합니다. 그다음 그 창에서 Ctrl+C를 누릅니다. 새 A3 ZIP을 확인하고 이전 패키지 옆에 압축을 풉니다. 같은 %LOCALAPPDATA%\MK8DX\NoDocker 데이터 폴더를 계속 씁니다. 새 패키지 안의 PowerShell에서 임시로 그 패키지 자체의 데이터베이스만 시작합니다:

python tooling/install.py maintenance --state-dir "$env:LOCALAPPDATA\MK8DX\NoDocker"

그 창을 열어 둡니다. 새 패키지에서 두 번째 PowerShell 창을 열고, 다른 새 백업 폴더를 지정해 업데이트합니다:

python tooling/install.py upgrade --state-dir "$env:LOCALAPPDATA\MK8DX\NoDocker" --backup-output "$env:USERPROFILE\Documents\MK8DX-backups\a3-update-2026-10-01"

두 기준 데이터 세트 모두 “unchanged”(변경 없음)와 “Backup verified”(백업 검증됨)가 나올 때까지 기다립니다. 유지 보수 창에서 Ctrl+C를 누릅니다. 새 패키지의 Start-MK8DX-No-Docker.cmd와 Apache를 다시 시작합니다. 도우미는 계정, 키, 데이터를 초기화하지 않고 패키지에서 파생된 경로만 새로 고칩니다. 같은 로그인, 기준 기록, 시험 결과를 확인하세요. 데이터베이스 엔진 변경을 일반적인 MK8DX 업데이트로 취급하지 마세요.

12. 다른 Windows 컴퓨터에서 복원을 시험하려면, 1단계와 2단계처럼 그곳에 XAMPP Apache, Node 24, Python을 설치합니다. 같은 A3 패키지의 압축을 풀고 4단계처럼 configure_xampp.ps1로 Apache를 설정합니다. 검증된 백업 폴더 전체를 비공개로 Documents\MK8DX-backups에 복사합니다. 그 컴퓨터에 있는 기존 데이터 폴더는 쓰지 마세요. 새 패키지에서 PowerShell을 열고 새 프로필만 만듭니다:

python tooling/install.py wizard --state-dir "$env:LOCALAPPDATA\MK8DX\NoDocker"

A3을 고르고 일단 내 관리자 주소를 입력합니다. 복원하면 원래 계정 프로필이 되돌아옵니다. 같은 패키지에서 두 번째 PowerShell을 엽니다. 첫 번째 창에서는 새로 만든 빈 MariaDB만 시작합니다:

python tooling/install.py maintenance --state-dir "$env:LOCALAPPDATA\MK8DX\NoDocker"

이 창을 열어 둡니다. 두 번째 창에서는 꺾쇠괄호 없이 실제 백업 폴더 이름을 씁니다:

python tooling/install.py restore-local --backup-input "$env:USERPROFILE\Documents\MK8DX-backups\a3-2026-10-01" --state-dir "$env:LOCALAPPDATA\MK8DX\NoDocker"

“Backup verified”(백업 검증됨)와 그다음 모든 마이그레이션의 확인 통과가 나와야 합니다. 유지 보수 창에서 Ctrl+C를 누릅니다. Start-MK8DX-No-Docker.cmd를 열고 XAMPP Control Panel에서 Apache를 시작합니다. 백업에 있는 기존 계정으로 로그인하고 관리자 권한과 알고 있는 결과를 확인합니다. 첫 관리자는 다시 부여되지 않습니다. 대상 컴퓨터에 이미 MK8DX 설치가 있거나 포트 18306을 쓰는 다른 프로세스가 있으면 그 컴퓨터를 복원 대상으로 쓰지 마세요. 도우미는 기존 데이터베이스를 지우지 않습니다. 원래 백업은 손대지 말고 보관하세요.

홈 네트워크에서 사용하기

집이나 클럽 네트워크에는 A2 패키지를 쓰세요. mk8dx-a2-windows-amd64-v0.2.3.zip(Linux: mk8dx-a2-linux-amd64 또는 mk8dx-a2-linux-arm64, Apple 실리콘 macOS: mk8dx-a2-macos-arm64, Intel 프로세서 macOS: mk8dx-a2-macos-amd64)과 SHA256SUMS.txt를 다운로드하고, “컴퓨터 한 대에서 시험해 보기”처럼 체크섬을 확인한 다음, 패키지의 압축을 풀고 Start-MK8DX-LAN.cmd를 두 번 클릭합니다(Linux와 macOS: sh tooling/start-mk8dx.sh). 브라우저에서 설치 화면이 열리고 Next(다음)로 모든 과정을 안내합니다: 네트워크 주소, 내 관리자 계정, 매일 밤 백업을 위한 종이 복구 코드, 각자의 휴대폰이나 PC용 로그인 카드가 있는 사람들. 인터넷, 메일 서버, hosts 파일은 필요 없습니다.

그림이 들어 있는 전체 단계별 안내서는 docs/install/A2_HOME_GUIDE_EN.md이며, 패키지 안에서는 docs/install/guide/en.html이기도 하고, 설치 화면의 Manual(설명서) 링크로 열립니다. Windows, Linux 또는 macOS 준비, 휴대폰과 PC, Android 앱, LiveTrial, 토너먼트 밤, 백업, 새 컴퓨터로 옮기기, 고정 주소, 새 네트워크 주소, 업데이트를 다룹니다.

고급: 자체 메일 서버 사용

이 장의 나머지 부분은 사설 호스트 이름과 자체 메일 서버를 통한 이메일 로그인 링크를 쓰는, 오래된 고급 방식을 설명합니다. 대부분의 사람에게는 필요 없습니다. mk8dx-host-local 패키지와 그 설정 질문의 A2 선택지를 씁니다.

이 방법은 Windows 호스트에 두 번째, 별도의 MK8DX 설치를 만듭니다. 컴퓨터 한 대에서 한 시험은 그대로 유지됩니다. 문서화된 첫 번째 클라이언트 방법은 Chrome이나 Edge를 쓰는 두 번째 Windows PC이며, 스캐너 이미지 업로드도 포함합니다. 실제 두 번째 PC나 휴대폰으로는 아직 실사용자 인수 테스트를 하지 않았습니다. 일반 Android 앱은 로컬 인증서를 자동으로 신뢰하지 않습니다. 앱에는 공유 호스팅이나 VPS의 공개 HTTPS 커뮤니티 주소를 쓰세요.

네트워크 웹사이트는 호스트의 포트 443을 씁니다. 같은 컴퓨터에서 XAMPP Apache가 실행 중이면 이미 그 포트를 쓰고 있을 수 있습니다. 그러면 A2와 그 Apache 사이트는 이 호스트에서 동시에 시작할 수 없습니다. A2에는 다른 Windows 호스트를 쓰거나, 계획한 시간 동안 XAMPP Control Panel에서 Apache를 멈추세요. 멈춰 있는 동안 다른 XAMPP 웹사이트는 사용할 수 없습니다.

먼저 “컴퓨터 한 대에서 시험해 보기”의 처음 세 단계처럼 호스트에 Docker Desktop, Python, 확인하고 압축을 푼 호스트 패키지를 준비합니다. A1 설치를 만들 필요는 없습니다. 두 PC는 같은 신뢰할 수 있는 사설 네트워크에 있어야 합니다. 게스트 Wi-Fi를 쓰거나 공유기 포트를 인터넷으로 포워딩하지 마세요. 호스트가 절전 상태로 들어가지 않게 하세요.

1. 호스트에서 Settings → Network & internet → Ethernet 또는 Wi-Fi → Properties(설정 → 네트워크 및 인터넷 → 이더넷 또는 Wi-Fi → 속성)에서 IPv4 주소를 찾습니다. 이 안내서에서 192.168.0.50은 예일 뿐입니다. 실제 주소를 적어 두세요. 정말 신뢰할 수 있는 네트워크일 때만 Windows 네트워크 프로필을 Private(개인)로 설정하세요. 나중에 주소가 바뀌면 두 PC 모두 업데이트하세요. 공유기의 DHCP 예약으로 변경을 막을 수 있습니다.

2. 두 Windows PC에서 같은 사설 이름을 씁니다. “Run as administrator”(관리자 권한으로 실행)로 메모장을 시작합니다. File → Open(파일 → 열기)을 고르고 이 폴더로 간 다음, 필터를 “All Files”(모든 파일)로 바꿉니다:

C:\Windows\System32\drivers\etc\

hosts를 엽니다. 실제 호스트 IP와 사설 이름이 있는 줄을 하나 추가합니다. 예:

192.168.0.50 mk8dx.home.arpa

.txt 없이 hosts라는 이름으로 저장합니다. 호스트와 두 번째 PC에서 똑같이 합니다. 두 컴퓨터의 PowerShell에서 확인합니다:

ping -n 1 mk8dx.home.arpa

ping 결과 앞에 호스트 IP가 나와야 합니다. 방화벽이 ping 자체를 막을 수 있습니다. 이 사설 이름에는 공개 DNS 레코드가 없으므로 기기마다 자체 hosts 항목이 필요합니다.

3. 다른 사용자를 위한 로그인 링크에는 실제 이메일 서비스가 필요합니다. 메일 제공 업체에서 발신 SMTP 서버 이름, 암시적 TLS를 쓰는 포트 465, 로그인, 비밀번호, 승인된 발신자 주소를 받으세요. 포트 587의 STARTTLS만 제공하는 서비스는 현재 마법사에 맞지 않습니다. 앞으로 쓸 MK8DX 관리자 주소는 별개의 값입니다. Mailpit을 공유 로그인 받은편지함으로 쓰지 마세요.

4. 호스트에서 Start-MK8DX-LAN.cmd를 두 번 클릭합니다. A2를 고르고 mk8dx.home.arpa를 확인하거나, hosts 파일에 쓴 이름을 정확히 입력합니다. 호스트의 실제 IPv4 주소는 따로 입력합니다. 그러면 마법사가 메일 값과 앞으로 쓸 내 관리자 주소를 묻습니다. 메일 비밀번호는 입력할 때 숨겨집니다. 첫 설정이 저절로 시작됩니다. 별도의 데이터 폴더는 %LOCALAPPDATA%\MK8DX\LAN입니다. 표시되는 웹사이트 주소는 https://mk8dx.home.arpa 여야 합니다.

호스트와 두 번째 PC의 LiveTrial에서도 이 HTTPS 주소를 쓰세요. 이름 뒤에 표준 포트 443을 쓸 필요는 없습니다. 찾은 IPv4 주소는 hosts 항목과 네트워크 설정에 쓰고, LiveTrial의 커뮤니티 주소로는 쓰지 마세요. 이 네트워크 방법은 실제 메일 제공 업체를 씁니다: 로그인 메일은 입력한 주소의 일반 받은편지함으로 도착합니다. 여기서는 사용자에게 로컬 Mailpit 주소가 없습니다.

5. 호스트에서 Windows Security → Firewall & network protection → Advanced settings → Inbound Rules → New Rule(Windows 보안 → 방화벽 및 네트워크 보호 → 고급 설정 → 인바운드 규칙 → 새 규칙)을 엽니다. Port(포트), TCP, 특정 로컬 포트 443, “Allow the connection”(연결 허용), Private(개인) 프로필만 고릅니다. 규칙 이름을 정합니다. 예: “MK8DX LAN HTTPS”. Scope(범위)에서, 내 네트워크의 서브넷을 안다면 원격 주소를 내 네트워크로 제한하세요. 데이터베이스나 Mailpit을 공용 네트워크에 열지 마세요.

6. 두 번째 Windows PC는 바로 이 설치의 로컬 인증서를 신뢰해야 합니다. 내가 관리하는 컴퓨터에서만 하세요. 호스트에서 압축을 푼 패키지 폴더의 PowerShell을 열고 다음 세 줄을 한 줄씩 실행합니다:

$state = Join-Path $env:LOCALAPPDATA 'MK8DX\LAN'
$compose = @('--env-file', (Join-Path $state 'compose.env'), '-f', 'compose.yaml', '-f', 'compose.lan.yaml', '-f', 'compose.images.yaml')
docker compose @compose cp web:/data/caddy/pki/authorities/local/root.crt (Join-Path $env:USERPROFILE 'Downloads\mk8dx-lan-root.crt')

호스트에서 인증서 지문을 확인합니다:

Get-FileHash (Join-Path $env:USERPROFILE 'Downloads\mk8dx-lan-root.crt') -Algorithm SHA256

신뢰할 수 있는 방법으로 mk8dx-lan-root.crt만 두 번째 PC로 옮깁니다. 지문은 따로 기록해 두세요. root.key, Caddy 폴더 전체, MK8DX 비밀 정보는 절대 복사하지 마세요. 두 번째 PC에서는 다운로드 폴더의 파일을 확인합니다:

Get-FileHash '.\mk8dx-lan-root.crt' -Algorithm SHA256

값이 정확히 일치하면 인증서를 두 번 클릭합니다. Install Certificate → Current User → Place all certificates in the following store → Browse → Trusted Root Certification Authorities → Finish(인증서 설치 → 현재 사용자 → 모든 인증서를 다음 저장소에 저장 → 찾아보기 → 신뢰할 수 있는 루트 인증 기관 → 마침)를 고릅니다. 브라우저를 다시 시작합니다. 지문이 다른 인증서는 설치하지 마세요. 브라우저 경고를 우회하지 마세요.

7. 두 번째 PC에서 https://mk8dx.home.arpa 를 엽니다. 인증서 경고가 없어야 합니다. 내 테스트 이미지로 https://mk8dx.home.arpa/scanner/ 도 시험해 보세요. 내 주소로 로그인하고 실제 받은편지함의 링크를 따라갑니다. 그렇게 로그인한 뒤 호스트에서 Start-MK8DX-LAN.cmd를 다시 열고 메뉴 5를 골라, 저장된 주소에 관리자 권한을 한 번 부여할 수 있습니다. A1의 사용자와 관리자는 A2로 자동으로 넘어오지 않습니다.

나중에 호스트 IP가 바뀌면 먼저 두 PC의 hosts를 업데이트합니다. 호스트의 패키지 폴더에서 PowerShell을 열고, 아래의 예시 IP를 새 실제 주소로 바꿉니다:

python tooling/install.py change-lan-address --state-dir (Join-Path $env:LOCALAPPDATA 'MK8DX\LAN') --lan-bind-address '192.168.0.51'
python tooling/install.py apply --state-dir (Join-Path $env:LOCALAPPDATA 'MK8DX\LAN')

주소, 웹사이트, 로그인 메일을 다시 확인하세요. 같은 A2 설치인 동안에는 두 번째 PC가 계속 인증서를 신뢰합니다. 새 프로젝트로 복원하면 새 로컬 인증 기관이 만들어집니다. “백업 복원하기”를 참고하세요.

Docker 없이 Node.js로 공개 공유 호스팅

이 방법은 mijn.host Starter 같은 공유 호스팅이 제공하는 Passenger와 MariaDB가 있는 Node.js를 씁니다. VPS, Docker, root 권한, 자체 Caddy 서버가 필요 없습니다. 패키지는 로컬 Linux와 MariaDB 환경에서 테스트되었습니다. 내 DirectAdmin 계정과 실제 메일 전송에서는 직접 단계를 확인해야 합니다. 별도의 (서브)도메인과 빈 데이터베이스를 쓰세요. 기존 웹사이트나 데이터베이스를 바꾸지 마세요. Starter는 현재 RAM 2 GB와 저장 공간 5 GB로 안내되어 있습니다. 업로드, npm 의존성, 데이터, 백업을 위한 공간이 충분한지 내 패널에서 확인하세요.

1. 환영합니다 장에 나온 릴리스 페이지에서 mk8dx-mijnhost-node-v0.2.3.zip과 SHA256SUMS.txt를 다운로드합니다. 이 ZIP이 업로드 패키지입니다. Docker 호스트 ZIP과 전체 소스 ZIP은 다른 파일입니다. 두 파일을 Windows PC의 한 폴더에 둡니다. 그곳에서 PowerShell을 열고 SHA-256 값 전체를 SHA256SUMS.txt의 줄과 비교합니다:

Get-FileHash '.\mk8dx-mijnhost-node-v0.2.3.zip' -Algorithm SHA256

값이 다르면 중단하세요.

2. PC에서 mijn.host 고객 패널에 로그인합니다. 호스팅 요금제를 열고 DirectAdmin을 엽니다. 오른쪽 위에서 이 새 MK8DX 사이트용 도메인이나 서브도메인을 선택합니다. www.mijneigenwebsite.nl은 예일 뿐이니 실제 호스트 이름을 쓰세요. Account Manager → SSL Certificates(계정 관리자 → SSL 인증서)에서 “Get automatic certificate from ACME Provider”(ACME 제공자에게서 자동 인증서 받기)에 정확히 그 이름이 포함되어 있는지 확인합니다. 나중에 브라우저에 인증서 경고가 없어야 합니다. DNS를 다른 곳에서 관리한다면 먼저 그 호스트 이름이 이 호스팅 요금제를 가리키게 하세요. 웹사이트 때문에 기존 메일 레코드를 바꾸지 마세요.

DirectAdmin Node.js guide: https://mijn.host/kb/web-apps/node-js-applicatie-draaien-op-je-hostingpakket
Let's Encrypt in DirectAdmin: https://mijn.host/kb/webhosting/lets-encrypt-ssl-certificaat-aanvragen

3. DirectAdmin의 Account Manager → MySQL Management 또는 Databases(계정 관리자 → MySQL 관리 또는 데이터베이스)에서 새 빈 데이터베이스와 그 데이터베이스로만 제한된 사용자를 만듭니다. 패널에 표시되는 전체 이름을 계정 접두사까지 포함해 적어 두세요. 예: account_mk8dx와 account_mk8dxuser. 생성된 비밀번호는 비공개로 보관하세요. root 계정은 쓰지 마세요. 데이터베이스 호스트는 패널이나 계정 세부 정보에서 찾습니다. localhost일 수도 있지만, 표시된 실제 값만 입력하세요. 포트 3306은 일반적인 예입니다. MK8DX는 마이그레이션 전에 실제 엔진과 버전을 확인합니다. 이 릴리스에는 MariaDB 11.4 이상 또는 MySQL 8.4 이상이 필요합니다. 패널에 “MySQL”이라고 적혀 있다고 해서 버전이 증명되는 것은 아닙니다.

4. DirectAdmin → E-mail Manager → E-mail Accounts(이메일 관리자 → 이메일 계정)를 엽니다. 이 사이트에 써도 되는 메일함을 만들거나 고릅니다. 전체 주소, 비밀번호, 발신 서버 이름을 적어 두세요. 흔한 형식은 SSL/TLS를 쓰는 포트 465의 mail.mijneigenwebsite.nl이지만, 실제 서버 이름은 내 계정에서 확인하세요. SMTP 로그인, 보이는 발신자, 앞으로 쓸 MK8DX 관리자 주소는 각각 용도가 다릅니다. 계정에서 발신을 허용한다면 포함된 메일함으로 충분합니다.

Mail settings at mijn.host: https://mijn.host/kb/email/e-mail-account-instellen-in-gmail

5. DirectAdmin에서 Extra Features → Setup Node.js App → Create Application(추가 기능 → Node.js 앱 설정 → 애플리케이션 만들기)을 엽니다. 패널에서 제공한다면 Node.js 24를 선택합니다. 최종 사이트에는 Production(운영)을 고르고, Application root(애플리케이션 루트)는 public_html 밖의 apps/mk8dx, Application URL(애플리케이션 URL)은 선택한 도메인의 루트, Application startup file(애플리케이션 시작 파일)은 api/dist/composition/passenger-hosted-main.js로 합니다. 패널이 처음에는 기본 app.js를 보여 줄 수 있습니다. MK8DX를 다시 시작하기 전에 시작 설정을 지정한 파일로 바꾸세요. 패널 위쪽에 표시된 Node 환경 활성화 줄을 그대로 복사합니다. Node 24나 시작 설정을 쓸 수 없으면 오래된 Node 버전으로 추측해서 하지 마세요. 그것은 계정별로 확인해야 할 사항입니다.

6. mijn.host 패널에서 내 서버 이름과 SSH 사용자 이름을 찾습니다. Windows PC에서 PowerShell을 열고 문서화된 SSH 포트 26으로 연결합니다. 받아들이기 전에 SSH 호스트 키 지문을 mijn.host가 따로 제공한 값과 비교하세요. B2는 SSH를 제공하는 모든 공유 Node.js 호스트에서 작동합니다. mijn.host는 테스트된 예이며, 포트 26은 그 업체의 SSH 포트이므로 다른 곳에서는 내 호스트의 포트(흔히 22)를 쓰세요. 패키지 이름은 그대로 mk8dx-mijnhost-node입니다. 꺾쇠괄호 예시를 괄호를 빼고 내 값으로 바꿉니다:

ssh -p 26 <your-username>@<your-server-name>

Linux 프롬프트가 나와야 합니다. 계정 비밀번호는 비밀번호 관리자에 보관하세요. 이것은 VPS root 권한이 아닙니다. 같은 SSH 경로로 확인한 ZIP을 전송합니다. PC의 다운로드 폴더에서 두 번째 PowerShell 창을 엽니다:

scp -P 26 '.\mk8dx-mijnhost-node-v0.2.3.zip' <your-username>@<your-server-name>:

ZIP은 내 호스팅 홈 디렉터리에 나타납니다. 별도의 SFTP 옵션은 설정이 다를 수 있습니다. 이 방법은 문서화된 SSH/SCP 접근만 씁니다.

SSH at mijn.host: https://mijn.host/kb/webhosting/verbinden-met-ssh

7. SSH 창으로 돌아갑니다. Python 3.9 이상, unzip, MariaDB 덤프 클라이언트가 있는지 확인합니다. 애플리케이션은 이미 빌드되어 있으며, Python은 기존 설치 도우미만 실행합니다:

python3 --version
command -v unzip
command -v mariadb-dump || command -v mysqldump

명령이 없으면 바로 그 없는 도구를 호스팅 패널이나 mijn.host 도움말과 비교해 보세요. 보호되지 않은 공개 설정 URL을 만들지 마세요. ZIP을 public_html이 아니라 개인 애플리케이션 폴더에 압축 해제합니다:

mkdir -p "$HOME/apps/mk8dx"
unzip "$HOME/mk8dx-mijnhost-node-v0.2.3.zip" -d "$HOME/apps/mk8dx"
cd "$HOME/apps/mk8dx"

api, web, scanner, assets, mysql, tooling이 보여야 합니다. 애플리케이션 폴더는 비공개입니다. 설치 프로그램은 프로필, 비밀 정보, 백업도 public_html 밖에 보관합니다.

8. 그 SSH 창에 Setup Node.js App 패널에 표시된 Node 활성화 줄을 그대로 붙여 넣습니다. 대개 source로 시작해서 Application root로 이동하는 cd로 끝납니다. 그다음 실행합니다:

node --version
cd "$HOME/apps/mk8dx/api"
npm ci --omit=dev --ignore-scripts --no-audit --no-fund
cd "$HOME/apps/mk8dx"

Node 24와, 잠긴 운영용 의존성의 설치 완료가 나와야 합니다. 이 과정은 TypeScript를 컴파일하지 않습니다. api/node_modules는 내 Linux 호스트에 속합니다. Windows의 node_modules를 업로드하지 마세요. 저장 공간이 부족하면 다른 계정 데이터를 지우지 말고 중단한 뒤 여유 공간을 확인하세요.

9. 애플리케이션 폴더에서 안내형 입력을 시작합니다:

python3 tooling/install.py wizard --state-dir "$HOME/mk8dx-private"

B2를 고릅니다. https:// 없이 정확한 HTTPS 웹사이트 호스트 이름을 입력하고, 그다음 3단계의 데이터베이스 호스트, 포트, 전체 데이터베이스 이름과 사용자 이름, 숨겨진 데이터베이스 비밀번호를 입력합니다. 4단계의 SMTP 호스트, 포트 465, 전체 메일함 로그인, 숨겨진 메일함 비밀번호, 허용된 발신자를 입력합니다. 관리자 주소에는 로그인 링크를 받을 개인 이메일 주소를 입력합니다. SMTP 로그인과 달라도 됩니다. 도우미는 $HOME/mk8dx-private 아래에 operator-profile.json, secrets.json, operator.json을 제한된 권한으로 씁니다. 같은 값을 다른 .env 파일에 다시 쓰지 마세요.

10. 데이터베이스 버전을 확인한 다음, 모든 마이그레이션과 두 기준 데이터 세트를 내가 새로 만든 빈 데이터베이스에만 적용합니다:

python3 tooling/install.py check-database --state-dir "$HOME/mk8dx-private"
python3 tooling/install.py setup --state-dir "$HOME/mk8dx-private"
python3 tooling/install.py check --state-dir "$HOME/mk8dx-private"

첫 줄은 측정된 MariaDB 또는 MySQL 버전과 tableCount 0을 보여 줘야 합니다. 엔진이 너무 오래되었거나 데이터베이스에 예상치 못한 테이블이 있으면 중단하세요. setup 후에는 모든 마이그레이션이 적용되고, Nintendo 스태프와 세계 기록이 applied(적용됨)로 표시되고, 그다음 ready(준비됨)가 나와야 합니다. 설치 프로그램은 알 수 없는, 이미 데이터가 있는 스키마를 절대 초기화하지 않습니다.

11. Passenger 설정을 생성하고 패널에서 시작합니다:

python3 tooling/install.py passenger-config --state-dir "$HOME/mk8dx-private"

이 명령은 public_html 밖의 개인 Application root에 mk8dx-hosted.env.json을 만듭니다. 그 폴더나 $HOME/mk8dx-private를 공개 파일 디렉터리로 절대 옮기지 마세요. DirectAdmin → Extra Features → Setup Node.js App에서 MK8DX 앱을 선택하고 Restart(다시 시작)를 클릭합니다. 프로세스와 HTTPS는 업체가 관리하므로, 추가로 nohup이나 PM2 서버를 실행하지 마세요. 내 실제 호스트 이름으로 /health/ready, 홈페이지, /scanner/, /client-config.json, /.well-known/assetlinks.json을 확인합니다. 알 수 없는 JSON이나 API URL이 HTML 홈페이지를 반환하면 안 됩니다. /secrets.json, /.env, 백업에 대한 요청은 아무 내용도 드러내지 않아야 합니다.

12. 사이트에서 로그인을 클릭하고 9단계의 관리자 주소를 씁니다. 실제 받은편지함의 링크를 열고 로그인합니다. 그다음에야 SSH로 돌아가, 필요하면 패널의 Node 환경을 다시 활성화하고, 애플리케이션 폴더로 가서 실행합니다:

cd "$HOME/apps/mk8dx"
python3 tooling/install.py admin --state-dir "$HOME/mk8dx-private"

created(생성됨), 반복하면 unchanged(변경 없음)가 나와야 합니다. 웹사이트를 새로 고치세요. 첫 가입만으로는 절대 관리 권한이 주어지지 않습니다. 코스, Nintendo 스태프와 세계 기록 합계, 내 타임 어택 기록, 스캐너 업로드를 확인하세요. 실제 로그인 메일이 오지 않으면 메일함 로그인, 발신자, TLS를 확인하세요. ready는 외부 받은편지함으로의 전달을 증명하지 않습니다.

13. 백업할 때는 DirectAdmin에서 이 Node 앱의 Stop(중지) 버튼으로 방문자 트래픽을 잠깐 멈춥니다. MariaDB 데이터베이스는 계속 사용할 수 있습니다. SSH의 애플리케이션 폴더에서 새 개인 폴더 이름을 정합니다:

python3 tooling/install.py backup --state-dir "$HOME/mk8dx-private" --backup-output "$HOME/mk8dx-backups/b2-2026-10-01"

도우미가 Backup verified(백업 검증됨)를 알립니다. 이 호스팅 계정 밖에도 보호된 사본을 보관하세요. DirectAdmin에서 Node 앱을 다시 시작하고 ready를 확인합니다. 백업에는 계정, 관리자 권한, 키가 들어 있습니다. public_html이나 공개 링크에 절대 올리지 마세요.

14. 업데이트할 때는 PC에서 새 B2 ZIP을 확인합니다. DirectAdmin에서 Node 앱을 멈추고 이전 애플리케이션으로 검증된 백업을 만듭니다. 같은 SSH/SCP 경로로 새 ZIP을 업로드합니다. SSH에서 이전 애플리케이션 폴더의 이름을 바꾼 다음 새 빈 폴더를 만듭니다. 새 ZIP이 홈 폴더에 있고 mk8dx-before-update 폴더가 아직 없을 때만 다음 명령을 쓰세요:

cd "$HOME"
mv "$HOME/apps/mk8dx" "$HOME/apps/mk8dx-before-update"
mkdir -p "$HOME/apps/mk8dx"
unzip "$HOME/mk8dx-mijnhost-node-v0.2.3.zip" -d "$HOME/apps/mk8dx"

DirectAdmin의 Node 24 활성화 줄을 다시 붙여 넣습니다. 새 api 폴더에 잠긴 Linux 의존성을 설치하고 애플리케이션 루트로 돌아갑니다:

cd "$HOME/apps/mk8dx/api"
npm ci --omit=dev --ignore-scripts --no-audit --no-fund
cd "$HOME/apps/mk8dx"

같은 개인 데이터 폴더를 유지합니다. 다른 새 백업 폴더를 씁니다:

python3 tooling/install.py upgrade --state-dir "$HOME/mk8dx-private" --backup-output "$HOME/mk8dx-backups/b2-update-2026-10-01"
python3 tooling/install.py passenger-config --state-dir "$HOME/mk8dx-private"

그다음 DirectAdmin에서 이 앱만 다시 시작합니다. 웹사이트, 로그인, 관리, 알고 있는 결과를 확인하세요. 스키마 마이그레이션 후에 이전 웹 파일만 무작정 되돌리지 마세요. MariaDB 버전 변경은 일반적인 MK8DX 업데이트가 아닙니다.

15. 복구에는 테스트된 것과 같은 데이터베이스 엔진과 버전 계열의 새 빈 데이터베이스와 별도의 테스트 서브도메인을 씁니다. 확인한 B2 패키지와 전체 개인 백업을 그 별도 설치에 둡니다. DirectAdmin에서 복원 시험용으로 Application root는 apps/mk8dx-restore, Application URL은 테스트 서브도메인인 별도의 Node 앱을 만듭니다. B2 ZIP을 그 새 개인 폴더에 압축 해제합니다. 이 새 앱 화면의 줄로 Node 24를 활성화하고, apps/mk8dx-restore/api 안에서 npm ci --omit=dev --ignore-scripts --no-audit --no-fund 를 실행한 다음 apps/mk8dx-restore로 갑니다. 안내형 복원은 비밀번호를 표시하지 않고 새 데이터베이스 정보를 묻고, 이전 계정과 키를 다시 씁니다:

python3 tooling/install.py restore-wizard --backup-input "$HOME/mk8dx-backups/b2-2026-10-01" --state-dir "$HOME/mk8dx-private-restore"
python3 tooling/install.py passenger-config --state-dir "$HOME/mk8dx-private-restore"

DirectAdmin에서 이 별도의 Passenger 앱을 테스트 서브도메인과 개인 Application root에 연결합니다. 시작하고 ready, 기존 로그인, 관리, 결과를 확인하세요. 또 다른 첫 관리자를 만들지 마세요. 실제 도메인 전환과 업체 백업은 직접 하는 별도의 단계입니다.

VPS에 공개 웹사이트 만들기

VPS는 인터넷에 있는 나만의 컴퓨터입니다. 이 방법은 x86-64의 Ubuntu 24.04 LTS를 씁니다. 권장 사양은 CPU 코어 2개, RAM 8 GB, SSD 40 GB에 더해 나중의 데이터와 백업을 위한 공간입니다. Mijn.host unmanaged VPS M은 VPS 페이지에 이 사양과 root/SSH를 안내하고 있지만, MK8DX는 바로 그 요금제에서 테스트되지 않았습니다. Ubuntu, Docker, 메일, 보안 업데이트, 백업은 내 책임입니다.

Mijn.host VPS overview: https://mijn.host/vps

Mijn.host Starter는 위의 별도 Node/Passenger 방법을 씁니다. 이 VPS 장은 Docker를 쓰며 일반 Starter 요금제에는 해당하지 않습니다.

Mijn.host shared hosting overview: https://mijn.host/webhosting

첫 설정 전에 내 도메인, IPv4와 Ubuntu가 있는 적당한 VPS 계정, DNS 관리 권한, 암시적 TLS를 쓰는 SMTP 465 메일 서비스가 필요합니다. 예시 www.mijneigenwebsite.nl은 모든 곳에서 내 호스트 이름으로 바꾸세요. 예시 IP 203.0.113.10은 실제 서버가 아닙니다. 업체 로그인, SSH 키, MK8DX 관리자 주소, SMTP 로그인은 각각 용도가 다릅니다. 비밀번호와 키는 비공개로 보관하세요.

1. VPS가 SSH 키를 쓴다면 Windows PC에서 접근 키를 만듭니다. PowerShell을 열고 실행합니다:

New-Item -ItemType Directory -Force (Join-Path $env:USERPROFILE '.ssh')
ssh-keygen -t ed25519 -f (Join-Path $env:USERPROFILE '.ssh\mk8dx_vps_ed25519')

물어보면 강력한 암호 문구를 고르세요. .pub이 없는 파일이 개인 키입니다. .pub 파일을 메모장으로 열고, 그 공개 키만 VPS 관리 포털의 SSH 키 기능에 추가합니다. 정확한 버튼은 업체마다 다릅니다. 찾을 수 없으면 업체에 위치를 물어보세요. 개인 키를 웹 폴더나 서버에 절대 두지 마세요.

2. 공식 웹사이트에서 WinSCP를 설치합니다. WinSCP → New Site(새 사이트)를 엽니다. SFTP를 고릅니다. Host name(호스트 이름)에 실제 VPS IP를, Port number(포트 번호)에 실제 SSH 포트를, User name(사용자 이름)에 VPS 계정을 입력합니다. 설명한 root 방법에는 업체가 root를 제공할 때만 root를 쓰세요. 키 로그인에는 Advanced → SSH → Authentication → Private key file(고급 → SSH → 인증 → 개인 키 파일)을 열고 1단계의 개인 키를 선택합니다. WinSCP가 OpenSSH 키를 .ppk 파일로 변환하겠다고 제안합니다. 개인 키 옆에 저장하고 WinSCP에서 그것을 쓰세요. 암호 문구는 여전히 필요합니다.

WinSCP: https://winscp.net/eng/download.php
WinSCP key formats: https://winscp.net/eng/docs/ui_login_authentication

업체의 독립적인 VPS 콘솔이나 지원팀을 통해 SSH 호스트 키 지문을 받으세요. WinSCP의 첫 연결 메시지와 비교합니다. 정확히 일치할 때만 받아들이세요. 확인한 mk8dx-host-local-v0.2.3-amd64.zip을 왼쪽(내 PC)에서 오른쪽(서버)의 /root/로 끌어다 놓습니다. 백업이나 비밀 정보를 public_html에 올리지 마세요.

3. 서버 터미널로 쓰기 위해 PC에서 PowerShell을 엽니다. 실제 IP, 포트, 키 경로를 씁니다. 이것은 변환한 .ppk 파일이 아니라 1단계의 같은 OpenSSH 키입니다:

$serverIp = '203.0.113.10'
$sshPort = 22
$key = Join-Path $env:USERPROFILE '.ssh\mk8dx_vps_ed25519'
ssh -i $key -p $sshPort "root@$serverIp"

여기서도 호스트 키 지문을 독립적으로 받은 값과 비교하세요. 그다음에만 키 암호 문구를 입력합니다. 업체가 다른 VPS 사용자나 SSH 포트를 지정한다면 root나 22를 바꾸세요. 공유 호스팅의 포트는 VPS 설정이 아닙니다.

Ubuntu 터미널에서 컴퓨터를 확인합니다:

cat /etc/os-release
uname -m
free -h
df -h /
python3 --version

Ubuntu 24.04, x86_64, Python 3.12~3.15가 나와야 합니다. 새 Ubuntu 24.04 서버에 Python이 없으면 실행합니다:

apt update
apt install python3
python3 --version

컴퓨터가 Linux x86-64가 아니면 진행하지 마세요. 제공된 이미지 패키지는 amd64입니다.

4. Docker가 이미 작동하는지 확인합니다:

command -v docker
docker compose version

없으면 이 서버에서 Docker의 공식 Ubuntu apt 방법을 씁니다. 각 묶음을 같은 서버 터미널에서 실행하고, 명령이 실패하면 중단하세요:

Docker for Ubuntu: https://docs.docker.com/engine/install/ubuntu/

apt update
apt install ca-certificates curl unzip
install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
chmod a+r /etc/apt/keyrings/docker.asc

공식 패키지 소스를 추가합니다. 마지막 EOF까지 포함해 이 줄들을 함께 복사하세요:

cat > /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
apt update
apt install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

확인합니다:

systemctl is-active docker
docker compose version

첫 번째 답은 active여야 합니다. 오류가 나면 두 번째 Docker 변형을 아무렇게나 설치하지 말고, 오류와 공식 페이지를 읽으세요.

5. 도메인을 관리하는 곳의 DNS 패널에서 도메인의 레코드를 엽니다. www.mijneigenwebsite.nl 같은 이름이라면 이름은 www, 값은 실제 VPS IPv4 주소인 A 레코드를 만듭니다. 기존 메일 레코드는 유지합니다. 기본 TTL이나 300초를 쓰세요. 변경이 퍼진 뒤 PC에서 확인합니다:

Resolve-DnsName www.mijneigenwebsite.nl -Type A

답은 내 VPS IP여야 합니다. 같은 이름에 기존 AAAA 레코드가 있는지 확인하세요: 작동하는 IPv6 사이트를 가리킬 때만 유지합니다. VPS 업체 패널에서 들어오는 TCP 80과 443을 허용합니다. SSH 포트는 접속 가능한 상태로 두고, MySQL 포트 3306은 공개하지 마세요. 서버 접근을 어떻게 되찾을지 모른다면 방화벽을 크게 바꾸지 마세요.

6. 메일 제공 업체에서 발신 SMTP 호스트, 암시적 TLS를 쓰는 포트 465, 로그인, 비밀번호, 승인된 발신자 주소를 받습니다. VPS에서 발신이 허용되는지 확인하세요. 이것은 MK8DX 관리자 주소와 다릅니다. 이 안내서는 실제 업체를 통한 전달을 테스트하지 않았습니다. 내 로그인 링크가 실제 받은편지함에 도착해야만 설치가 성공한 것입니다.

7. Ubuntu 터미널에서, WinSCP로 전송한 ZIP은 /root/ 아래에 있습니다. 확인하고 압축을 풉니다:

pwd
ls -lh /root/mk8dx-host-local-v0.2.3-amd64.zip
mkdir -p /opt/mk8dx/host /var/lib/mk8dx
unzip -q /root/mk8dx-host-local-v0.2.3-amd64.zip -d /opt/mk8dx/host
cd /opt/mk8dx/host
ls Start-MK8DX.cmd compose.yaml tooling/start-mk8dx.sh images/docker-images-amd64.tar

이름이 하나라도 없으면 올바른 전체 ZIP의 압축을 풀었는지 확인하세요. 기존 설치 도우미를 시작합니다:

sh tooling/start-mk8dx.sh /var/lib/mk8dx/instance

B1을 고릅니다. https:// 없이 정확한 호스트 이름을 입력합니다. 다섯 가지 메일 값과 앞으로 쓸 내 MK8DX 관리자 주소를 입력합니다. SMTP 비밀번호는 숨겨집니다. 메뉴 1을 고릅니다. 도우미가 내부 데이터베이스, 키, 연결을 만듭니다. 다시 할 때는 같은 /var/lib/mk8dx/instance 폴더를 쓰세요. DNS나 메일 문제를 피하려고 다른 프로필을 만들지 마세요.

8. PC에서 예시 대신 내 호스트 이름으로 준비 상태 주소와 웹사이트를 엽니다:

https://www.mijneigenwebsite.nl/health/ready
https://www.mijneigenwebsite.nl

브라우저에 인증서 경고가 없어야 합니다. 로그인을 클릭하고, 저장한 관리자 주소를 쓰고, 실제 받은편지함의 링크를 엽니다. 그렇게 인증된 로그인 뒤에만, 서버 터미널에서 패키지 폴더로 돌아가 메뉴 5를 고릅니다:

cd /opt/mk8dx/host
sh tooling/start-mk8dx.sh /var/lib/mk8dx/instance

답은 created(생성됨), 반복하면 unchanged(변경 없음)입니다. 사이트를 새로 고치세요. 코스와 내 타임 어택 제출도 확인하세요. 컨테이너가 실행 중이라는 것만으로는 DNS, 인증서, 메일 전달이 증명되지 않습니다.

Android, LiveTrial, 스캐너, Tournament 사용하기

결과를 보내기 위해 이 도구들은 기존 커뮤니티의 주소를 씁니다. LiveTrial과 Tournament Tools는 웹사이트 없이 단독으로도 작동합니다. Android 앱과 브라우저 스캐너에는 웹사이트가 필요합니다. 같은 Windows 컴퓨터에서는 LiveTrial과 Tournament가 http://127.0.0.1:18080 (A1) 또는 http://127.0.0.1:18090 (A3)을 쓸 수 있습니다. 공개 웹사이트에는 신뢰할 수 있는 HTTPS 주소를 쓰세요. Android에는 신뢰할 수 있는 HTTPS가 필요합니다. 로컬 Windows 확인이 Android 연결을 증명하지는 않습니다. 일반 Android 앱과 Windows 클라이언트에서는 커뮤니티 주소를 고를 수 있으며, 도메인이 달라도 소스 코드를 바꿀 필요가 없습니다. 공개 클라이언트 설정에는 서버 비밀번호가 절대 들어 있지 않습니다. 클라이언트에 내부 mysql 이름, API 컨테이너 주소, SSH IP를 절대 입력하지 마세요.

내 설치의 “Website”(웹사이트, 또는 “origin”이나 “Web origin”)로 표시된 전체 웹사이트 주소를, 포트가 표시되어 있다면 포트까지 포함해 항상 그대로 복사하세요. 테스트 받은편지함 주소(“Sign-in mail” 또는 “localMailInbox”)를 LiveTrial에 절대 입력하지 마세요: 그 주소는 로컬 테스트 받은편지함만 엽니다. 두 번째 기기에서는 서버의 127.0.0.1 주소가 아니라 HTTPS 네트워크 이름이나 공개 도메인을 쓰세요.

Android에는 Android 8.0 이상이 필요하며 arm64를 권장합니다. 로컬에서 릴리스 서명된 APK는 약 530 MB입니다. 설치 여유분으로 최소 1 GB를 비워 두세요. PC에서 mk8dx-android-release-v0.2.3.apk를 SHA256SUMS.txt와 대조하고, 휴대폰으로 복사한 다음 Files(파일)나 Downloads(다운로드)에서 엽니다. Android가 이 파일 앱에서의 설치를 허용할지 물으면 확인한 패키지에 대해서만 허용하세요. 나중에 그 권한을 꺼도 됩니다.

처음 시작하면 “커뮤니티 선택”이 내 커뮤니티가 어떻게 플레이하는지 묻습니다. 온라인 커뮤니티라면 “웹사이트 주소”에 신뢰할 수 있는 전체 HTTPS 커뮤니티 주소(예: https://www.mijneigenwebsite.nl)를 경로나 끝 슬래시 없이 입력하고 “저장”을 탭합니다. 집이나 클럽 설치(A2)라면 “QR 코드 스캔”을 탭하고 Prepare a device(기기 준비) 카드를 스캔합니다. A2 안내서가 이 단계를 하나씩 설명합니다. 나중에 앱 위쪽의 커뮤니티 이름을 탭해 커뮤니티를 전환하거나 “커뮤니티 추가”로 추가할 수 있습니다. 각 커뮤니티는 자체 계정과 대기 중인 기록을 유지하며, 그 사이에서 자동으로 옮겨지는 것은 없습니다. 내 기록은 내 이름 → 내 기록에 있으며 오프라인에서도 볼 수 있습니다. 실패하면 휴대폰 브라우저에서 같은 주소를 열어 보세요. 그다음 내 계정으로 브라우저 코드를 통해 로그인합니다. 이전 공개 APK는 디버그 서명되었습니다. 아직 보내지 않은 결과를 저장하고, 그 디버그 앱을 한 번 제거한 다음 이 릴리스 서명된 APK를 설치하세요. 같은 릴리스 키로 서명된 이후의 APK는 덮어써서 업데이트할 수 있습니다. 이것은 Play 스토어 릴리스가 아닙니다.

APK는 도메인마다 따로가 아니라 만든 사람이 서명합니다. 자동 Android 앱 링크에는 실제 앱 ID, 실제 서명 인증서, 내 도메인 사이의 공개 연결이 필요합니다. 그래서 기본 /.well-known/assetlinks.json에는 JSON으로 []가 들어 있습니다. 수동 서버 선택과 로그인은 그 자동 연결 없이도 작동합니다. 따로 서명한 맞춤 빌드는 개발자 방법에 속합니다.

Windows x86-64의 LiveTrial에는 desktop-client-v0.2.3.zip을 SHA256SUMS.txt와 대조하고 ZIP 전체를 압축 해제합니다(예: 문서 폴더 아래). 압축 해제와 내 녹화를 위해 약 2 GB를 확보하세요. 이것은 여유분이며 측정된 최소값이 아닙니다. LiveTrial.exe를 엽니다. 캡처 카드에서 실시간으로 캡처하려면 FFmpeg도 필요한데, 라이선스 때문에 포함되어 있지 않습니다: PowerShell에서 winget install Gyan.FFmpeg 를 한 번 실행하고 LiveTrial을 다시 시작하세요(영상 분석은 FFmpeg 없이도 작동). 설정 → 커뮤니티 웹사이트 주소로 가서 내 설치의 정확한 주소를 입력하고 서버 저장을 고릅니다. 전환을 확인합니다.

LiveTrial이 주소를 저장하고 스스로 다시 시작합니다. 그동안 창을 열어 두세요. 다시 시작한 뒤 설정에 내 정확한 주소가 표시되는지 확인하세요. 그다음에만 로그인합니다. 로그인하면 내 커뮤니티가 열려야 합니다. 기록을 열면, 필요한 경우 그 섹션이 로컬 서버를 잠깐 기다린 뒤 저절로 불러옵니다. F5를 누를 필요는 없어야 합니다. LiveTrial이 자동 재시작에 실패했다고 하면, 앱 안에서 LiveTrial 종료를 고르고 완전히 닫힐 때까지 기다린 다음 LiveTrial.exe를 다시 여세요. 브라우저 창만 닫는 것으로는 충분하지 않습니다: LiveTrial이 백그라운드에서 계속 실행될 수 있습니다.

칸이 여전히 https://www.example.org 예시만 있는 빈 칸이거나, 로그인이 엉뚱한 사이트를 열면 중단하세요. LiveTrial 종료로 기존 LiveTrial 인스턴스를 끝냅니다. 같은 PC의 다른 Windows 계정이 그것을 시작했을 수도 있습니다. 다시 열고 주소를 확인하세요. server.json을 직접 편집하거나 주행 기록을 엉뚱한 웹사이트로 보내지 마세요. 영상 파일에는 캡처 카드가 필요 없습니다. 실시간 캡처에는 호환되는 카드와 드라이버가 필요합니다. 로컬 결과와 대기열은 서버마다 따로 유지됩니다.

브라우저 스캐너는 이미 웹사이트의 일부입니다. 신뢰할 수 있는 HTTPS 주소에서 /scanner/ 를 열고 “이미지 업로드”(영어 화면 “image upload”, 네덜란드어 화면 “afbeelding uploaden”)로 시작하세요. 내 결과 이미지를 선택하고, 인식된 세부 정보를 검토한 뒤, 확인을 마친 후에만 확정하세요. 실시간 카메라 사용에는 브라우저 권한과, localhost 밖에서는 신뢰할 수 있는 HTTPS가 필요합니다. 인식은 녹화 상태에도 좌우됩니다. A2에서 설명한 두 번째 Windows 브라우저 방법은 문서화되어 있지만 처음부터 끝까지 테스트되지는 않았습니다.

Windows x86-64의 Tournament에는 tournament-tools-v0.2.3.zip을 확인하고 ZIP 전체를 압축 해제합니다. Install-MK8DX-TournamentTools.cmd를 엽니다. 몇 GB의 여유 공간을 확보하세요: 약 160 MB인 ZIP과 압축 해제에 필요한 약 1 GB만으로는 모든 의존성과 내 미디어를 감당할 수 없습니다. 설치 프로그램은 Python 3.12와 공개 패키지를 다운로드하기 위해 인터넷이 한 번 필요합니다. 검출용과 라틴 문자용 OCR 모델은 포함되어 있습니다. 처음 영어 OCR을 실행할 때 모델 하나(english_g2.pth, 약 15 MB)를 한 번만 더 다운로드하며, 그 뒤 처리는 오프라인으로 작동합니다. 모든 의존성과 미디어에 필요한 정확한 최소값은 측정되지 않았습니다. GPU 설정은 필요 없습니다: 최신 NVIDIA 드라이버가 있으면 설치 프로그램이 알아서 CUDA 버전을 고르고, 그러면 그래픽 카드가 이름, 점수, 기록 읽기(OCR)를 빠르게 합니다. 녹화의 첫 스캔은 패키지의 OpenCV 빌드에 CUDA 지원이 없기 때문에 항상 프로세서에서 실행됩니다. 패키지 안의 USING_MK8DX_TOURNAMENT_TOOLS.md가 두 단계를 모두 설명합니다. SUCCESS가 나올 때까지 기다리고 runtime-assets는 그대로 두세요. 실패하면 패키지 폴더의 install.log를 읽으세요.

.mp4나 .mkv 녹화를 TournamentProcessor.cmd 위로 끌어다 놓습니다. 프로그램이 영상 옆에 Excel, CSV, 그리고 이름이 _TournamentRaceResultsV1.json으로 끝나는 파일이 들어 있는 세션 폴더를 만듭니다. TournamentLive.cmd는 실시간 입력을 위해 적당한 캡처 하드웨어와 드라이버가 필요합니다.

캡처 카드 없이 기존 영상으로 Tournament Live를 시험해 볼 수도 있습니다. TournamentLive.cmd를 열고 영상 파일 추가를 고른 뒤 .mp4나 .mkv 파일을 선택하고 모두 시작을 고릅니다. 영상과 분석이 끝날 때까지 기다립니다. 확정 순위를 확인하고, 결과 파일을 보려면 내보내기 폴더 열기를 고릅니다. 이 일반 영상 방법은 점수 애니메이션과 최종 순위가 자리 잡을 때까지 기다리는 점수 선택을 씁니다. 이름, 순위, 점수를 직접 확인하세요. OCR이 틀릴 수 있습니다. 영상 재생으로는 실제 캡처 카드를 테스트할 수 없습니다. 별도의 TournamentLiveCli.cmd 재생 명령은 진단용이며 이 방법을 대신하지 않습니다.

이 실행을 웹사이트에 넘기려면 Tournament Live에서 Tournament Manager에 연결(연결한 뒤에는 토너먼트 변경)을 고르고, 브라우저 로그인을 마친 뒤 목록에서 토너먼트를 고르세요. 이 선택은 제안일 뿐입니다. 웹사이트에서 토너먼트를 열고 5단계(결승 그룹은 9단계)로 가서 사용 가능한 Tournament Live 녹화에서 실행을 찾으세요. 그룹에 연결에서 그룹을 고른 다음 검토된 녹화 연결을 고릅니다. 레이스는 승인할 때까지 대기 중인 증거로 남아 있습니다. Tournament Live는 기억하고 있는 캡처 카드를 스스로 추가해 그룹 1의 추가 소스로 둘 수 있습니다. 그룹 1에 영상도 있으면 모두 시작이 멈추고 각 피드를 서로 다른 그룹에 지정하라고 합니다. 추가 소스를 선택하고 선택 항목 삭제를 고르거나, 그 소스에 자기 그룹을 지정한 뒤 다시 시작하세요.

선택 사항인 웹사이트 연결을 쓰려면 패키지 폴더에서 PowerShell을 열고 실행합니다:

.\TournamentConnect.cmd sign-in

처음에는 내 설치의 정확한 주소를 입력하고 브라우저 로그인을 마칩니다. A1이나 A3에서는 MK8DX 창에 표시되는 http://127.0.0.1 주소입니다. 예: http://127.0.0.1:18080. 암호화하지 않은 HTTP는 이 PC의 이런 주소에만 허용됩니다. 다음 명령은 주소를 보여 주거나 바꿉니다. 바꿀 때는 확인을 묻습니다:

.\TournamentConnect.cmd server
.\TournamentConnect.cmd server https://www.example.org

example.org를 실제 커뮤니티로 바꾸세요. 이전 서버로 보낼 대기 중인 업로드는 이전 서버에 남습니다. TournamentConnect.cmd send로 파일을 보내려면, 관리자가 먼저 관리 → 토너먼트 → 디렉터를 열고 로그인한 플레이어를 검색해 이름을 선택해야 합니다. 이렇게 하면 일반 관리 권한이 아니라 토너먼트 접근 권한이 주어집니다. 다시 보내세요. 레이스는 검토될 때까지 수신된 결과에 남아 있습니다. 웹사이트에서 관리자는 확인한 결과를 관리 → 토너먼트 → 기준 레이스 결과 가져오기로, 또는 그룹 안에서 오프라인 대안: 저장된 Live / Processor 결과 파일 가져오기로 가져옵니다. 업로드가 곧 자동 공개는 아닙니다.

새 토너먼트를 열 때는 관리자가 관리 → 토너먼트를 열고 그곳에서 토너먼트를 만듭니다. 플레이어를 추가하고, 누가 참석했는지 표시하고, 사용할 수 있는 Switch를 배정하고, 그룹 배치를 확정합니다. 그다음 그 그룹의 수신된 결과를 엽니다. 인식된 이름을 올바른 플레이어와 맞추고, 코스와 결승 순위를 확인한 뒤, 검토한 레이스에 대해 확정을 고릅니다. 임시 실시간 표는 아직 공식 결과가 아닙니다. 웹사이트에서 마지막 그룹 단계를 마칩니다. 확정 검토 전에 위쪽의 회차 번호 설정을 고르고 이번 회차의 번호(예: 1)를 입력합니다. 최종 표를 확인한 다음 확정 검토 → 토너먼트 확정을 고릅니다. 공개된 결과를 보려면 새 브라우저 창에서 공개 토너먼트 페이지를 여세요.

설정 변경과 사이트 관리

설치 도우미는 논리적인 값마다 한 번씩만 묻습니다. 프로필은 operator-profile.json에, 비밀번호와 키는 따로 secrets.json에 개인 데이터 폴더 안에 보관합니다. 웹, API, Docker, 공개 클라이언트 설정은 도우미가 직접 만들어 냅니다. api.env, compose.env, operator.json, public-client.json을 따로 편집하지 마세요. 공개 /client-config.json에는 웹사이트 주소만 들어 있습니다. 시작을 반복해도 새 계정, 관리자, 키, 데이터베이스가 만들어지지 않습니다.

Windows에서 A1은 기본적으로 %LOCALAPPDATA%\MK8DX\Server를, A2는 %LOCALAPPDATA%\MK8DX\LAN을 씁니다. VPS에서 B1은 /var/lib/mk8dx/instance를 씁니다. 이 폴더들은 데이터 폴더이며, 소프트웨어 업데이트 중에 바꿔치기할 폴더가 아닙니다. 업체 로그인과 VPS SSH 키는 MK8DX 밖에 있습니다. 각 Android 기기나 Windows 기기는 자체 커뮤니티 선택과 세션을 저장합니다.

Windows에서 시작, 상태, 중지, 관리자, 백업을 하려면 해당하는 Start-MK8DX.cmd나 Start-MK8DX-LAN.cmd를 다시 엽니다(카운트다운을 생략하려면 -SkipCountdown을 붙이고, 신호음을 없애려면 MK8DX_SOUND=0을 설정. Ubuntu에서는 --skip-countdown). Ubuntu에서는 /opt/mk8dx/host로 가서 sh tooling/start-mk8dx.sh /var/lib/mk8dx/instance 를 실행합니다. 메뉴는 2가 시작, 3이 상태, 4가 중지, 5가 인증된 첫 관리자, 6이 백업, 7이 검증된 백업을 먼저 만드는 업데이트입니다. 옵션 1은 중단된 첫 설정을 이어서 할 수 있습니다. 유지하려는 설치에는 docker compose down -v 를 절대 쓰지 마세요: -v는 데이터베이스 볼륨을 지웁니다. 시험 설치를 완전히 지우려면(데이터베이스, 계정, 키가 삭제됩니다. 나중에 되돌릴 수도 있다면 먼저 6으로 백업하세요): 4로 중지한 다음 패키지 폴더에서 PowerShell을 열고 docker compose --env-file "$env:LOCALAPPDATA\MK8DX\Server\compose.env" -f compose.yaml -f compose.local.yaml -f compose.images.yaml down -v 를 실행한 뒤 %LOCALAPPDATA%\MK8DX\Server 폴더를 삭제합니다(홈 네트워크 방법에는 compose.lan.yaml을 씀). Ubuntu에서는 같은 명령을 --env-file /var/lib/mk8dx/instance/compose.env 로 실행하고(VPS에는 compose.production.yaml) 그다음 /var/lib/mk8dx/instance 를 삭제합니다.

A2나 B1에서 메일 서비스나 비밀번호를 바꾸려면 먼저 메뉴 6으로 백업을 만드세요. A2에서는 압축을 푼 호스트 폴더에서 PowerShell을 열고 실행합니다:

python tooling/install.py change-smtp --state-dir (Join-Path $env:LOCALAPPDATA 'MK8DX\LAN')
python tooling/install.py apply --state-dir (Join-Path $env:LOCALAPPDATA 'MK8DX\LAN')
python tooling/install.py check --state-dir (Join-Path $env:LOCALAPPDATA 'MK8DX\LAN')

Ubuntu에서는 /opt/mk8dx/host에서 python3와 --state-dir /var/lib/mk8dx/instance 로 같은 작업을 실행합니다. 질문에는 smtp.host, smtp.port, smtp.username, smtp.fromAddress가 나오고, 숨겨진 비밀번호를 묻습니다. Enter를 누르면 기존 값이 유지됩니다. 그 뒤 실제 받은편지함에서 새 로그인 메시지를 확인하세요. check만으로는 메일 전달이 증명되지 않습니다. 관리자 주소, 발신자 주소, SMTP 로그인은 같지 않아도 됩니다.

공개 웹사이트 주소는 새 DNS 주소와 HTTPS가 준비된 뒤에만 바꾸세요. 먼저 백업을 만드세요. 이 A1 예시는 정확한 변경 작업을 보여 줍니다. 예시 포트를 원하는 빈 포트로 바꾸세요:

python tooling/install.py change-origin --state-dir (Join-Path $env:LOCALAPPDATA 'MK8DX\Server') --origin 'http://127.0.0.1:18090'
python tooling/install.py apply --state-dir (Join-Path $env:LOCALAPPDATA 'MK8DX\Server')
python tooling/install.py check --state-dir (Join-Path $env:LOCALAPPDATA 'MK8DX\Server')

B1에는 python3, /var/lib/mk8dx/instance, 그리고 완전한 새 https:// 주소를 쓰세요. 상태, /client-config.json, 새 로그인 링크를 확인합니다. 모든 기기도 새 주소를 가리키게 하세요. 첫 부여 전에는 설치 도우미에서 잘못된 관리자 주소를 고칠 수 있지만, 이미 사용한 첫 부여가 다시 열리지는 않습니다. 기존 관리자는 제한된 복구 절차와 소유자의 명시적 결정을 거쳐야만 다른 인증된 관리자를 추가할 수 있습니다.

웹사이트의 관리 → 설치 설정에 사이트 전체의 선택 사항이 있습니다. 커뮤니티 이름(예: “클럽 북부”)은 앱에서 웹 주소 대신 표시됩니다. 이름을 쓰지 않으려면 비워 두세요. 다른 커뮤니티의 기록은 플레이어가 다른 커뮤니티에서 가져온 기록을 거부할지(끄기, 기본값), 관리자가 관리 → 타임 어택에서 그 옆의 공개를 클릭할 때까지 기다리게 할지(승인 필요), 일반 공개 규칙을 따르게 할지(허용) 정합니다. 가져온 기록이 아직 기다리는 중에 승인 필요에서 다른 것으로 바꾸면, 페이지가 그 기록을 어떻게 할지 묻습니다. 모든 변경은 관리자의 이름과 함께 기록됩니다.

백업, 복원, 업데이트

해당 호스트에서 메뉴 6을 고릅니다. Windows에서는 백업이 Documents\MK8DX-backups\<timestamp> 아래에 저장됩니다. Ubuntu에서 root로 작업한다면 /root/mk8dx-backups/<timestamp> 아래에 저장됩니다. 데이터베이스, 계정, 관리자 권한, 설정, 키가 들어 있습니다. 폴더 전체를 비공개로 보관하고, 호스트 밖의 보호된 저장소에도 복사하세요. 같은 고장 난 VPS에 있는 사본으로는 충분하지 않습니다.

실제로 만들어진 폴더를 검증합니다. 아래의 <ACTUAL_FOLDER>를 도우미가 보여 준 폴더 이름으로 바꾸세요. Windows에서는 호스트 패키지의 PowerShell에서:

python tooling/lifecycle.py verify --backup "$env:USERPROFILE\Documents\MK8DX-backups\<ACTUAL_FOLDER>"

Ubuntu에서는 호스트 패키지 폴더에서:

python3 tooling/lifecycle.py verify --backup '/root/mk8dx-backups/<ACTUAL_FOLDER>'

기대하는 답은 “Backup verified”(백업 검증됨)입니다. 백업을 이슈, 이메일, 공개 클라우드 링크로 절대 공유하지 마세요.

백업 복원하기

복원 시험은 새 데이터 폴더와 새 Docker 프로젝트를 씁니다. 기존 설치는 건드리지 않습니다. 복원 작업은 처음에 새 데이터베이스만 시작합니다. 복구된 웹사이트는 그 뒤에 내 설치 방법에 따라 시작합니다. 시험이 끝난 뒤에도 원래 백업을 보관하세요.

A1이라면 호스트 패키지에서 PowerShell을 엽니다. 아직 없는 대상 폴더를 고르고 실행합니다:

python tooling/lifecycle.py restore-new --backup "$env:USERPROFILE\Documents\MK8DX-backups\<ACTUAL_FOLDER>" --state-dir (Join-Path $env:LOCALAPPDATA 'MK8DX\Herstelproef')
python tooling/install.py status --state-dir (Join-Path $env:LOCALAPPDATA 'MK8DX\Herstelproef')
python tooling/install.py start --state-dir (Join-Path $env:LOCALAPPDATA 'MK8DX\Herstelproef')
python tooling/install.py check --state-dir (Join-Path $env:LOCALAPPDATA 'MK8DX\Herstelproef')

복구된 A1 사이트는 자체의 빈 로컬 포트를 받습니다. status에서 새 Web origin을 엽니다. 알고 있는 계정, 관리 화면, 내 결과를 확인하세요. 원래 사이트는 계속 실행해도 됩니다. 복원 시험에 새 첫 관리자를 부여하지 마세요.

공개 B1을 교체할 때는 확인한 호스트 패키지, Docker, Python, 열린 포트 80/443이 있는 새 Ubuntu 24.04 VPS를 씁니다. 이전 VPS는 당분간 유지하세요. 짧은 유지 보수 시간을 잡으세요. 이전 VPS에서 먼저 Web과 API만 멈춰서, 마지막 백업 뒤에 새 결과가 들어오지 않게 합니다. 이전 호스트 패키지 폴더에서 실행합니다:

docker compose --env-file /var/lib/mk8dx/instance/compose.env -f compose.yaml -f compose.production.yaml -f compose.images.yaml stop web api

이제 웹사이트는 일시적으로 사용할 수 없습니다. 이전 VPS에서 MySQL이 아직 실행 중일 때 새 백업을 위해 메뉴 6을 고릅니다. 위의 verify 명령으로 바로 이 새 백업을 검증합니다. 실패하면 메뉴 2로 이전 사이트를 다시 시작하고 원인을 조사하세요. 검증된 백업 폴더 전체를 검증된 WinSCP 연결로 새 VPS의 개인 폴더(웹 폴더는 절대 안 됨)에 전송합니다. 예를 들어 /root/mk8dx-backups/ 아래에 두세요. 새 서버의 /opt/mk8dx/host에서 실제 백업 폴더 이름으로 실행합니다:

docker load --input images/docker-images-amd64.tar
python3 tooling/lifecycle.py restore-new --backup '/root/mk8dx-backups/<ACTUAL_FOLDER>' --state-dir /var/lib/mk8dx/herstelproef
python3 tooling/install.py status --state-dir /var/lib/mk8dx/herstelproef

새 데이터베이스가 이제 자체 프로젝트에서 준비되었습니다. 복원된 데이터를 기존 개인 백업과 상태와 비교해 확인하세요. 짧은 전환을 계획하세요. DNS 패널에서 MK8DX 호스트 이름의 A 레코드만 새 VPS IPv4 주소로 바꿉니다. 메일 레코드는 유지합니다. PC의 Resolve-DnsName이 새 IP를 보여 줄 때까지 기다립니다. 그다음 새 VPS에서 복구된 서비스를 시작합니다:

python3 tooling/install.py start --state-dir /var/lib/mk8dx/herstelproef
python3 tooling/install.py check --state-dir /var/lib/mk8dx/herstelproef

PC에서 https://<your-real-host-name>/health/ready 와 웹사이트를 엽니다. 유효한 인증서, 실제 받은편지함에 온 내 로그인 이메일, 알고 있는 계정, 관리 화면, 결과를 확인하세요. 새 Docker 설치는 자체 공개 인증서를 요청하므로, 포트 80/443과 새 DNS 목적지에 접속할 수 있어야 합니다. 이전 VPS는 방문자 경로 밖에 두고, 조사나 복귀를 위해 남겨 두세요. 확인에 실패하면 백업을 그대로 두고 DNS, 포트, 인증서, SMTP를 조사한 뒤, A 레코드를 이전 IP로 되돌리는 변경을 신중하게 계획하세요. 빠른 해결책으로 볼륨을 지우지 마세요. 외부 서비스를 포함한 실제 전환은 이 로컬 후보 버전에서 아직 수행되지 않았습니다.

A2라면 같은 신뢰할 수 있는 네트워크의 다른 Windows 호스트에 복원합니다. Docker, Python, 호스트 패키지를 준비합니다. 짧은 유지 보수 시간 동안 이전 호스트에서 Web과 API만 멈춥니다. 마지막 백업을 위해 데이터베이스는 계속 실행됩니다. 이전 패키지 폴더에서 PowerShell을 엽니다:

$state = Join-Path $env:LOCALAPPDATA 'MK8DX\LAN'
$compose = @('--env-file', (Join-Path $state 'compose.env'), '-f', 'compose.yaml', '-f', 'compose.lan.yaml', '-f', 'compose.images.yaml')
docker compose @compose stop web api

그다음 이전 호스트에서 메뉴 6을 고르고 새 백업을 검증합니다. 실패하면 메뉴 2로 이전 설치를 다시 시작하세요. 검증된 백업 폴더를 비공개로 새 호스트에 옮깁니다. 같은 폴더 이름으로 Documents\MK8DX-backups\ 아래에 두거나, 다음 명령의 백업 경로를 맞게 고치세요. 그곳에서, 아직 없는 LAN 복구 폴더로 restore-new를 실행합니다. 시작하기 전에 저장된 연결 주소를 새 호스트의 실제 IPv4로 바꿉니다:

docker load --input images/docker-images-amd64.tar
python tooling/lifecycle.py restore-new --backup "$env:USERPROFILE\Documents\MK8DX-backups\<ACTUAL_FOLDER>" --state-dir (Join-Path $env:LOCALAPPDATA 'MK8DX\LAN-Herstel')
python tooling/install.py change-lan-address --state-dir (Join-Path $env:LOCALAPPDATA 'MK8DX\LAN-Herstel') --lan-bind-address '192.168.0.51'
python tooling/install.py start --state-dir (Join-Path $env:LOCALAPPDATA 'MK8DX\LAN-Herstel')
python tooling/install.py check --state-dir (Join-Path $env:LOCALAPPDATA 'MK8DX\LAN-Herstel')

예시 IP를 바꾸고, 새 호스트에서 TCP 443을 Private(개인) 프로필에 대해서만 허용합니다. 호스트와 두 번째 PC에서 mk8dx.home.arpa의 hosts 항목을 새 IP로 바꿉니다. 이 새 Docker 프로젝트에는 새 로컬 인증 기관이 있습니다. 홈 네트워크 장의 인증서 명령으로 이 복구 프로젝트에서 새 root.crt를 가져오되, $state에는 LAN-Herstel을 씁니다. SHA-256을 다시 비교하고 두 번째 PC에 새 인증서를 설치합니다. 이전 인증서는 certmgr.msc의 Trusted Root Certification Authorities → Certificates(신뢰할 수 있는 루트 인증 기관 → 인증서)에서, 이전 지문으로 찾아 제거합니다. 그다음에야 경고 없이 사이트를 열고 로그인과 기존 결과를 확인하세요. 실제 A2 전환은 아직 테스트되지 않았습니다. 원래 호스트와 백업을 유지하세요.

소프트웨어를 업데이트할 때는 먼저 새 호스트 패키지의 SHA-256을 확인합니다. 이전 소프트웨어 폴더 옆에 압축을 풉니다. 같은 개인 데이터 폴더를 쓰고 새 패키지에서 메뉴 7을 고릅니다. 도우미는 먼저 백업을 만들어 검증하고, 빠진 마이그레이션을 실행하고, 제공된 서버 프로그램만 교체합니다. 그 뒤 같은 프로젝트 ID, 웹사이트, 로그인, 데이터를 확인하세요. 실패하면 백업을 보관하고, 데이터베이스 스키마 변경 뒤에 더 오래된 이미지를 무작정 실행하지 마세요.

0.2.3으로의 업데이트는 Docker 데이터베이스를 MySQL 8.4에서 MySQL 9.7 LTS로 옮깁니다. MySQL은 새 버전으로 처음 시작할 때 데이터 파일을 한 번 업그레이드하며, 이것은 백업을 복원해야만 되돌릴 수 있습니다. 그러니 새 패키지 폴더에서 먼저 7(업데이트)을 고르세요: 확인된 백업을 만들고 데이터베이스 업데이트를 적용합니다. 0.2.4부터는 업데이트가 끝날 때까지 2(시작)가 실행을 거부합니다. 0.2.3 패키지에서는 2가 백업을 건너뜁니다. 메뉴 3(점검)은 무해합니다. A2 패키지에서는 브라우저의 Update(업데이트)가 알아서 먼저 백업을 만듭니다. 첫 업데이트는 조금 더 오래 걸릴 뿐이며, 백업은 Documents\MK8DX-backups에 있습니다. A3와 B2는 자체 MariaDB나 MySQL을 쓰므로 영향을 받지 않습니다.

문제 해결과 직접 빌드하기

웹사이트가 비어 있으면 메뉴 3부터 시작하고 Docker가 실행 중인지 확인하세요. A1에서는 로그인 메일이 Mailpit으로 가고, A2와 B1에서는 실제 받은편지함으로 가야 합니다. 항상 같은 설치, 주소, 이메일을 쓰고 있는지 확인하세요. 공개 방법에서 로그인 메일이 오지 않으면 실제 SMTP 값과 업체 접속 가능 여부를 확인해야 합니다. /health/ready는 API와 데이터베이스의 준비 상태를 알려 줄 뿐, 받은편지함 전달은 알려 주지 않습니다.

A1에서 Start-MK8DX.cmd가 “all predefined address pools have been fully subnetted”로 멈추면, 오래된 Docker 네트워크가 Docker의 주소 범위를 다 써 버린 것입니다. PowerShell에서 docker network ls를 실행해 목록을 확인하세요. 쓰지 않는다고 확실히 아는 네트워크만 지우세요. 예를 들어 docker network prune은 어떤 컨테이너도 쓰지 않는 네트워크만 지웁니다. 그런 다음 Start-MK8DX.cmd를 다시 여세요.

A2에서는 먼저 두 PC의 hosts 항목, 사설 네트워크, 방화벽 포트, 인증서 지문을 확인하세요. B1에서는 DNS A 레코드, 업체 포트 80/443, 유효한 HTTPS를 확인한 다음 메일을 확인하세요. 인증서 경고를 무시하지 마세요. 도움을 요청할 때 secrets.json, 백업, 로그인 링크, SSH 키, 비밀번호가 들어 있는 로그 줄을 절대 공유하지 마세요.

내 코드, 브랜딩, 최종 서명 APK를 빌드하려면 같은 릴리스 페이지에서 mk8dx-full-local 패키지를 다운로드하세요. 여기에는 소스, 내부 에셋 모음, 빌드 방법이 들어 있습니다. 개발자 안내는 docs/DEVELOPMENT.md와 docs/CLIENT_BUILDS.md에 있습니다. 저장소 클론(git clone https://github.com/fromthelake/MK8DX-Ecosystem.git)이나 그 패키지에서, docs/guides/HOSTING.md(“Build the host package from a clone”)는 Docker 호스트 패키지와 공유 호스팅 및 XAMPP 패키지를 빌드하고, docs/CLIENT_BUILDS.md는 Android, LiveTrial, Tournament 패키지를 빌드합니다. 일반 설치와 서버 선택에는 Android Studio, 소스 편집, 직접 빌드한 Docker 이미지가 필요 없습니다. 패키지 안의 게임 자료는 자체 조건을 따릅니다. docs/THIRD_PARTY_MATERIALS.md를 참고하세요.

Linux 사용하기

지금 로컬에서 시험해 볼 수 있는 것

Windows 컴퓨터 없이 내 Linux 컴퓨터만 있으면 됩니다. x86-64에서 Ubuntu 24.04가 실행된다면, 포함된 Docker 호스트 패키지가 로컬 서버 방법입니다. 먼저 uname -m 을 실행하고 x86_64라고 나오는지 확인하세요. Compose 플러그인이 있는 Docker Engine, Python 3.12~3.15, unzip을 설치합니다. Ubuntu의 Docker 설치는 “VPS에 공개 웹사이트 만들기”에 단계별로 설명되어 있습니다. 이 로컬 시험에서는 DNS, 인터넷 방화벽 포트 열기, 실제 SMTP를 건너뛰세요. 같은 릴리스에서 mk8dx-host-local-v0.2.3-amd64.zip과 그 SHA256SUMS.txt를 다운로드합니다. 다운로드 폴더에서 터미널을 열고 ZIP을 확인합니다. 결과를 SHA256SUMS.txt의 해당 줄과 비교합니다. 다르면 중단하세요:

sha256sum mk8dx-host-local-v0.2.3-amd64.zip

패키지의 압축을 풀고 그 폴더로 들어갑니다:

mkdir -p "$HOME/MK8DX/host"
unzip -q mk8dx-host-local-v0.2.3-amd64.zip -d "$HOME/MK8DX/host"
cd "$HOME/MK8DX/host"

기존 Linux 시작 스크립트는 다음과 같습니다:

sh tooling/start-mk8dx.sh "$HOME/mk8dx-data"

A1을 입력하면 첫 설정이 저절로 시작됩니다. 시작 스크립트가 전체 웹사이트 주소를 “Web origin”(웹 주소)으로, Mailpit을 “Local mail inbox”(로컬 메일 받은편지함)로 보여 줍니다. 두 127.0.0.1 주소 모두 이 Linux 컴퓨터에서 작동합니다. 브라우저에서 웹사이트를 열고, 로그인 링크를 보려면 두 번째 탭에서 Mailpit을 엽니다. 사이트가 시작되면 그곳에서 로컬로 웹사이트와 브라우저 스캐너를 쓸 수 있습니다. 로그인, 제출, 그리고 그것이 웹사이트에 보이는지가 실제로 작동하는지 직접 확인하세요. 이 릴리스에서는 그 전체 로컬 과정을 Linux에서 실행해 보지 않았습니다. 컨테이너가 실행 중이라는 것만으로는 증명되지 않습니다.

아직 개발이 필요한 것

포함된 LiveTrial과 Tournament 프로그램은 Windows 프로그램입니다. Linux 애플리케이션으로 바로 실행되지 않습니다. XAMPP ZIP과 그 Windows Apache 도우미도 Linux 설치 프로그램이 아닙니다. 미리 빌드된 네이티브 Linux 클라이언트나 Linux 캡처 인수 테스트는 없습니다. Windows 없이 전체 에코시스템을 쓰려면, Linux에 익숙한 개발자가 데스크톱 클라이언트, 그 OCR 의존성, 캡처 인터페이스를 이식하고 패키징한 뒤, 로그인과 데이터베이스를 거쳐 웹사이트까지의 전달을 테스트해야 합니다. Android APK는 Linux가 아니라 Android에 설치됩니다. A1/B1 호스트 패키지는 amd64 전용입니다. Linux ARM(arm64)에서는 A2 패키지 mk8dx-a2-linux-arm64를 쓰세요.

macOS 사용하기

지금 로컬에서 시험해 볼 수 있는 것

Windows 컴퓨터나 다른 서버 없이 내 Mac만 있으면 됩니다. Intel Mac에서는 개발자가 포함된 Linux/amd64 Docker 이미지를 로컬에서 실행해 볼 수 있습니다. 웹사이트, API, 데이터베이스가 실제로 시작되면 같은 Mac의 브라우저에서 표시된 A1 웹사이트와 Mailpit 주소를 엽니다. 스캐너는 웹사이트의 일부입니다. 아직 어떤 Mac 시험에서도 새 계정, 제출, 데이터베이스 레코드, 웹사이트에 보이는 결과가 확인되지 않았습니다. 홈페이지가 작동한다는 것만으로는 완전한 설치가 증명되지 않습니다.

Intel Mac에서는 Mac용 Docker Desktop과 Python 3.12~3.15를 설치합니다. 같은 호스트 ZIP과 SHA256SUMS.txt를 다운로드합니다. 다운로드 폴더에서 터미널을 열고 shasum -a 256 mk8dx-host-local-v0.2.3-amd64.zip 을 실행한 뒤, 결과를 SHA256SUMS.txt와 비교합니다. 다르면 중단하세요. 그다음 Linux 장의 mkdir, unzip, cd 명령을 씁니다. 같은 셸 시작 스크립트를 시작하고 A1을 고릅니다. 이것은 개발자 시험이며, 승인된 Mac 사용자 방법이 아닙니다. Apple 실리콘에서는 이 A1 호스트 패키지의 amd64 이미지에 에뮬레이션이 필요합니다. 네이티브 arm64 A1 패키지는 없으며, 에뮬레이션에서의 기능과 속도는 증명되지 않았습니다. Apple 실리콘 Mac에서는 대신 A2 패키지 mk8dx-a2-macos-arm64를 쓰세요(“홈 네트워크에서 사용하기” 참고).

Docker Desktop for Mac: https://docs.docker.com/desktop/setup/install/mac-install/

아직 개발이 필요한 것

XAMPP/Node ZIP과 미리 빌드된 LiveTrial 및 Tournament 클라이언트는 Windows 패키지이며, Mac 애플리케이션을 제공하지 않습니다. macOS에 익숙한 개발자가 OCR 의존성과 캡처 카드 연동을 포함해 이 클라이언트들을 이식하고 빌드한 뒤, 전체 전달 과정을 테스트해야 합니다. Windows VM이나 호환성 계층은 대체 클라이언트 방법으로 인정되지 않았습니다. Android APK는 Android 기기용으로 남아 있습니다.
